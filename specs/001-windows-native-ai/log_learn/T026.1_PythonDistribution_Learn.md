# T026.1 - Python Distribution Learnings

**Task**: Create Python distribution configuration
**Date**: 2025-12-18

## Key Learnings

### 1. PyInstaller Spec File Structure

A PyInstaller spec file is a Python script that configures the build:

```python
# Analysis - defines what to include
a = Analysis(
    ['main.py'],              # Entry point
    pathex=[...],             # Python paths
    hiddenimports=[...],      # Dynamically loaded modules
    datas=[...],              # Additional data files
    excludes=[...],           # Modules to exclude
)

# PYZ - Python zip archive
pyz = PYZ(a.pure, a.zipped_data)

# EXE - Executable configuration
exe = EXE(pyz, a.scripts, ...)

# COLLECT - Folder distribution (recommended for large apps)
coll = COLLECT(exe, a.binaries, a.datas, ...)
```

### 2. Hidden Imports for Dynamic Loading

Frameworks that load modules dynamically need explicit declarations:

**FastAPI/Uvicorn:**
```python
'uvicorn.protocols.http.auto',
'uvicorn.lifespan.on',
'starlette.routing',
```

**Transformers:**
```python
'transformers.models.layoutlmv3.modeling_layoutlmv3',
'transformers.models.layoutlmv3.configuration_layoutlmv3',
```

**PyTorch:**
```python
'torch.nn',
'torch.nn.functional',
```

### 3. Folder vs Single-File Distribution

**Single File (onefile mode):**
- Creates one large .exe
- Extracts to temp directory at runtime
- Slower startup
- May trigger antivirus

**Folder Mode (COLLECT):**
- Creates directory with .exe and dependencies
- Faster startup
- Easier to debug
- Better for services

Recommendation: Use folder mode for services.

### 4. CPU-Only PyTorch

For deployment without GPU:
```
torch==2.1.2+cpu
```

Benefits:
- Smaller size (~500MB vs ~2GB)
- No CUDA dependencies
- Sufficient for invoice processing

### 5. Model Weight Bundling Strategy

Two approaches:

**Bundle at build time:**
```python
datas = [
    ('models/layoutlm', 'models/layoutlm'),
]
```
- Larger distribution (~1.5GB)
- Works offline
- No download at runtime

**Download at runtime:**
```python
from transformers import LayoutLMv3Processor
processor = LayoutLMv3Processor.from_pretrained("microsoft/layoutlmv3-base")
```
- Smaller distribution (~500MB)
- Requires internet on first run
- Uses HuggingFace cache

### 6. Build Script Best Practices

```python
def main():
    check_prerequisites()    # Fail fast
    clean_build()            # Start fresh
    download_models()        # Prepare assets
    run_pyinstaller()        # Build
    validate_build()         # Verify output
```

Important validations:
- Executable exists
- Size is reasonable (>100MB for PyTorch)
- Key dependencies included

### 7. Exclusions for Smaller Builds

Exclude unnecessary modules:
```python
excludes=[
    'tkinter',       # GUI toolkit
    'matplotlib',    # Plotting
    'scipy',         # Scientific computing
    'pandas',        # Data analysis
    'IPython',       # Interactive shell
]
```

### 8. Console Mode for Services

For Windows services, keep console mode enabled:
```python
exe = EXE(
    ...,
    console=True,    # Important for service logging
)
```

This allows:
- Logging to stdout/stderr
- Service manager integration
- Debug visibility

## Common Issues

### 1. Missing Hidden Imports
Symptom: `ModuleNotFoundError` at runtime
Solution: Add module to `hiddenimports` list

### 2. Missing Data Files
Symptom: `FileNotFoundError` for config/models
Solution: Add to `datas` list with correct destination

### 3. DLL Missing
Symptom: Windows error about missing DLL
Solution: Check `binaries` list, may need VC++ runtime

### 4. Build Size Too Large
Solution:
- Use `--exclude` for unused modules
- Use CPU-only PyTorch
- Don't bundle models (download at runtime)

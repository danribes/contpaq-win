# T028.1 - Electron Builder Learnings

**Task**: Configure electron-builder for Windows packaging
**Date**: 2025-12-18

## Key Learnings

### 1. ASAR Archives and Native Modules

ASAR (Atom Shell Archive) is Electron's archive format for bundling app files:

```json
{
  "asar": true,
  "asarUnpack": [
    "**/*.node",
    "**/better-sqlite3/**"
  ]
}
```

**Why native modules need unpacking:**
- `.node` files are native binaries (DLLs)
- Node.js cannot load native modules from archives
- They must exist as real files on disk
- `asarUnpack` extracts them to `app.asar.unpacked/`

### 2. Native Module Rebuilding

Native modules must be compiled for Electron's Node.js version:

```json
{
  "npmRebuild": true
}
```

**How it works:**
1. Electron uses a different Node.js version than system
2. Native modules compiled for system Node won't work
3. electron-builder rebuilds them with Electron's headers
4. Uses `node-gyp` with Electron-specific settings

**Common native modules:**
- `better-sqlite3` - SQLite database
- `node-pty` - Terminal emulation
- `sharp` - Image processing
- `serialport` - Serial communication

### 3. NSIS Installer Configuration

NSIS (Nullsoft Scriptable Install System) is the default Windows installer:

```json
{
  "nsis": {
    "oneClick": false,
    "perMachine": true,
    "allowElevation": true,
    "allowToChangeInstallationDirectory": true,
    "language": "1034"
  }
}
```

**Key settings:**
- `oneClick: false` - Shows installation wizard
- `perMachine: true` - Installs for all users
- `allowElevation: true` - Requests admin rights
- `language: "1034"` - Spanish (LCID code)

**Language codes (LCID):**
| Code | Language |
|------|----------|
| 1033 | English (US) |
| 1034 | Spanish |
| 1031 | German |
| 1036 | French |

### 4. Code Signing for Windows

Code signing authenticates the publisher:

```json
{
  "win": {
    "publisherName": "ContPAQ Win",
    "forceCodeSigning": false
  }
}
```

**Environment variables for signing:**
```bash
# Path to certificate (.p12 or .pfx)
export CSC_LINK=/path/to/certificate.p12

# Certificate password
export CSC_KEY_PASSWORD=your_password

# Or base64-encoded certificate
export CSC_LINK="base64://..."
```

**Why code signing matters:**
- Windows SmartScreen trusts signed apps
- Unsigned apps show scary warnings
- Enterprise environments may block unsigned
- Required for Microsoft Store

**Development without signing:**
- Set `forceCodeSigning: false` or omit
- Apps work but show "Unknown publisher"
- Useful for local development

### 5. Extra Resources

Bundle additional files outside the ASAR:

```json
{
  "extraResources": [
    {
      "from": "../ai-service",
      "to": "ai-service",
      "filter": [
        "**/*",
        "!**/__pycache__/**"
      ]
    }
  ]
}
```

**Access at runtime:**
```javascript
const path = require('path');

// In packaged app
const resourcePath = process.resourcesPath;
const aiServicePath = path.join(resourcePath, 'ai-service');

// In development
const devPath = path.join(__dirname, '..', 'ai-service');
```

### 6. Artifact Naming

Configure output filename pattern:

```json
{
  "win": {
    "artifactName": "${productName}-${version}-Setup.${ext}"
  }
}
```

**Available variables:**
- `${productName}` - From package.json or config
- `${version}` - Package version
- `${arch}` - Architecture (x64, ia32, arm64)
- `${ext}` - File extension
- `${os}` - Operating system

### 7. Compression Settings

```json
{
  "compression": "maximum"
}
```

**Options:**
- `store` - No compression (fastest build)
- `normal` - Default compression
- `maximum` - Best compression (slower build)

Use `maximum` for release builds, `store` for development.

### 8. Build Resources Directory

```json
{
  "directories": {
    "output": "release",
    "buildResources": "build"
  }
}
```

**Expected structure:**
```
desktop-app/
├── build/
│   ├── icon.ico          # Windows icon
│   ├── icon.icns         # macOS icon
│   ├── icon.png          # Linux icon
│   └── background.png    # Installer background
├── release/              # Build output
└── electron-builder.json
```

### 9. Debugging Build Issues

**Common problems:**

1. **Native module errors:**
   ```
   Module did not self-register
   ```
   Solution: Check `npmRebuild: true`, verify Electron version

2. **ASAR loading errors:**
   ```
   Cannot find module '...'
   ```
   Solution: Add to `asarUnpack`

3. **Code signing errors:**
   ```
   Cannot sign: certificate not found
   ```
   Solution: Set CSC_LINK/CSC_KEY_PASSWORD or set `forceCodeSigning: false`

### 10. Build Commands

```bash
# Build only
npm run package

# Build for specific platform
npx electron-builder --win

# Build without signing
npx electron-builder --win --config.win.forceCodeSigning=false

# Verbose output
DEBUG=electron-builder npm run package
```

## Configuration File Locations

electron-builder reads configuration from:
1. `electron-builder.json` (standalone file)
2. `package.json` under `"build"` key
3. Command line arguments

Priority: CLI > electron-builder.json > package.json

## Related Files

- `desktop-app/electron-builder.json` - Main configuration
- `desktop-app/package.json` - Dependencies and scripts
- `desktop-app/build/` - Build resources (icons, etc.)

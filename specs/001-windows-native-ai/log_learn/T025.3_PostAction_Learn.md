# T025.3 - Post Action Learnings

**Task**: Implement post action flow
**Date**: 2025-12-18

## Key Learnings

### 1. State Machine Pattern for Complex Flows

For multi-step async operations, a state machine provides clear control:

```typescript
export type PostStatus =
  | 'idle'
  | 'checking_duplicate'
  | 'duplicate_warning'
  | 'checking_vendor'
  | 'vendor_required'
  | 'creating_vendor'
  | 'creating_entry'
  | 'success'
  | 'error';
```

Benefits:
- Clear status for UI rendering
- Easy to test each state
- Predictable transitions
- Supports user intervention points (duplicate_warning, vendor_required)

### 2. Preserving Input Data with useRef

When a flow can be interrupted (waiting for user input), preserve the original data:

```typescript
const inputRef = useRef<PostToContPAQiInput | null>(null);
const forceDuplicateRef = useRef<boolean>(false);

const startPost = useCallback(async (input: PostToContPAQiInput) => {
  inputRef.current = input;
  // ...start the flow
}, []);

const continueDespiteDuplicate = useCallback(async () => {
  // Can still access inputRef.current
  await checkVendorAndContinue(true);
}, []);
```

Using refs avoids stale closure issues with callbacks.

### 3. Testing Mocked Classes with instanceof

When mocking classes in Jest, preserve error classes for instanceof checks:

```typescript
// BAD: Mocks entire module, breaks instanceof
jest.mock('../services/bridge-service');

// GOOD: Preserves BridgeServiceError class
jest.mock('../services/bridge-service', () => {
  const originalModule = jest.requireActual('../services/bridge-service');
  return {
    ...originalModule,
    BridgeServiceClient: jest.fn(),
  };
});
```

### 4. Testing Async Hooks

Use `act()` for all async operations in hook tests:

```typescript
await act(async () => {
  await result.current.startPost(defaultInput);
});

// For operations that need to wait mid-flow
act(() => {
  result.current.startPost(defaultInput);
});
// Check intermediate state
expect(result.current.state.status).toBe('checking_duplicate');

await act(async () => {
  resolveCheck!(checkResult);
});
```

### 5. User Intervention Points

Design flows with clear intervention points where UI can render:

```typescript
if (duplicateResult.isDuplicate) {
  // Stop and wait for user - UI will render DuplicateWarningModal
  updateState({
    status: 'duplicate_warning',
    duplicateInfo: { existingFolio, existingDate },
  });
  return; // Don't continue automatically
}
```

The hook pauses and provides functions for the user to continue:
- `continueDespiteDuplicate()` - User chose to proceed
- `cancel()` - User chose to abort

### 6. Error Handling Strategy

Consistent error handling throughout the flow:

```typescript
try {
  // API call
} catch (error) {
  const message = error instanceof BridgeServiceError
    ? error.message
    : error instanceof Error
      ? error.message
      : 'Error desconocido';

  updateState({
    status: 'error',
    error: message,
  });
}
```

This ensures:
- Custom error messages from BridgeServiceError are preserved
- Generic errors are handled
- Unknown errors have a fallback message

### 7. Color Semantics in UI

Different colors for different modal purposes:
- **Orange**: Warning (duplicate found)
- **Blue**: Action/Creation (create vendor)
- **Green**: Success (entry created)

### 8. Lazy Client Initialization

Create the API client lazily and cache it:

```typescript
const clientRef = useRef<BridgeServiceClient | null>(null);
const getClient = useCallback(() => {
  if (!clientRef.current) {
    clientRef.current = new BridgeServiceClient(baseUrl);
  }
  return clientRef.current;
}, [baseUrl]);
```

Benefits:
- Client only created when needed
- Same client reused for entire flow
- Easy to mock in tests

## Complete T025 Flow

With T025.1, T025.2, and T025.3 combined:

```tsx
function InvoicePostButton({ invoice, extraction }) {
  const {
    state,
    startPost,
    continueDespiteDuplicate,
    createVendorAndContinue,
    cancel,
    reset,
  } = usePostToContPAQi();

  const handlePost = async () => {
    await startPost({
      vendorRfc: extraction.vendorRfc.value,
      vendorName: extraction.vendorName.value,
      invoiceNumber: extraction.invoiceNumber.value,
      invoiceDate: new Date(extraction.invoiceDate.value),
      subtotal: parseFloat(extraction.subtotal.value),
      ivaAmount: parseFloat(extraction.ivaAmount.value),
      total: parseFloat(extraction.total.value),
      lineItems: extraction.lineItems,
    });
  };

  return (
    <>
      <button onClick={handlePost}>Enviar a ContPAQi</button>

      <DuplicateWarningModal
        isOpen={state.status === 'duplicate_warning'}
        existingFolio={state.duplicateInfo?.existingFolio ?? ''}
        existingDate={state.duplicateInfo?.existingDate ?? null}
        vendorRfc={extraction.vendorRfc.value}
        invoiceNumber={extraction.invoiceNumber.value}
        onContinue={() => continueDespiteDuplicate()}
        onCancel={cancel}
      />

      <CreateVendorModal
        isOpen={state.status === 'vendor_required'}
        rfc={state.vendorInfo?.rfc ?? ''}
        suggestedName={state.vendorInfo?.suggestedName}
        onSubmit={createVendorAndContinue}
        onCancel={cancel}
      />

      <PostSuccessModal
        isOpen={state.status === 'success'}
        folio={state.folio ?? ''}
        onClose={reset}
      />
    </>
  );
}
```

### File Created
Created `database/migrations/001_initial_schema.sql` with the complete database schema for the ContPAQ Win Invoice Processing application.

### Schema Content

#### PRAGMA Statement
```sql
PRAGMA foreign_keys = ON;
```
Enables foreign key constraint enforcement in SQLite.

#### Tables Created

| Table | Description | Primary Key |
|-------|-------------|-------------|
| vendors | Business entities that issue invoices | id (TEXT/UUID) |
| invoices | Primary invoice entity with state machine | id (TEXT/UUID) |
| line_items | Individual line items from invoices | id (TEXT/UUID) |
| extraction_results | AI extraction output with confidence | id (TEXT/UUID) |
| contpaqi_entries | ContPAQi posting records | id (TEXT/UUID) |

### Key Design Decisions

1. **UUIDs as TEXT**: SQLite doesn't have native UUID type, using TEXT
2. **Timestamps as TEXT**: Using ISO 8601 format via datetime('now')
3. **CHECK constraints**: Enforcing valid states and source types
4. **CASCADE deletes**: Line items, extraction results delete with parent invoice
5. **UNIQUE constraint**: contpaqi_entries.invoice_id ensures one entry per invoice

### Schema Validation
- All tables use `CREATE TABLE IF NOT EXISTS` for idempotency
- Foreign key relationships properly defined
- CHECK constraints for enum-like fields:
  - invoice.state: UPLOADED, EXTRACTED, VALIDATED, POSTED
  - invoice.source_type: text_based, scanned
  - contpaqi_entries.posting_status: pending, success, failed

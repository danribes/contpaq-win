# T004.2.4 Learning Guide: ASP.NET Core Dependency Injection

## Overview
This guide covers ASP.NET Core's built-in dependency injection (DI) container configuration, service lifetimes, and common patterns.

## Key Concepts

### 1. Dependency Injection Basics
DI is a design pattern where dependencies are "injected" rather than created directly:

```csharp
// Without DI - tight coupling
public class Controller
{
    private SdkService _sdk = new SdkService(); // Hard dependency
}

// With DI - loose coupling
public class Controller
{
    private readonly ISdkService _sdk;

    public Controller(ISdkService sdk) // Injected
    {
        _sdk = sdk;
    }
}
```

### 2. Service Registration
Services are registered in Program.cs using `builder.Services`:

```csharp
// Register with interface-implementation pattern
builder.Services.AddScoped<ISdkService, SdkService>();

// Register concrete type
builder.Services.AddScoped<SomeService>();

// Register with factory
builder.Services.AddScoped<ISdkService>(sp =>
    new SdkService(sp.GetRequiredService<ILogger<SdkService>>()));
```

### 3. Service Lifetimes

| Lifetime | Method | Behavior |
|----------|--------|----------|
| **Transient** | `AddTransient<>()` | New instance every injection |
| **Scoped** | `AddScoped<>()` | One instance per HTTP request |
| **Singleton** | `AddSingleton<>()` | Single instance for app lifetime |

#### Lifetime Guidelines

```csharp
// Transient - stateless, lightweight services
builder.Services.AddTransient<IEmailService, EmailService>();

// Scoped - request-specific state (DbContext, unit of work)
builder.Services.AddScoped<IUnitOfWork, UnitOfWork>();
builder.Services.AddScoped<ISdkService, SdkService>();

// Singleton - expensive to create, thread-safe, shared state
builder.Services.AddSingleton<ICache, MemoryCache>();
builder.Services.AddSingleton<IConfigurationService, ConfigService>();
```

### 4. Options Pattern
Bind configuration sections to strongly-typed options:

```csharp
// In Program.cs
builder.Services.Configure<BridgeOptions>(
    builder.Configuration.GetSection("Bridge"));

// Options class
public class BridgeOptions
{
    public const string SectionName = "Bridge";
    public string? SdkPath { get; set; }
    public int ConnectionTimeoutSeconds { get; set; } = 30;
}

// Usage via injection
public class SdkService
{
    private readonly BridgeOptions _options;

    public SdkService(IOptions<BridgeOptions> options)
    {
        _options = options.Value;
    }
}
```

#### Options Interfaces

| Interface | Use Case |
|-----------|----------|
| `IOptions<T>` | Singleton, read at startup |
| `IOptionsSnapshot<T>` | Scoped, re-reads per request |
| `IOptionsMonitor<T>` | Singleton, supports change notifications |

### 5. Built-in Infrastructure Services

```csharp
// HTTP client factory - manages HttpClient lifecycle
builder.Services.AddHttpClient();

// Memory cache - in-process caching
builder.Services.AddMemoryCache();

// Health checks - monitoring endpoint
builder.Services.AddHealthChecks();
app.MapHealthChecks("/health");

// Logging - usually configured automatically
// builder.Services.AddLogging();
```

### 6. HttpClient Factory Pattern
Never create HttpClient directly - use the factory:

```csharp
// Registration
builder.Services.AddHttpClient();

// Or with named client
builder.Services.AddHttpClient("AIService", client =>
{
    client.BaseAddress = new Uri("http://localhost:8000");
    client.Timeout = TimeSpan.FromSeconds(30);
});

// Usage
public class AIServiceClient
{
    private readonly HttpClient _client;

    public AIServiceClient(IHttpClientFactory factory)
    {
        _client = factory.CreateClient("AIService");
    }
}
```

### 7. Health Checks
Implement custom health checks:

```csharp
// Registration
builder.Services.AddHealthChecks()
    .AddCheck<SdkHealthCheck>("sdk")
    .AddCheck<DatabaseHealthCheck>("database");

// Custom health check
public class SdkHealthCheck : IHealthCheck
{
    private readonly ISdkService _sdk;

    public SdkHealthCheck(ISdkService sdk)
    {
        _sdk = sdk;
    }

    public Task<HealthCheckResult> CheckHealthAsync(
        HealthCheckContext context,
        CancellationToken cancellationToken = default)
    {
        return Task.FromResult(_sdk.IsAvailable()
            ? HealthCheckResult.Healthy("SDK available")
            : HealthCheckResult.Unhealthy("SDK not available"));
    }
}
```

## Best Practices

### 1. Interface Segregation
```csharp
// Good - specific interfaces
public interface ISdkReader { ... }
public interface ISdkWriter { ... }

// Bad - god interface
public interface ISdkService { /* 50 methods */ }
```

### 2. Avoid Service Locator Pattern
```csharp
// Bad - service locator
public class Service
{
    public void DoWork()
    {
        var dep = ServiceLocator.Get<IDependency>(); // Anti-pattern
    }
}

// Good - constructor injection
public class Service
{
    private readonly IDependency _dep;

    public Service(IDependency dep) => _dep = dep;
}
```

### 3. Validate Scopes
Enable scope validation in development:

```csharp
var builder = WebApplication.CreateBuilder(args);
builder.Host.UseDefaultServiceProvider(options =>
{
    options.ValidateScopes = builder.Environment.IsDevelopment();
    options.ValidateOnBuild = builder.Environment.IsDevelopment();
});
```

### 4. Avoid Captive Dependencies
Never inject scoped services into singletons:

```csharp
// WRONG - scoped service captured by singleton
public class MySingleton
{
    private readonly IScopedService _scoped; // Bug!
}

// Correct - use IServiceScopeFactory
public class MySingleton
{
    private readonly IServiceScopeFactory _factory;

    public void DoWork()
    {
        using var scope = _factory.CreateScope();
        var scoped = scope.ServiceProvider.GetRequiredService<IScopedService>();
    }
}
```

## Common Patterns

### Factory Pattern with DI
```csharp
public interface ISdkServiceFactory
{
    ISdkService Create(string company);
}

builder.Services.AddSingleton<ISdkServiceFactory, SdkServiceFactory>();
```

### Decorator Pattern
```csharp
// Register implementation
builder.Services.AddScoped<SdkService>();

// Decorate with logging
builder.Services.AddScoped<ISdkService>(sp =>
    new LoggingSdkServiceDecorator(
        sp.GetRequiredService<SdkService>(),
        sp.GetRequiredService<ILogger<LoggingSdkServiceDecorator>>()));
```

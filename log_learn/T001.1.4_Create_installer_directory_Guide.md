# Learning Guide: T001.1.4 - Installer Directory Structure

## What is the Installer?

The **Installer** is the component responsible for packaging and deploying ContPAQ-Win on Windows systems. Unlike traditional installers that create MSI packages, we use a script-based approach with NSSM for service management.

## Why This Approach?

### Traditional Installer vs. Script-Based
| Aspect | MSI Installer | Script-Based (Our Approach) |
|--------|--------------|----------------------------|
| Complexity | High (requires WiX toolset) | Low (PowerShell scripts) |
| Updates | Full reinstall needed | Partial updates possible |
| Service Management | Windows SCM directly | NSSM (more reliable) |
| Debugging | Difficult | Easy (readable scripts) |
| Developer Experience | Steep learning curve | Familiar tools |

### What is NSSM?

**NSSM (Non-Sucking Service Manager)** is a utility that allows any executable to run as a Windows service. Benefits:

1. **Automatic restarts** - If the service crashes, NSSM restarts it
2. **Console output logging** - Captures stdout/stderr to log files
3. **Environment variables** - Can set per-service environment
4. **Graceful shutdown** - Handles stop signals properly

## Directory Structure Explanation

```
installer/
├── scripts/
│   └── .gitkeep
└── assets/
    └── .gitkeep
```

### `installer/scripts/`

Will contain PowerShell scripts for installation tasks:

```powershell
# Example: install.ps1
# Install all ContPAQ-Win services

param(
    [string]$InstallPath = "C:\ContPAQWin"
)

# Copy files
Copy-Item -Recurse .\ai-service $InstallPath\ai-service
Copy-Item -Recurse .\windows-bridge $InstallPath\windows-bridge

# Install NSSM services
.\assets\nssm.exe install ContPAQWin-AI "$InstallPath\ai-service\venv\Scripts\python.exe" "-m uvicorn src.main:app"
.\assets\nssm.exe install ContPAQWin-Bridge "$InstallPath\windows-bridge\ContPAQWinBridge.exe"

# Start services
Start-Service ContPAQWin-AI
Start-Service ContPAQWin-Bridge
```

### `installer/assets/`

Will contain:
- **nssm.exe** - Service manager binary
- **app.ico** - Application icon
- **LICENSE.txt** - Software license
- **README.txt** - Quick start guide

## Installation Flow

```
1. User downloads ContPAQ-Win-Setup.zip
         │
         ▼
2. Extracts to C:\ContPAQWin (or custom location)
         │
         ▼
3. Runs install.ps1 as Administrator
         │
         ├──► Copies application files
         ├──► Installs Python virtual environment
         ├──► Registers NSSM services
         ├──► Creates desktop shortcut
         └──► Opens Desktop App
         │
         ▼
4. ContPAQ-Win running!
```

## Key Concepts

### Windows Services

A Windows Service is a long-running executable that performs specific functions. Services:
- Start automatically at boot (if configured)
- Run without user login
- Have their own identity and permissions
- Can be managed via `services.msc` or PowerShell

### PowerShell

PowerShell is Windows' scripting language. Key features used:
- `param()` - Define script parameters
- `Copy-Item` - File operations
- `Start-Service` - Service management
- `Test-Path` - Check file/folder existence

### Firewall Configuration

Our services bind to localhost only (127.0.0.1), but we still configure firewall rules for defense in depth:

```powershell
# Allow only localhost connections to AI Service
New-NetFirewallRule -DisplayName "ContPAQ-Win AI Service" `
    -Direction Inbound -LocalPort 8000 -Protocol TCP `
    -RemoteAddress 127.0.0.1 -Action Allow
```

## Security Considerations

1. **Principle of Least Privilege** - Services run with minimal permissions
2. **Localhost Binding** - No external network access
3. **No Elevated Desktop App** - Only installer needs admin rights
4. **No Secrets in Scripts** - All configuration via environment variables

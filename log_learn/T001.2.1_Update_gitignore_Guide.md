# Learning Guide: T001.2.1 - .gitignore Configuration

## What is .gitignore?

The `.gitignore` file tells Git which files and directories to ignore when tracking changes. Files matching patterns in .gitignore won't be:
- Shown in `git status`
- Added with `git add`
- Committed to the repository

## Why is it Important?

### Security
Without proper .gitignore, you might accidentally commit:
- **API keys** (`.env` files)
- **Database passwords**
- **Private certificates**

These secrets can be extracted from git history even after deletion!

### Repository Size
Ignoring build artifacts keeps the repository small:
- `node_modules/` can be **500MB+**
- `venv/` typically **200-400MB**
- `.dll` and `.exe` files can be **tens of MB**

### Clean History
Build outputs change constantly and pollute commit history.

## Pattern Types in .gitignore

### 1. Simple Filenames
```gitignore
Thumbs.db    # Matches any file named Thumbs.db
.DS_Store    # Matches macOS metadata files
```

### 2. Wildcard Patterns
```gitignore
*.log        # Any file ending in .log
*.pyc        # Python bytecode files
npm-debug.*  # npm debug logs with any extension
```

### 3. Directory Patterns
```gitignore
node_modules/   # Directory (trailing slash)
__pycache__/    # Python cache directory
bin/            # .NET build output
```

### 4. Negation (Include Exceptions)
```gitignore
.claude/*           # Ignore everything in .claude
!.claude/commands/  # BUT include the commands folder
```

### 5. Double Asterisk (Recursive)
```gitignore
**/logs/      # Match logs/ in any subdirectory
**/*.temp     # Match *.temp anywhere in tree
```

## Technology-Specific Patterns

### Python
| Pattern | Purpose |
|---------|---------|
| `__pycache__/` | Bytecode cache directory |
| `*.pyc` | Compiled Python files |
| `.venv/` | Virtual environment |
| `*.egg-info/` | Package metadata |

### Node.js
| Pattern | Purpose |
|---------|---------|
| `node_modules/` | Dependencies (reinstalled via npm) |
| `dist/` | Build output directory |
| `npm-debug.log` | Debug logs from failed installs |

### .NET
| Pattern | Purpose |
|---------|---------|
| `bin/` | Compiled binaries |
| `obj/` | Intermediate build files |
| `*.dll` | Dynamic link libraries |
| `*.exe` | Executables |
| `*.pdb` | Debug symbols |

## Common Mistakes

### 1. Adding Files After Commit
```bash
# WRONG: File already tracked, won't be ignored
echo "secret.txt" >> .gitignore

# RIGHT: Remove from tracking first
git rm --cached secret.txt
echo "secret.txt" >> .gitignore
```

### 2. Trailing Spaces
```gitignore
# WRONG: Trailing space makes it not match
node_modules/

# RIGHT: No trailing space
node_modules/
```

### 3. Forgetting Nested Directories
```gitignore
# WRONG: Only matches root level bin/
/bin/

# RIGHT: Matches bin/ at any level
bin/
```

## Global vs. Project .gitignore

### Project .gitignore (what we created)
- Lives in repository root
- Shared with all collaborators
- Contains project-specific patterns

### Global .gitignore (personal)
```bash
# Set up global gitignore
git config --global core.excludesfile ~/.gitignore_global
```

Use for personal editor/OS files:
```gitignore
# ~/.gitignore_global
.DS_Store        # macOS
Thumbs.db        # Windows
*.swp            # Vim swap files
.idea/           # JetBrains IDEs
```

## Testing Your .gitignore

```bash
# Check if a file is ignored
git check-ignore -v filename.txt

# List all ignored files
git status --ignored

# See what would be added
git add --dry-run .
```

## Related Concepts

### .gitattributes
Controls how Git handles files (line endings, diff drivers).

### .dockerignore
Similar concept for Docker build context - prevents sending unnecessary files to Docker daemon.

### .npmignore
Controls what gets published to npm registry.

# T004.2.1 Learning Guide: ASP.NET Core Program.cs

## Overview
This guide explains the Program.cs file structure in modern ASP.NET Core applications, covering top-level statements, the WebApplication builder pattern, and service configuration.

## Evolution of Program.cs

### Legacy Pattern (.NET 5 and earlier)
```csharp
public class Program
{
    public static void Main(string[] args)
    {
        CreateHostBuilder(args).Build().Run();
    }

    public static IHostBuilder CreateHostBuilder(string[] args) =>
        Host.CreateDefaultBuilder(args)
            .ConfigureWebHostDefaults(webBuilder =>
            {
                webBuilder.UseStartup<Startup>();
            });
}
```

### Modern Pattern (.NET 6+)
```csharp
var builder = WebApplication.CreateBuilder(args);
builder.Services.AddControllers();

var app = builder.Build();
app.MapControllers();
app.Run();
```

## WebApplication Builder Pattern

### Creating the Builder
```csharp
var builder = WebApplication.CreateBuilder(args);
```

This creates a builder with defaults for:
- Configuration (appsettings.json, environment variables)
- Logging (Console, Debug, EventSource)
- Kestrel web server
- Dependency injection container

### Configuring Services
```csharp
// Add MVC controllers
builder.Services.AddControllers();

// Add Swagger
builder.Services.AddEndpointsApiExplorer();
builder.Services.AddSwaggerGen();

// Add custom services
builder.Services.AddScoped<IMyService, MyService>();
```

### Building and Running
```csharp
var app = builder.Build();

// Configure middleware pipeline
app.UseSwagger();
app.MapControllers();

app.Run();
```

## Serilog Integration

### Why Serilog?
- Structured logging (logs as data, not strings)
- Multiple sinks (Console, File, Seq, etc.)
- Rich context and enrichers
- Configuration from files

### Bootstrap Logger
```csharp
Log.Logger = new LoggerConfiguration()
    .WriteTo.Console()
    .CreateBootstrapLogger();
```

The bootstrap logger catches errors during startup before the full configuration is loaded.

### Full Configuration
```csharp
builder.Host.UseSerilog((context, services, configuration) => configuration
    .ReadFrom.Configuration(context.Configuration)
    .ReadFrom.Services(services)
    .Enrich.FromLogContext()
    .WriteTo.Console()
    .WriteTo.File("logs/app-.log", rollingInterval: RollingInterval.Day));
```

### Request Logging
```csharp
app.UseSerilogRequestLogging();
```

Logs HTTP request details automatically:
- Method, path, status code
- Response time
- Request correlation

## Swagger/OpenAPI Configuration

### Basic Setup
```csharp
builder.Services.AddEndpointsApiExplorer();
builder.Services.AddSwaggerGen();
```

### With Custom Info
```csharp
builder.Services.AddSwaggerGen(options =>
{
    options.SwaggerDoc("v1", new OpenApiInfo
    {
        Title = "My API",
        Version = "v1",
        Description = "API description"
    });
    options.EnableAnnotations();
});
```

### Middleware
```csharp
app.UseSwagger();
app.UseSwaggerUI(options =>
{
    options.SwaggerEndpoint("/swagger/v1/swagger.json", "My API v1");
    options.RoutePrefix = "swagger"; // Available at /swagger
});
```

## Middleware Pipeline

### Order Matters!
```csharp
// 1. Exception handling (first)
app.UseExceptionHandler("/error");

// 2. HTTPS redirection
app.UseHttpsRedirection();

// 3. Static files
app.UseStaticFiles();

// 4. Routing
app.UseRouting();

// 5. Authentication
app.UseAuthentication();

// 6. Authorization
app.UseAuthorization();

// 7. Endpoints (last)
app.MapControllers();
```

### For Localhost-Only Services
```csharp
// Skip HTTPS redirection for localhost-only service
// Skip authorization for localhost-only service

app.UseSerilogRequestLogging();
app.UseSwagger();
app.UseSwaggerUI();
app.MapControllers();
```

## Error Handling Pattern

### Global Exception Handling
```csharp
try
{
    var builder = WebApplication.CreateBuilder(args);
    // ... configuration ...

    var app = builder.Build();
    // ... middleware ...

    app.Run();
}
catch (Exception ex)
{
    Log.Fatal(ex, "Application terminated unexpectedly");
}
finally
{
    Log.CloseAndFlush();
}
```

### Benefits
- Catches startup errors
- Logs fatal exceptions
- Ensures log flush on shutdown

## Controller Mapping

### Traditional Controllers
```csharp
builder.Services.AddControllers();
// ...
app.MapControllers();
```

### With Minimal APIs
```csharp
app.MapGet("/health", () => Results.Ok(new { Status = "Healthy" }));
```

### Both Together
```csharp
builder.Services.AddControllers();
// ...
app.MapControllers();
app.MapGet("/health", () => Results.Ok());
```

## Configuration Sources

### Default Order (later overrides earlier)
1. appsettings.json
2. appsettings.{Environment}.json
3. User secrets (Development)
4. Environment variables
5. Command line arguments

### Accessing Configuration
```csharp
var port = builder.Configuration.GetValue<int>("Port");
var connectionString = builder.Configuration.GetConnectionString("Default");
```

## ContPAQWinBridge Specifics

### Localhost-Only Design
The Windows Bridge service:
- Runs only on 127.0.0.1:5000
- Called only by the desktop app
- No external network access
- No need for HTTPS or auth

### Service Architecture
```
Desktop App (Electron)
    ↓
    HTTP (localhost:5000)
    ↓
Windows Bridge (ASP.NET Core)
    ↓
    COM Interop
    ↓
ContPAQi SDK
```

## Key Takeaways

1. **Top-level statements** simplify Program.cs
2. **WebApplication.CreateBuilder** provides sensible defaults
3. **Middleware order** is critical
4. **Serilog bootstrap** catches startup errors
5. **try-catch-finally** ensures proper shutdown
6. **Swagger** enables API documentation

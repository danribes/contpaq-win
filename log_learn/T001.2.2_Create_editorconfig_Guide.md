# Learning Guide: T001.2.2 - EditorConfig Configuration

## What is EditorConfig?

EditorConfig is a file format and collection of text editor plugins for maintaining consistent coding styles between different editors and IDEs.

## Why Do We Need It?

Without EditorConfig, team members using different editors might:
- Use tabs vs. spaces inconsistently
- Have different indentation sizes
- Use different line endings (LF vs. CRLF)
- Create files with different character encodings

This leads to:
- Noisy git diffs (whitespace changes mixed with real changes)
- Merge conflicts over formatting
- Inconsistent code appearance
- CI/CD failures on style checks

## How EditorConfig Works

```
1. Developer opens a file in their editor
         │
         ▼
2. Editor plugin looks for .editorconfig
         │
         ▼
3. Plugin searches up directory tree until:
   - Finds .editorconfig with root = true, OR
   - Reaches filesystem root
         │
         ▼
4. Settings are merged (closest file wins)
         │
         ▼
5. Editor applies settings automatically
```

## File Format Explained

### Root Setting
```ini
root = true
```
Stops the editor from looking in parent directories. Essential for project isolation.

### Section Headers
```ini
[*]              # All files
[*.py]           # Python files only
[*.{ts,tsx}]     # TypeScript files
[Makefile]       # Exact filename match
[lib/**.js]      # Files in lib/ directory
```

### Common Properties

| Property | Values | Description |
|----------|--------|-------------|
| `indent_style` | `space`, `tab` | Soft tabs vs. hard tabs |
| `indent_size` | integer | Number of columns per indent |
| `end_of_line` | `lf`, `crlf`, `cr` | Line ending style |
| `charset` | `utf-8`, `latin1`, etc. | Character encoding |
| `trim_trailing_whitespace` | `true`, `false` | Remove trailing spaces on save |
| `insert_final_newline` | `true`, `false` | Ensure file ends with newline |

## Language-Specific Conventions

### Python (PEP 8)
```ini
[*.py]
indent_style = space
indent_size = 4        # PEP 8 standard
max_line_length = 88   # Black formatter default
```

### TypeScript/JavaScript
```ini
[*.{ts,tsx,js,jsx}]
indent_style = space
indent_size = 2        # Common in JS ecosystem
```

### C# (.NET)
```ini
[*.cs]
indent_style = space
indent_size = 4        # Microsoft convention
```

## Special Cases

### Markdown
```ini
[*.md]
trim_trailing_whitespace = false
```
Markdown uses trailing spaces for line breaks (`  \n` = `<br>`).

### Makefiles
```ini
[Makefile]
indent_style = tab
```
Makefiles **require** tabs for recipe indentation. Spaces will cause syntax errors.

### Windows Scripts
```ini
[*.{ps1,bat,cmd}]
end_of_line = crlf
```
Windows scripts may fail with LF line endings.

## Editor Support

### Native Support (no plugin needed)
- Visual Studio 2017+
- JetBrains IDEs (IntelliJ, WebStorm, Rider, PyCharm)
- GitHub (displays .editorconfig-aware formatting)

### Plugin Required
- **VS Code**: EditorConfig for VS Code
- **Vim**: editorconfig-vim
- **Sublime Text**: EditorConfig package
- **Atom**: editorconfig package

## Relationship with Other Tools

### EditorConfig vs. Prettier
- **EditorConfig**: Editor-level formatting (live as you type)
- **Prettier**: Build-time formatting (formats on save/commit)

Use both! EditorConfig for live editing, Prettier for enforced formatting.

### EditorConfig vs. ESLint/Black
- **EditorConfig**: Basic formatting (indentation, line endings)
- **Linters**: Advanced rules (naming, complexity, patterns)

EditorConfig handles the basics, linters handle the rest.

## Best Practices

1. **Always set `root = true`** - Prevents inheriting settings from parent directories

2. **Start with sensible defaults** - Set `[*]` section first, then override for specific files

3. **Match your linter settings** - If Black uses 88 chars, set `max_line_length = 88`

4. **Document exceptions** - Add comments for non-obvious settings

5. **Commit to version control** - Everyone should use the same settings

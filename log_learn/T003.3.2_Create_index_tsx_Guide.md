# Learning Guide: T003.3.2 - Create desktop-app/src/renderer/index.tsx

## Overview

This guide covers creating a React 18 entry point for an Electron renderer process, including proper bootstrapping and error handling.

## Concepts Covered

### 1. React 18 Entry Point

React 18 introduced a new root API that replaces `ReactDOM.render()`:

```typescript
// React 17 (deprecated)
import ReactDOM from 'react-dom';
ReactDOM.render(<App />, document.getElementById('root'));

// React 18 (current)
import { createRoot } from 'react-dom/client';
const root = createRoot(document.getElementById('root')!);
root.render(<App />);
```

Benefits of the new API:
- Enables concurrent features
- Better batching of updates
- Automatic batching for promises, timeouts
- More consistent behavior

### 2. StrictMode

StrictMode is a development tool that helps find bugs:

```typescript
import { StrictMode } from 'react';

root.render(
  <StrictMode>
    <App />
  </StrictMode>
);
```

What StrictMode does:
- **Double-renders** components to find side effects
- **Double-invokes** effects to find cleanup issues
- Warns about **deprecated APIs**
- Warns about **legacy context API**
- Warns about **unsafe lifecycles**

### 3. Error Handling for Missing Root

Always check that the root element exists:

```typescript
const rootElement = document.getElementById('root');

if (!rootElement) {
  throw new Error('Critical: Root element not found');
}

const root = createRoot(rootElement);
```

Alternatively, use TypeScript's non-null assertion:

```typescript
// Less safe, but more concise
const root = createRoot(document.getElementById('root')!);
```

### 4. Import Organization

Follow a consistent import order:

```typescript
// 1. React and React-related
import React, { StrictMode } from 'react';
import { createRoot } from 'react-dom/client';

// 2. Third-party libraries (if any)
// import { Provider } from 'react-redux';

// 3. Local components
import App from './App';

// 4. Styles (always last)
import './styles/index.css';
```

### 5. Tailwind CSS Integration

The entry point imports the main CSS file which includes Tailwind:

```typescript
import './styles/index.css';
```

The CSS file contains Tailwind directives:

```css
/* styles/index.css */
@tailwind base;
@tailwind components;
@tailwind utilities;

/* Custom styles below */
```

## Code Example

### Complete Entry Point

```typescript
/**
 * React Application Entry Point
 *
 * Bootstraps the React application with:
 * - React 18 concurrent features
 * - StrictMode for development checks
 * - Tailwind CSS styling
 */

import React, { StrictMode } from 'react';
import { createRoot } from 'react-dom/client';

import App from './App';
import './styles/index.css';

// Get the root element
const rootElement = document.getElementById('root');

// Ensure root element exists
if (!rootElement) {
  throw new Error(
    'Error crítico: No se encontró el elemento root. ' +
    'Verifique que index.html contiene <div id="root"></div>'
  );
}

// Create and render
const root = createRoot(rootElement);

root.render(
  <StrictMode>
    <App />
  </StrictMode>
);
```

## Best Practices

### 1. Always Use StrictMode in Development

```typescript
// Development: Use StrictMode
root.render(
  <StrictMode>
    <App />
  </StrictMode>
);

// Note: StrictMode has no effect in production builds
```

### 2. Provide Descriptive Error Messages

Use the target language for error messages:

```typescript
// For Spanish-speaking users
throw new Error(
  'Error crítico: No se encontró el elemento root.'
);

// For English-speaking users
throw new Error(
  'Critical error: Root element not found.'
);
```

### 3. Keep Entry Point Minimal

The entry point should only:
- Import dependencies
- Get root element
- Create root
- Render app

Complex logic belongs in App or other components.

### 4. Import Styles in Entry Point

Import global styles in the entry point so they're available everywhere:

```typescript
// Import order: React → Components → Styles
import App from './App';
import './styles/index.css';  // Global styles
```

## Common Patterns

### With Redux Provider

```typescript
import { Provider } from 'react-redux';
import { store } from './store';

root.render(
  <StrictMode>
    <Provider store={store}>
      <App />
    </Provider>
  </StrictMode>
);
```

### With Router

```typescript
import { BrowserRouter } from 'react-router-dom';

root.render(
  <StrictMode>
    <BrowserRouter>
      <App />
    </BrowserRouter>
  </StrictMode>
);
```

### With Multiple Providers

```typescript
root.render(
  <StrictMode>
    <Provider store={store}>
      <ThemeProvider theme={theme}>
        <BrowserRouter>
          <App />
        </BrowserRouter>
      </ThemeProvider>
    </Provider>
  </StrictMode>
);
```

## Common Issues

### Issue: "Cannot find module './App'"
**Cause**: App.tsx doesn't exist yet
**Solution**: Create App.tsx (T003.3.3) before running the app

### Issue: StrictMode Double-Rendering
**Cause**: Normal StrictMode behavior in development
**Solution**: This is expected; effects run twice to catch bugs

### Issue: CSS Not Loading
**Cause**: Missing or incorrect path to CSS file
**Solution**: Verify styles/index.css exists and path is correct

### Issue: TypeScript Error on getElementById
**Cause**: getElementById returns `HTMLElement | null`
**Solution**: Use non-null assertion (`!`) or explicit check

## Electron-Specific Considerations

### Context Isolation

In Electron with context isolation, the renderer has limited access:

```typescript
// The entry point runs in the renderer process
// It cannot access Node.js APIs directly
// Use preload script for IPC communication
```

### Window Object

For Electron apps, the window object includes preload APIs:

```typescript
// TypeScript declaration (in types/index.ts)
declare global {
  interface Window {
    electronAPI: ElectronAPI;
  }
}
```

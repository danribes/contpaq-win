# T004.3.1 Learning Guide: ASP.NET Core Controllers

## Overview
This guide covers ASP.NET Core API controller structure, base controllers, and common patterns for REST APIs.

## Key Concepts

### 1. Controller Basics
Controllers handle HTTP requests and return responses:

```csharp
[ApiController]
[Route("api/[controller]")]
public class ProductsController : ControllerBase
{
    [HttpGet]
    public IActionResult GetAll() => Ok(products);

    [HttpGet("{id}")]
    public IActionResult GetById(int id) => Ok(product);

    [HttpPost]
    public IActionResult Create(Product product) => Created(uri, product);
}
```

### 2. [ApiController] Attribute
Enables API-specific behaviors:

| Feature | Behavior |
|---------|----------|
| Model validation | Automatic 400 response for invalid models |
| Binding source inference | `[FromBody]`, `[FromRoute]` inferred |
| Problem details | Standardized error responses |
| Required attribute | Non-nullable types required by default |

```csharp
// Without [ApiController] - manual validation
[HttpPost]
public IActionResult Create(Product product)
{
    if (!ModelState.IsValid)
        return BadRequest(ModelState);
    // ...
}

// With [ApiController] - automatic
[HttpPost]
public IActionResult Create(Product product)
{
    // ModelState already validated
    // ...
}
```

### 3. Routing Patterns

```csharp
// Route templates
[Route("api/[controller]")]      // api/products
[Route("api/v1/[controller]")]   // api/v1/products

// Action routes
[HttpGet]                        // GET api/products
[HttpGet("{id}")]                // GET api/products/5
[HttpGet("search")]              // GET api/products/search
[HttpGet("{id}/details")]        // GET api/products/5/details
```

### 4. Base Controller Pattern
Create a base class for shared functionality:

```csharp
[ApiController]
[Route("api/[controller]")]
[Produces("application/json")]
public abstract class BaseController : ControllerBase
{
    // Shared properties
    protected ILogger Logger { get; }

    // Shared methods
    protected ObjectResult ErrorResponse(string message, int code = 500)
    {
        return StatusCode(code, new { error = message });
    }
}

// Derived controller
public class ProductsController : BaseController
{
    // Inherits attributes and methods
}
```

### 5. Action Results

| Method | HTTP Status | Use Case |
|--------|-------------|----------|
| `Ok()` | 200 | Successful GET |
| `Created()` | 201 | Successful POST |
| `NoContent()` | 204 | Successful DELETE |
| `BadRequest()` | 400 | Invalid input |
| `NotFound()` | 404 | Resource not found |
| `Conflict()` | 409 | Duplicate/conflict |
| `StatusCode()` | Any | Custom status |

```csharp
[HttpGet("{id}")]
public IActionResult GetById(int id)
{
    var item = _repo.Find(id);
    if (item == null)
        return NotFound();
    return Ok(item);
}
```

### 6. Dependency Injection in Controllers

```csharp
public class ProductsController : BaseController
{
    private readonly IProductService _service;
    private readonly ILogger<ProductsController> _logger;

    public ProductsController(
        IProductService service,
        ILogger<ProductsController> logger)
    {
        _service = service;
        _logger = logger;
    }

    [HttpGet]
    public async Task<IActionResult> GetAll()
    {
        _logger.LogInformation("Getting all products");
        var products = await _service.GetAllAsync();
        return Ok(products);
    }
}
```

### 7. Request/Response Handling

```csharp
// Reading request headers
var correlationId = Request.Headers["X-Correlation-ID"];

// Setting response headers
Response.Headers.Add("X-Custom-Header", "value");

// Reading route values
var id = RouteData.Values["id"];

// Reading query string
var page = Request.Query["page"];
```

## Best Practices

### 1. Controller Organization
```
Controllers/
├── BaseController.cs          # Abstract base class
├── HealthController.cs        # Health checks
├── VendorsController.cs       # Vendor operations
├── EntriesController.cs       # Entry operations
└── Admin/                     # Admin-specific controllers
    └── ConfigController.cs
```

### 2. Single Responsibility
Each controller handles one resource:
```csharp
// Good - single responsibility
public class VendorsController : BaseController { }
public class EntriesController : BaseController { }

// Bad - multiple resources
public class ContPAQiController : BaseController
{
    // Vendors + Entries + Companies... too many responsibilities
}
```

### 3. Thin Controllers
Keep controllers thin, delegate to services:
```csharp
// Good - delegates to service
[HttpPost]
public async Task<IActionResult> Create(CreateEntryRequest request)
{
    var result = await _entryService.CreateAsync(request);
    return result.IsSuccess
        ? Created($"api/entries/{result.Value.Id}", result.Value)
        : BadRequest(result.Error);
}

// Bad - business logic in controller
[HttpPost]
public async Task<IActionResult> Create(CreateEntryRequest request)
{
    // Validation logic here...
    // Business rules here...
    // Database operations here...
    // All mixed together - hard to test
}
```

### 4. Standardized Responses
Use consistent response format:
```csharp
public class ApiResponse<T>
{
    public bool Success { get; set; }
    public string? Message { get; set; }
    public T? Data { get; set; }
    public DateTime Timestamp { get; set; } = DateTime.UtcNow;
}
```

## Common Patterns

### Correlation ID Tracking
```csharp
protected string? GetCorrelationId()
{
    return Request.Headers.TryGetValue("X-Correlation-ID", out var value)
        ? value.ToString()
        : HttpContext.TraceIdentifier;
}
```

### Pagination
```csharp
[HttpGet]
public IActionResult GetAll([FromQuery] int page = 1, [FromQuery] int pageSize = 20)
{
    var items = _service.GetPaged(page, pageSize);
    Response.Headers.Add("X-Total-Count", items.TotalCount.ToString());
    return Ok(items.Data);
}
```

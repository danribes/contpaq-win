# T004.3.3 Learning Guide: API Response Models

## Overview
This guide covers API response model design patterns for consistent, well-structured API responses.

## Key Concepts

### 1. Standardized API Responses
Use consistent response structure across all endpoints:

```csharp
// All responses follow same structure
{
  "success": true,
  "message": "Operación exitosa",
  "data": { ... },
  "timestamp": "2025-12-16T00:00:00Z"
}
```

### 2. Generic Response Wrapper
Create a generic wrapper for typed responses:

```csharp
public record ApiResponse<T>
{
    public bool Success { get; init; }
    public string? Message { get; init; }
    public T? Data { get; init; }
    public ErrorDetails? Error { get; init; }
    public DateTime Timestamp { get; init; }
}

// Usage
return ApiResponse<VendorDto>.Ok(vendor, "Proveedor encontrado");
return ApiResponse<VendorDto>.Fail("Proveedor no encontrado", "NOT_FOUND");
```

### 3. Factory Methods
Provide convenient factory methods:

```csharp
public record ApiResponse<T>
{
    // Success factory
    public static ApiResponse<T> Ok(T data, string? message = null) => new()
    {
        Success = true,
        Data = data,
        Message = message
    };

    // Failure factory
    public static ApiResponse<T> Fail(string message, string? code = null) => new()
    {
        Success = false,
        Message = message,
        Error = new ErrorDetails { Code = code, Message = message }
    };
}
```

### 4. Error Details Structure
Structured error information for clients:

```csharp
public record ErrorDetails
{
    public string? Code { get; init; }        // "NOT_FOUND", "VALIDATION_ERROR"
    public string? Message { get; init; }     // Human-readable message
    public string? Details { get; init; }     // Additional info (dev only)
    public string? CorrelationId { get; init; } // Request tracking
}
```

### 5. Health Check Models
Standardized health check responses:

```csharp
public record HealthResponse
{
    public string Status { get; init; }       // "Healthy", "Degraded", "Unhealthy"
    public DateTime Timestamp { get; init; }
    public string? Version { get; init; }
    public ComponentHealth Components { get; init; }
}

// Component-level health
public record ComponentStatus
{
    public string Status { get; init; }
    public bool IsAvailable { get; init; }
    public string? Version { get; init; }
}
```

## Best Practices

### 1. Use Records for Immutability
```csharp
// Good - immutable record
public record ApiResponse<T>
{
    public bool Success { get; init; }
}

// Avoid - mutable class
public class ApiResponse<T>
{
    public bool Success { get; set; }  // Mutable
}
```

### 2. Include Timestamps
```csharp
public record ApiResponse<T>
{
    public DateTime Timestamp { get; init; } = DateTime.UtcNow;
}
```

### 3. Separate Success and Error Data
```csharp
// Good - clear separation
public record ApiResponse<T>
{
    public T? Data { get; init; }        // Only on success
    public ErrorDetails? Error { get; init; } // Only on failure
}

// Avoid - ambiguous
public record ApiResponse<T>
{
    public T? Result { get; init; }  // Could be data or error
}
```

### 4. Use Constants for Status Values
```csharp
public static class HealthStatus
{
    public const string Healthy = "Healthy";
    public const string Degraded = "Degraded";
    public const string Unhealthy = "Unhealthy";
}

// Usage
Status = HealthStatus.Healthy;
```

### 5. Controller Usage Pattern
```csharp
[HttpGet("{rfc}")]
public async Task<ActionResult<ApiResponse<VendorDto>>> GetByRfc(string rfc)
{
    var vendor = await _vendorService.GetByRfcAsync(rfc);

    if (vendor == null)
        return NotFound(ApiResponse<VendorDto>.Fail(
            "Proveedor no encontrado",
            "NOT_FOUND"));

    return Ok(ApiResponse<VendorDto>.Ok(vendor));
}
```

## JSON Serialization

### Response Examples

```json
// Success response
{
  "success": true,
  "message": "Proveedor encontrado",
  "data": {
    "code": "PROV001",
    "rfc": "ABC123456789",
    "name": "Proveedor Ejemplo SA de CV"
  },
  "error": null,
  "timestamp": "2025-12-16T12:00:00Z"
}

// Error response
{
  "success": false,
  "message": "Proveedor no encontrado",
  "data": null,
  "error": {
    "code": "NOT_FOUND",
    "message": "Proveedor no encontrado",
    "details": null,
    "correlationId": "abc-123-def"
  },
  "timestamp": "2025-12-16T12:00:00Z"
}

// Health response
{
  "status": "Healthy",
  "timestamp": "2025-12-16T12:00:00Z",
  "version": "1.0.0",
  "components": {
    "sdk": {
      "status": "Healthy",
      "isAvailable": true,
      "version": "15.0.0"
    },
    "database": null
  }
}
```

# T006.1.1 Learning Guide: Health Check Endpoint

## Overview

This guide explains the implementation of a health check endpoint for the AI service using FastAPI. Health endpoints are essential for monitoring service availability and operational status.

## What is a Health Check Endpoint?

A health check endpoint is an HTTP endpoint that:
- Returns service status information
- Allows monitoring systems to verify service availability
- Provides operational data (version, dependencies, etc.)
- Is typically exposed at `/health` or `/healthz`

## Key Concepts

### 1. FastAPI APIRouter

```python
from fastapi import APIRouter

router = APIRouter()

@router.get("/health")
async def health_check():
    return {"status": "healthy"}
```

The `APIRouter` allows organizing routes into modules that can be included in the main FastAPI application.

### 2. Pydantic Response Models

```python
from pydantic import BaseModel

class HealthResponse(BaseModel):
    status: str
    timestamp: str
    version: str
    models_loaded: bool
    ocr_available: bool
```

Using Pydantic models for responses provides:
- Type validation
- Automatic JSON serialization
- OpenAPI documentation generation
- IDE autocompletion

### 3. Async Endpoints

```python
@router.get("/health", response_model=HealthResponse)
async def health_check() -> HealthResponse:
    return HealthResponse(...)
```

FastAPI supports both sync and async endpoints. Async is preferred for I/O-bound operations.

### 4. Health Check Components

A typical health response includes:

| Field | Type | Purpose |
|-------|------|---------|
| status | string | Overall health ("healthy", "degraded", "unhealthy") |
| timestamp | string | Current server time (ISO 8601 format) |
| version | string | Service version for debugging |
| models_loaded | boolean | AI model availability |
| ocr_available | boolean | OCR service availability |

### 5. Dependency Checks

```python
def check_ocr_available() -> bool:
    import shutil
    # Check if tesseract is in PATH
    if shutil.which("tesseract") is not None:
        return True
    # Check common Windows paths
    ...
    return False
```

Health endpoints often check:
- Database connectivity
- External service availability
- Required dependencies (OCR, AI models)
- Memory/CPU resources

## Testing Health Endpoints

### Using FastAPI TestClient

```python
from fastapi import FastAPI
from fastapi.testclient import TestClient
from api.routes import router

app = FastAPI()
app.include_router(router)
client = TestClient(app)

def test_health_returns_200():
    response = client.get("/health")
    assert response.status_code == 200
```

### Testing Response Structure

```python
def test_health_has_required_fields():
    response = client.get("/health")
    data = response.json()

    assert "status" in data
    assert "timestamp" in data
    assert data["status"] == "healthy"
```

## Best Practices

1. **Always Return 200**: Health endpoints should return 200 even if dependencies are unavailable - include status in the response body instead.

2. **Use UTC Timestamps**: Always use timezone-aware UTC timestamps:
   ```python
   from datetime import datetime, timezone
   timestamp = datetime.now(timezone.utc).isoformat()
   ```

3. **Include Version**: Makes debugging production issues easier.

4. **Check Critical Dependencies**: Report status of databases, external services, required files.

5. **Keep It Fast**: Health checks are called frequently by load balancers - avoid expensive operations.

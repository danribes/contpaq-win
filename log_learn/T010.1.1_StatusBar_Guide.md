# T010.1.1 Learning Guide: StatusBar React Component with Tailwind

## Overview

This guide covers creating a status bar component in React with Tailwind CSS for displaying service status information in a desktop application.

## Key Concepts

### 1. Status Indicator Pattern

Use colored dots to indicate service status at a glance:

```typescript
function getStatusColor(status: ServiceStatus): string {
  switch (status) {
    case 'running':
      return 'bg-green-500';
    case 'starting':
    case 'stopping':
      return 'bg-yellow-400';
    case 'error':
      return 'bg-red-500';
    case 'stopped':
    default:
      return 'bg-gray-400';
  }
}
```

### 2. Internationalization (i18n)

Map status codes to user-friendly text:

```typescript
function getStatusText(status: ServiceStatus): string {
  switch (status) {
    case 'running':
      return 'Activo';      // Active
    case 'starting':
      return 'Iniciando...'; // Starting...
    case 'stopping':
      return 'Deteniendo...'; // Stopping...
    case 'stopped':
      return 'Detenido';    // Stopped
    case 'error':
      return 'Error';
    default:
      return 'Desconocido'; // Unknown
  }
}
```

### 3. Conditional Rendering

Only render elements when data is available:

```tsx
{companyName && companyName.length > 0 && (
  <span data-testid="company-name">
    {companyName}
  </span>
)}
```

## Code Patterns

### Status Indicator Component

```tsx
interface StatusIndicatorProps {
  status: ServiceStatus;
  testId: string;
}

function StatusIndicator({ status, testId }: StatusIndicatorProps): JSX.Element {
  return (
    <span
      data-testid={testId}
      className={`w-2 h-2 rounded-full ${getStatusColor(status)}`}
    />
  );
}
```

### Complete StatusBar Structure

```tsx
export function StatusBar({
  aiStatus,
  bridgeStatus,
  companyName,
}: StatusBarProps): JSX.Element {
  return (
    <div className="bg-white border-t border-gray-200 px-4 py-2">
      <div className="flex items-center justify-between">
        {/* Left: Status items */}
        <div className="flex items-center space-x-4">
          <span className="flex items-center space-x-2">
            <StatusIndicator status={aiStatus} testId="ai-status-indicator" />
            <span>AI Service: {getStatusText(aiStatus)}</span>
          </span>
          {/* More status items... */}
        </div>

        {/* Right: Version info */}
        <span>v0.1.0</span>
      </div>
    </div>
  );
}
```

## Testing Strategies

### 1. Testing Component Export

```tsx
it('should export StatusBar component', async () => {
  const module = await import('../components/StatusBar');
  expect(module.StatusBar).toBeDefined();
});
```

### 2. Testing Text Content

```tsx
it('should display status text', async () => {
  render(<StatusBar aiStatus="running" bridgeStatus="stopped" />);
  expect(screen.getByText(/AI Service: Activo/i)).toBeInTheDocument();
});
```

### 3. Testing CSS Classes with data-testid

```tsx
it('should show green indicator when running', async () => {
  render(<StatusBar aiStatus="running" bridgeStatus="stopped" />);
  const indicator = screen.getByTestId('ai-status-indicator');
  expect(indicator).toHaveClass('bg-green-500');
});
```

### 4. Testing Conditional Rendering

```tsx
it('should not display company when not provided', async () => {
  render(<StatusBar aiStatus="running" bridgeStatus="running" />);
  expect(screen.queryByTestId('company-name')).not.toBeInTheDocument();
});
```

### 5. Testing Multiple Elements

```tsx
it('should display both services', async () => {
  render(<StatusBar aiStatus="running" bridgeStatus="error" />);

  const aiIndicator = screen.getByTestId('ai-status-indicator');
  const bridgeIndicator = screen.getByTestId('bridge-status-indicator');

  expect(aiIndicator).toHaveClass('bg-green-500');
  expect(bridgeIndicator).toHaveClass('bg-red-500');
});
```

## Common Pitfalls

### 1. Multiple Matching Elements

**Problem**: `getByText` fails when multiple elements match.

**Solution**: Use more specific selectors or `getAllByText`:
```tsx
// Instead of:
expect(screen.getByText(/Activo/i)).toBeInTheDocument();

// Use:
expect(screen.getByText(/AI Service: Activo/i)).toBeInTheDocument();
// or
const activeElements = screen.getAllByText(/Activo/i);
expect(activeElements.length).toBeGreaterThanOrEqual(1);
```

### 2. Testing Dynamic Classes

**Problem**: Class changes based on props.

**Solution**: Use `toHaveClass()` to check specific classes:
```tsx
expect(element).toHaveClass('bg-green-500');
```

### 3. Import Path Errors

**Problem**: Jest can't find module.

**Solution**: Verify relative paths from test file:
```
tests/renderer/components/StatusBar.test.tsx
     → ../../../src/renderer/components/StatusBar
```

## Best Practices

1. **Use data-testid**: Add test IDs for elements that need specific testing
2. **Separate Concerns**: Extract helper functions for status mapping
3. **Conditional Rendering**: Only show elements when data is available
4. **Tailwind Utilities**: Use utility classes for consistent styling
5. **Type Safety**: Define props interface with proper types
6. **Default Props**: Provide sensible defaults where applicable

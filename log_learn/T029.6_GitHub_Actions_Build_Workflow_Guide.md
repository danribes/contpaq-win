## What is GitHub Actions?

GitHub Actions is a CI/CD (Continuous Integration/Continuous Deployment) platform that allows you to automate your build, test, and deployment pipelines directly from your GitHub repository.

### Key Concepts

1. **Workflow**: A configurable automated process defined in YAML
2. **Job**: A set of steps that execute on the same runner
3. **Step**: An individual task that runs commands or actions
4. **Runner**: A server that runs your workflows (GitHub-hosted or self-hosted)
5. **Action**: A reusable unit of code (e.g., `actions/checkout@v4`)

## Workflow File Structure

Workflows are stored in `.github/workflows/` directory:

```yaml
name: Build Installer       # Workflow name (shown in GitHub UI)

on:                         # Trigger conditions
  push:
    tags:
      - 'v*'               # Trigger on version tags
  workflow_dispatch:        # Allow manual trigger
    inputs:
      version:
        description: 'Version number'
        required: false
        default: '0.1.0'

permissions:                # Required permissions
  contents: write          # For creating releases
  issues: write            # For creating issues on failure

env:                        # Global environment variables
  PYTHON_VERSION: '3.11'
  NODE_VERSION: '20'

jobs:
  build:
    name: Build Windows Installer
    runs-on: windows-latest  # Use Windows runner

    steps:
      - name: Checkout repository
        uses: actions/checkout@v4
```

## Building Multi-Technology Projects

### 1. Setting Up Build Environments

Each technology needs its own setup step:

```yaml
# Python
- name: Setup Python
  uses: actions/setup-python@v5
  with:
    python-version: '3.11'
    cache: 'pip'
    cache-dependency-path: 'ai-service/requirements.txt'

# Node.js
- name: Setup Node.js
  uses: actions/setup-node@v4
  with:
    node-version: '20'
    cache: 'npm'
    cache-dependency-path: 'desktop-app/package-lock.json'

# .NET
- name: Setup .NET
  uses: actions/setup-dotnet@v4
  with:
    dotnet-version: '8.0.x'
```

### 2. Building Python with PyInstaller

```yaml
- name: Build AI Service
  shell: pwsh
  working-directory: ai-service
  run: |
    pip install -r requirements.txt
    pip install pyinstaller
    pyinstaller --onefile --name contpaq-ai-service src/main.py
```

### 3. Building .NET as Single-File Executable

```yaml
- name: Build Windows Bridge
  shell: pwsh
  working-directory: windows-bridge/src
  run: |
    dotnet publish ContPAQWinBridge/ContPAQWinBridge.csproj `
      -c Release `
      -r win-x64 `
      --self-contained true `
      -o ContPAQWinBridge/bin/publish/win-x64 `
      /p:PublishSingleFile=true
```

### 4. Building Electron App

Electron apps require special handling due to native modules:

```yaml
- name: Build Desktop App
  shell: pwsh
  working-directory: desktop-app
  env:
    ELECTRON_MIRROR: https://npmmirror.com/mirrors/electron/
  run: |
    npm ci
    npm run build

    # Remove problematic native modules
    if (Test-Path "node_modules/canvas") {
      Remove-Item -Recurse -Force "node_modules/canvas"
    }

    npm run package
```

## Handling Native Modules

### The Canvas Problem

`canvas` is a native module that requires Cairo/GTK libraries. These aren't available on GitHub Actions runners.

**Solutions:**

1. **Remove before packaging** (used in this project):
```yaml
Remove-Item -Recurse -Force "node_modules/canvas"
```

2. **Exclude from electron-builder**:
```json
{
  "files": [
    "!**/canvas/**"
  ]
}
```

3. **Skip optional dependencies**:
```bash
npm ci --ignore-optional
```

## Vite Configuration for Electron

Electron apps with Vite need special configuration:

```typescript
// vite.config.ts
import { defineConfig } from 'vite';
import path from 'path';

export default defineConfig({
  // Set root to where index.html is located
  root: path.resolve(__dirname, 'src/renderer'),

  build: {
    outDir: path.resolve(__dirname, 'dist/renderer'),
  },

  // Externalize electron modules
  rollupOptions: {
    external: ['electron', 'better-sqlite3'],
  },
});
```

## Retry Logic for Network Issues

GitHub Actions runners sometimes have network issues. Implement retry logic:

```powershell
$maxRetries = 4
for ($i = 1; $i -le $maxRetries; $i++) {
  Write-Host "Attempt $i of $maxRetries..."
  npm ci
  if ($LASTEXITCODE -eq 0) {
    Write-Host "Success"
    break
  }
  if ($i -lt $maxRetries) {
    $waitTime = [math]::Pow(2, $i)  # Exponential backoff
    Write-Host "Failed, retrying in $waitTime seconds..."
    Start-Sleep -Seconds $waitTime
    Remove-Item -Recurse -Force "node_modules" -ErrorAction SilentlyContinue
  } else {
    throw "Failed after $maxRetries attempts"
  }
}
```

## Downloading External Dependencies

Some files aren't in the repository and need downloading:

```powershell
# Download NSSM
$nssmUrl = "https://nssm.cc/release/nssm-2.24.zip"
Invoke-WebRequest -Uri $nssmUrl -OutFile "$env:TEMP\nssm.zip"

```

## Creating Releases

### Upload Artifact

```yaml
- name: Upload installer artifact
  uses: actions/upload-artifact@v4
  with:
    name: ContPaq-proPDF-Installer
    path: installer/output/*.exe
    retention-days: 30
```

### Create GitHub Release

```yaml
- name: Create Release
  if: startsWith(github.ref, 'refs/tags/')
  uses: softprops/action-gh-release@v1
  with:
    name: ContPaq-proPDF v${{ steps.version.outputs.VERSION }}
    body: |
      ## Installation
      1. Download the installer
      2. Run as Administrator
      3. Follow the wizard
    files: |
      ${{ env.INSTALLER_PATH }}
  env:
    GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
```

## Failure Notification

Create an issue when the build fails:

```yaml
notify-failure:
  runs-on: ubuntu-latest
  needs: build
  if: failure()
  steps:
    - uses: actions/github-script@v7
      with:
        script: |
          await github.rest.issues.create({
            owner: context.repo.owner,
            repo: context.repo.repo,
            title: `Build failed for ${context.ref}`,
            body: `Check the [workflow run](${context.serverUrl}/.../runs/${context.runId})`,
            labels: ['bug', 'build']
          });
```

## Best Practices

### 1. Use Caching
```yaml
- uses: actions/setup-node@v4
  with:
    cache: 'npm'
    cache-dependency-path: 'package-lock.json'
```

### 2. Set Timeouts
```yaml
jobs:
  build:
    timeout-minutes: 30
```

### 3. Use Matrix for Multiple Platforms
```yaml
strategy:
  matrix:
    os: [windows-latest, macos-latest]
```

### 4. Fail Fast
```yaml
strategy:
  fail-fast: true
```

### 5. Use Specific Action Versions
```yaml
# Good
uses: actions/checkout@v4

# Bad
uses: actions/checkout@latest
```

## Debugging Tips

1. **Enable Debug Logging**
   - Set secret `ACTIONS_STEP_DEBUG` to `true`

2. **SSH into Runner** (for self-hosted)
   - Use `mxschmitt/action-tmate@v3`

3. **Upload Logs as Artifacts**
   ```yaml
   - uses: actions/upload-artifact@v4
     if: failure()
     with:
       name: logs
       path: '**/*.log'
   ```

4. **Check Exit Codes**
   ```powershell
   if ($LASTEXITCODE -ne 0) {
     throw "Command failed with exit code $LASTEXITCODE"
   }
   ```

## Common Errors and Solutions

| Error | Solution |
|-------|----------|
| `ETIMEDOUT` | Add retry logic with exponential backoff |
| `Cannot find module` | Check if module is optional, may need to install |
| `Permission denied` | Add appropriate permissions to workflow |
| `File not found` | Use `if (Test-Path)` before accessing files |
| `CA1416` warnings | Add `[SupportedOSPlatform]` attribute |

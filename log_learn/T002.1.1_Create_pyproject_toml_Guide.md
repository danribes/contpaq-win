# Learning Guide: T002.1.1 - pyproject.toml Configuration

## What is pyproject.toml?

`pyproject.toml` is the standard configuration file for Python projects, defined in PEP 518 and PEP 621. It replaces older files like `setup.py`, `setup.cfg`, and tool-specific configs.

## Why pyproject.toml?

### Before (Multiple Files)
```
project/
├── setup.py           # Package configuration
├── setup.cfg          # More configuration
├── requirements.txt   # Dependencies
├── .flake8           # Linter config
├── .isort.cfg        # Import sorter config
├── mypy.ini          # Type checker config
└── pytest.ini        # Test runner config
```

### After (Single File)
```
project/
├── pyproject.toml    # Everything in one place!
└── requirements.txt  # Only runtime dependencies
```

## File Structure Explained

### Build System Section
```toml
[build-system]
requires = ["setuptools>=68.0", "wheel"]
build-backend = "setuptools.build_meta"
```

This tells pip how to build your package:
- **requires**: Packages needed to build (not run)
- **build-backend**: Which tool does the building

Common backends:
| Backend | Use Case |
|---------|----------|
| setuptools | Traditional, most compatible |
| hatchling | Modern, fast |
| poetry | Poetry projects |
| flit | Simple packages |

### Project Metadata Section
```toml
[project]
name = "contpaq-win-ai-service"
version = "0.1.0"
description = "AI-powered invoice processing"
requires-python = ">=3.11"
```

Essential fields:
- **name**: Package name (lowercase, hyphens)
- **version**: Semantic versioning (MAJOR.MINOR.PATCH)
- **description**: One-line summary
- **requires-python**: Minimum Python version

### Dependencies
```toml
[project]
dependencies = [
    "fastapi>=0.109.0",
    "uvicorn>=0.27.0",
]

[project.optional-dependencies]
dev = [
    "pytest>=7.4.0",
    "black>=23.12.0",
]
```

Note: We use separate `requirements.txt` files for clearer dependency management.

## Tool Configuration

### Black (Formatter)
```toml
[tool.black]
line-length = 88
target-version = ['py311']
```

Why 88 characters?
- Fits comfortably on most screens
- 10% shorter than PEP 8's 79
- Chosen by Black's author as optimal

### Ruff (Linter)
```toml
[tool.ruff]
line-length = 88
select = ["E", "W", "F", "I", "B", "C4", "UP"]
```

Rule categories:
| Code | Description |
|------|-------------|
| E | pycodestyle errors |
| W | pycodestyle warnings |
| F | Pyflakes (unused imports, etc.) |
| I | isort (import ordering) |
| B | flake8-bugbear (bug patterns) |
| C4 | flake8-comprehensions |
| UP | pyupgrade (modern syntax) |

### Mypy (Type Checker)
```toml
[tool.mypy]
python_version = "3.11"
disallow_untyped_defs = true
strict_optional = true
```

Strict settings help catch bugs:
```python
# Without types (mypy error)
def process(data):
    return data.upper()

# With types (mypy happy)
def process(data: str) -> str:
    return data.upper()
```

### Pytest
```toml
[tool.pytest.ini_options]
testpaths = ["tests"]
asyncio_mode = "auto"
addopts = "-v --tb=short"
```

Options explained:
- **testpaths**: Where to find tests
- **asyncio_mode**: Auto-handle async tests
- **addopts**: Default command-line options

## Version Specifiers

```toml
dependencies = [
    "fastapi>=0.109.0",      # 0.109.0 or newer
    "fastapi~=0.109.0",      # 0.109.x only
    "fastapi==0.109.0",      # Exactly 0.109.0
    "fastapi>=0.109,<0.110", # Range
]
```

| Specifier | Meaning |
|-----------|---------|
| `>=1.0` | 1.0 or newer |
| `~=1.0` | Compatible (1.x) |
| `==1.0` | Exact version |
| `!=1.0` | Not this version |

## Semantic Versioning

```
MAJOR.MINOR.PATCH
  │     │     │
  │     │     └── Bug fixes (backwards compatible)
  │     └──────── New features (backwards compatible)
  └────────────── Breaking changes
```

Examples:
- `0.1.0` → `0.1.1`: Bug fix
- `0.1.0` → `0.2.0`: New feature
- `0.1.0` → `1.0.0`: Breaking change

## Common Patterns

### Monorepo Structure
```
contpaq-win/
├── ai-service/
│   └── pyproject.toml      # AI service config
├── desktop-app/
│   └── package.json        # Node config
└── windows-bridge/
    └── ContPAQWinBridge.csproj  # .NET config
```

Each component has its own configuration file.

### Development vs. Production
```toml
[project.optional-dependencies]
dev = ["pytest", "black", "mypy"]
test = ["pytest", "pytest-cov"]
```

Install specific groups:
```bash
pip install -e ".[dev]"    # Development
pip install -e ".[test]"   # Testing only
```

## Validation

Check your pyproject.toml:
```bash
# Validate TOML syntax
python -c "import tomllib; tomllib.load(open('pyproject.toml', 'rb'))"

# Build and check package
pip install build
python -m build --check
```

## Related Concepts

### requirements.txt
Still useful for:
- Exact versions for reproducibility
- CI/CD pipelines
- Docker builds

### setup.py
Legacy format, still needed for:
- Complex build steps
- C extensions
- Backwards compatibility

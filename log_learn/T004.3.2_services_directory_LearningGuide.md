# T004.3.2 Learning Guide: Service Layer Interfaces

## Overview
This guide covers service layer design patterns, interface definitions, and DTOs in ASP.NET Core applications.

## Key Concepts

### 1. Service Layer Pattern
The service layer encapsulates business logic:

```
Controller → Service Interface → Service Implementation → SDK/Database
```

Benefits:
- Separation of concerns
- Testability (mock interfaces)
- Flexibility (swap implementations)
- Clean architecture

### 2. Interface Design Principles

```csharp
// Good - specific, cohesive interface
public interface IVendorService
{
    Task<VendorDto?> GetByRfcAsync(string rfc);
    Task<VendorDto> CreateAsync(CreateVendorRequest request);
}

// Bad - too many responsibilities
public interface IContPAQiService
{
    // Vendors + Entries + Reports + Settings... ISP violation
}
```

### 3. Async/Await Pattern
Use async for I/O operations:

```csharp
public interface IVendorService
{
    // Async methods for SDK/database calls
    Task<VendorDto?> GetByRfcAsync(string rfc);

    // Return Task<T> for async operations
    Task<IEnumerable<VendorDto>> SearchAsync(string term, int limit);

    // Use ValueTask for potential sync paths
    ValueTask<bool> ExistsAsync(string rfc);
}
```

### 4. DTO Pattern
Data Transfer Objects separate internal and external data:

```csharp
// Domain/internal model (not exposed)
internal class Vendor
{
    public int Id { get; set; }
    public string InternalCode { get; set; }
    // ... implementation details
}

// DTO (exposed via API)
public record VendorDto
{
    public string Code { get; init; }
    public string Rfc { get; init; }
    public string Name { get; init; }
}
```

### 5. Request/Response Objects
Separate input from output:

```csharp
// Request - what client sends
public record CreateVendorRequest
{
    public required string Rfc { get; init; }
    public required string Name { get; init; }
}

// Response - what client receives
public record VendorDto
{
    public string Code { get; init; }  // Server-generated
    public string Rfc { get; init; }
    public string Name { get; init; }
}
```

### 6. Result Objects
Encapsulate operation outcomes:

```csharp
public record EntryResultDto
{
    public bool Success { get; init; }
    public string? Folio { get; init; }      // On success
    public string? ErrorMessage { get; init; } // On failure
    public DateTime Timestamp { get; init; }
}

// Usage
var result = await _entryService.CreateAsync(request);
if (result.Success)
    return Ok(result);
else
    return BadRequest(result.ErrorMessage);
```

## Best Practices

### 1. Interface Segregation
Split large interfaces:

```csharp
// Instead of one large interface
public interface IVendorService
{
    // Query operations
    Task<VendorDto?> GetByRfcAsync(string rfc);
    Task<IEnumerable<VendorDto>> SearchAsync(string term);

    // Command operations
    Task<VendorDto> CreateAsync(CreateVendorRequest request);
}

// Could be split if needed
public interface IVendorQueryService { /* queries */ }
public interface IVendorCommandService { /* commands */ }
```

### 2. Nullable Reference Types
Be explicit about nullability:

```csharp
// Clearly indicates vendor might not exist
Task<VendorDto?> GetByRfcAsync(string rfc);

// Required properties in DTOs
public record CreateVendorRequest
{
    public required string Rfc { get; init; }  // Required
    public string? CommercialName { get; init; } // Optional
}
```

### 3. Immutable DTOs
Use records for immutability:

```csharp
// Record - immutable, value equality
public record VendorDto
{
    public string Code { get; init; }
    public string Rfc { get; init; }
}

// Create with "with" expression
var updated = vendor with { Name = "New Name" };
```

### 4. Collection Returns
Return interfaces, not concrete types:

```csharp
// Good - returns interface
Task<IEnumerable<VendorDto>> SearchAsync(string term);

// Avoid - exposes implementation
Task<List<VendorDto>> SearchAsync(string term);
```

### 5. Default Parameters
Use defaults for optional parameters:

```csharp
Task<IEnumerable<VendorDto>> SearchAsync(
    string searchTerm,
    int limit = 20,           // Default limit
    int offset = 0,           // Default offset
    bool includeInactive = false);
```

## Interface Design for ContPAQi

### ISdkService
Low-level SDK operations:
```csharp
public interface ISdkService
{
    bool IsAvailable();
    string? GetVersion();
    bool IsConnected { get; }
}
```

### IVendorService
Vendor CRUD operations:
```csharp
public interface IVendorService
{
    Task<VendorDto?> GetByRfcAsync(string rfc);
    Task<IEnumerable<VendorDto>> SearchAsync(string term, int limit);
    Task<VendorDto> CreateAsync(CreateVendorRequest request);
    Task<bool> ExistsAsync(string rfc);
}
```

### IEntryService
Accounting entry operations:
```csharp
public interface IEntryService
{
    Task<EntryResultDto> CreateAsync(CreateEntryRequest request);
    Task<DuplicateCheckResult> CheckDuplicateAsync(...);
    Task<EntryResultDto?> GetByFolioAsync(string folio);
}
```

# T008.3.4 Learning Guide: Restart Logging

## Overview

This guide covers implementing and testing console logging for process restart events. Good logging is essential for debugging and monitoring service health.

## Key Concepts

### 1. Console Log Levels

| Level | Use Case | Example |
|-------|----------|---------|
| `console.log` | Normal operation info | "Restarting service..." |
| `console.warn` | Warning conditions | "Max restarts exceeded" |
| `console.error` | Error conditions | "Restart failed: error" |

### 2. Structured Log Messages

Good log messages include:
- **Service identifier**: `[ai]` or `[bridge]`
- **Action**: "Auto-restarting", "Max exceeded"
- **Context**: Attempt number, max retries, delay

Example: `[ai] Auto-restarting (attempt 1/3) in 1000ms...`

### 3. Testing Console Output

Use Jest spies to capture and verify console calls:

```typescript
const spy = jest.spyOn(console, 'log').mockImplementation();

// Do something that logs
myFunction();

// Verify log was called
expect(spy).toHaveBeenCalled();
expect(spy).toHaveBeenCalledWith(expect.stringContaining('expected text'));

// Clean up
spy.mockRestore();
```

## Code Patterns

### Basic Logging Implementation

```typescript
private handleAutoRestart(service: string): void {
  // Log when disabled
  if (!this.config.enableAutoRestart) {
    console.log(`[${service}] Auto-restart disabled`);
    return;
  }

  // Warn when max exceeded
  if (restartCount >= maxRestarts) {
    console.warn(`[${service}] Max restarts (${maxRestarts}) exceeded`);
    return;
  }

  // Log restart attempt
  console.log(`[${service}] Auto-restarting (attempt ${count}/${max}) in ${delay}ms`);

  // Log failures
  setTimeout(() => {
    this.startService().catch((err) => {
      console.error(`[${service}] Auto-restart failed:`, err);
    });
  }, delay);
}
```

### Log Message Format

```typescript
// Format: [service] Action (context)
`[${service}] ${action} (${context})`

// Examples:
`[ai] Auto-restarting (attempt 1/3) in 1000ms...`
`[bridge] Max restarts (3) exceeded, not restarting`
`[ai] Auto-restart disabled, not restarting`
`[bridge] Auto-restart failed: Error: Connection refused`
```

## Testing Strategies

### 1. Basic Spy Setup

```typescript
describe('Logging Tests', () => {
  let logSpy: jest.SpyInstance;
  let warnSpy: jest.SpyInstance;
  let errorSpy: jest.SpyInstance;

  beforeEach(() => {
    logSpy = jest.spyOn(console, 'log').mockImplementation();
    warnSpy = jest.spyOn(console, 'warn').mockImplementation();
    errorSpy = jest.spyOn(console, 'error').mockImplementation();
  });

  afterEach(() => {
    logSpy.mockRestore();
    warnSpy.mockRestore();
    errorSpy.mockRestore();
  });
});
```

### 2. Testing Specific Log Content

```typescript
it('should log service name', async () => {
  // Trigger logging action
  await manager.startAIService();
  processes[0].emit('exit', 1, null);

  // Verify content
  expect(logSpy).toHaveBeenCalledWith(
    expect.stringContaining('[ai]')
  );
});
```

### 3. Clearing Before Test

```typescript
it('should log specific message', async () => {
  // Setup creates logs we don't care about
  await manager.startService();

  // Clear to isolate what we're testing
  logSpy.mockClear();

  // Now do the action we want to test
  processes[0].emit('exit', 1, null);

  // Verify only our expected log
  expect(logSpy).toHaveBeenCalledTimes(1);
});
```

### 4. Testing Different Log Levels

```typescript
it('should warn on max exceeded, not log', async () => {
  // Exhaust retries
  // ...

  // Should use warn, not log
  expect(warnSpy).toHaveBeenCalledWith(
    expect.stringContaining('Max restarts')
  );
  expect(logSpy).not.toHaveBeenCalledWith(
    expect.stringContaining('Max restarts')
  );
});
```

## Common Pitfalls

### 1. Not Mocking Implementation

**Problem**: Logs print during tests (noisy).

**Solution**: Mock the implementation:
```typescript
// Wrong - logs still print
jest.spyOn(console, 'log');

// Correct - logs captured but not printed
jest.spyOn(console, 'log').mockImplementation();
```

### 2. Not Restoring Spies

**Problem**: Spy leaks to other tests.

**Solution**: Always restore in afterEach:
```typescript
afterEach(() => {
  logSpy.mockRestore();
});
```

### 3. Not Clearing Between Actions

**Problem**: Startup logs interfere with test assertions.

**Solution**: Clear after setup:
```typescript
await manager.startService(); // This logs
logSpy.mockClear();           // Clear startup logs
doAction();                    // Test this log
```

### 4. Exact String Matching

**Problem**: Tests break with minor log changes.

**Solution**: Use `stringContaining` for flexibility:
```typescript
// Brittle - breaks if format changes
expect(spy).toHaveBeenCalledWith('[ai] Restarting...');

// Flexible - survives minor changes
expect(spy).toHaveBeenCalledWith(expect.stringContaining('[ai]'));
```

## Best Practices

1. **Use Appropriate Levels**: log for info, warn for warnings, error for errors
2. **Include Service Name**: Prefix with service identifier
3. **Include Context**: Add relevant data (attempt, delay, etc.)
4. **Be Consistent**: Use consistent format across all logs
5. **Mock in Tests**: Always mock console methods
6. **Restore After Tests**: Clean up spies in afterEach
7. **Clear Before Assert**: Clear spy before testing specific action

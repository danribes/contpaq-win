# T004.1.2 Learning Guide: .NET SDK-Style Project Files

## Overview
This guide explains SDK-style project files (.csproj) in modern .NET development, specifically for creating ASP.NET Core Web API projects like ContPAQWinBridge.

## SDK-Style vs Legacy Project Files

### Legacy Format (Pre-.NET Core)
```xml
<?xml version="1.0" encoding="utf-8"?>
<Project ToolsVersion="15.0" xmlns="http://schemas.microsoft.com/developer/msbuild/2003">
  <Import Project="$(MSBuildExtensionsPath)\$(MSBuildToolsVersion)\Microsoft.Common.props" />
  <PropertyGroup>
    <Configuration Condition=" '$(Configuration)' == '' ">Debug</Configuration>
    <Platform Condition=" '$(Platform)' == '' ">AnyCPU</Platform>
    <!-- Many more properties... -->
  </PropertyGroup>
  <ItemGroup>
    <Reference Include="System" />
    <Reference Include="System.Core" />
    <!-- Explicit file listings... -->
  </ItemGroup>
  <Import Project="$(MSBuildToolsPath)\Microsoft.CSharp.targets" />
</Project>
```

### SDK-Style Format (Modern)
```xml
<Project Sdk="Microsoft.NET.Sdk.Web">
  <PropertyGroup>
    <TargetFramework>net8.0</TargetFramework>
    <Nullable>enable</Nullable>
    <ImplicitUsings>enable</ImplicitUsings>
  </PropertyGroup>
</Project>
```

**Key differences:**
- No XML namespace required
- Automatic file inclusion (no need to list every .cs file)
- Implicit references to common assemblies
- Much cleaner and shorter

## Available SDKs

| SDK | Use Case |
|-----|----------|
| `Microsoft.NET.Sdk` | Console apps, libraries |
| `Microsoft.NET.Sdk.Web` | ASP.NET Core web apps and APIs |
| `Microsoft.NET.Sdk.Worker` | Background services |
| `Microsoft.NET.Sdk.Razor` | Razor class libraries |
| `Microsoft.NET.Sdk.BlazorWebAssembly` | Blazor WASM apps |

## Common PropertyGroup Settings

### Target Framework
```xml
<TargetFramework>net8.0</TargetFramework>
```

Available target frameworks:
- `net8.0` - .NET 8 (LTS, recommended)
- `net7.0` - .NET 7
- `net6.0` - .NET 6 (LTS)
- `netstandard2.0` - For cross-framework compatibility

### Nullable Reference Types
```xml
<Nullable>enable</Nullable>
```

Options:
- `enable` - All code uses nullable annotations
- `disable` - No nullable checking (legacy behavior)
- `warnings` - Emit warnings but no errors
- `annotations` - Enable annotations, no warnings

### Implicit Usings
```xml
<ImplicitUsings>enable</ImplicitUsings>
```

When enabled, automatically includes:
```csharp
using System;
using System.Collections.Generic;
using System.IO;
using System.Linq;
using System.Net.Http;
using System.Threading;
using System.Threading.Tasks;
// Plus SDK-specific usings for Web SDK
using Microsoft.AspNetCore.Builder;
using Microsoft.AspNetCore.Hosting;
using Microsoft.AspNetCore.Http;
using Microsoft.Extensions.Configuration;
using Microsoft.Extensions.DependencyInjection;
// ... and more
```

### Documentation Generation
```xml
<GenerateDocumentationFile>true</GenerateDocumentationFile>
```

Generates XML documentation file used by:
- Swagger/OpenAPI for API documentation
- IntelliSense in IDEs
- NuGet packages for consumers

### Assembly Information
```xml
<RootNamespace>ContPAQWinBridge</RootNamespace>
<AssemblyName>ContPAQWinBridge</AssemblyName>
<Version>1.0.0</Version>
<Authors>Team Name</Authors>
<Description>Project description</Description>
<Product>Product Name</Product>
<Copyright>Copyright © 2025</Copyright>
```

## Adding NuGet Packages

### Using PackageReference (Modern)
```xml
<ItemGroup>
  <PackageReference Include="Serilog.AspNetCore" Version="8.0.0" />
  <PackageReference Include="Swashbuckle.AspNetCore" Version="6.5.0" />
</ItemGroup>
```

### Using CLI
```bash
dotnet add package Serilog.AspNetCore
dotnet add package Swashbuckle.AspNetCore
```

## Project References

### Referencing Other Projects
```xml
<ItemGroup>
  <ProjectReference Include="..\OtherProject\OtherProject.csproj" />
</ItemGroup>
```

### Referencing Assemblies
```xml
<ItemGroup>
  <Reference Include="SomeDll">
    <HintPath>path\to\Some.dll</HintPath>
  </Reference>
</ItemGroup>
```

## Conditional Compilation

### Configuration-Based
```xml
<PropertyGroup Condition="'$(Configuration)' == 'Debug'">
  <DefineConstants>DEBUG;TRACE</DefineConstants>
</PropertyGroup>

<PropertyGroup Condition="'$(Configuration)' == 'Release'">
  <Optimize>true</Optimize>
</PropertyGroup>
```

### Platform-Based
```xml
<PropertyGroup Condition="$([MSBuild]::IsOSPlatform('Windows'))">
  <DefineConstants>WINDOWS</DefineConstants>
</PropertyGroup>
```

## Best Practices for ASP.NET Core Projects

### 1. Enable Nullable and Implicit Usings
```xml
<Nullable>enable</Nullable>
<ImplicitUsings>enable</ImplicitUsings>
```

### 2. Generate Documentation
```xml
<GenerateDocumentationFile>true</GenerateDocumentationFile>
```

### 3. Set Proper Metadata
```xml
<Version>1.0.0</Version>
<Authors>Team Name</Authors>
<Description>Clear description</Description>
```

### 4. Use Central Package Management (Optional)
In `Directory.Packages.props`:
```xml
<Project>
  <PropertyGroup>
    <ManagePackageVersionsCentrally>true</ManagePackageVersionsCentrally>
  </PropertyGroup>
  <ItemGroup>
    <PackageVersion Include="Serilog.AspNetCore" Version="8.0.0" />
  </ItemGroup>
</Project>
```

Then in .csproj:
```xml
<PackageReference Include="Serilog.AspNetCore" />
```


## Key Takeaways

1. **SDK-style is the standard** for all modern .NET projects
2. **Choose the right SDK** - Web for APIs, standard for libraries
3. **Enable modern features** - Nullable and ImplicitUsings
4. **Generate docs** for OpenAPI/Swagger support
5. **Use semantic versioning** for the Version element
6. **PackageReference** is the modern way to add NuGet packages

# Learning Guide: T002.3.1 - Configuration with Pydantic Settings

## What is Pydantic Settings?

Pydantic Settings is a library for managing application configuration with:
- **Type safety** - Settings are validated against type hints
- **Environment variables** - Automatic loading from env vars
- **`.env` file support** - Load from dotenv files
- **Default values** - Sensible defaults for development

## Why Use Pydantic Settings?

### Without Pydantic Settings (Fragile)

```python
import os

# No validation, no type safety
HOST = os.getenv("HOST", "127.0.0.1")
PORT = int(os.getenv("PORT", "8000"))  # Crashes if PORT="abc"
DEBUG = os.getenv("DEBUG", "false") == "true"  # String comparison
```

### With Pydantic Settings (Robust)

```python
from pydantic_settings import BaseSettings

class Settings(BaseSettings):
    HOST: str = "127.0.0.1"
    PORT: int = 8000  # Auto-converts "8000" to 8000
    DEBUG: bool = False  # Understands "true", "1", "yes"

settings = Settings()
```

## Pydantic v2 Syntax

### Old (Pydantic v1)
```python
from pydantic import BaseSettings

class Settings(BaseSettings):
    HOST: str = "127.0.0.1"

    class Config:
        env_file = ".env"
```

### New (Pydantic v2) - What We Use
```python
from pydantic_settings import BaseSettings, SettingsConfigDict

class Settings(BaseSettings):
    HOST: str = "127.0.0.1"

    model_config = SettingsConfigDict(
        env_file=".env",
        env_file_encoding="utf-8",
    )
```

Key changes:
- Import from `pydantic_settings` (separate package)
- Use `model_config = SettingsConfigDict(...)` instead of nested `class Config`

## Configuration Priority

Settings are loaded in this order (later overrides earlier):

1. **Default values** in the Settings class
2. **`.env` file** values
3. **Environment variables** (highest priority)

```python
class Settings(BaseSettings):
    PORT: int = 8000  # Default

# .env file
PORT=9000

# Environment variable
export PORT=3000

# Result: settings.PORT == 3000 (env var wins)
```

## Common Configuration Patterns

### Basic Settings

```python
class Settings(BaseSettings):
    # Server
    HOST: str = "127.0.0.1"
    PORT: int = 8000

    # Logging
    LOG_LEVEL: str = "INFO"

    # Paths
    MODEL_PATH: str = "./models"
```

### With Validation

```python
from pydantic import Field

class Settings(BaseSettings):
    PORT: int = Field(default=8000, ge=1, le=65535)
    LOG_LEVEL: str = Field(default="INFO", pattern="^(DEBUG|INFO|WARNING|ERROR)$")
```

### With Environment Prefix

```python
class Settings(BaseSettings):
    HOST: str = "127.0.0.1"

    model_config = SettingsConfigDict(
        env_prefix="CONTPAQ_",  # Requires CONTPAQ_HOST
    )
```

### Nested Settings

```python
class DatabaseSettings(BaseSettings):
    HOST: str = "localhost"
    PORT: int = 5432
    NAME: str = "app_db"

class Settings(BaseSettings):
    database: DatabaseSettings = DatabaseSettings()
```

## Singleton Pattern with lru_cache

```python
from functools import lru_cache

@lru_cache
def get_settings() -> Settings:
    """Get cached settings instance."""
    return Settings()

# First call: loads settings from env
settings1 = get_settings()

# Second call: returns cached instance (no reload)
settings2 = get_settings()

assert settings1 is settings2  # Same object
```

Why use this pattern?
1. **Performance** - Settings loaded only once
2. **Consistency** - All code uses same settings
3. **Testability** - Can clear cache in tests

### Clearing Cache in Tests

```python
def test_with_different_settings():
    get_settings.cache_clear()  # Clear the cache
    os.environ["PORT"] = "9000"
    settings = get_settings()
    assert settings.PORT == 9000
```

## .env File

Create a `.env` file for local development:

```env
# .env
HOST=127.0.0.1
PORT=8000
LOG_LEVEL=DEBUG
TESSERACT_PATH=/usr/bin/tesseract
MODEL_PATH=./models/layoutlm
```

**Important**: Never commit `.env` to git! Add to `.gitignore`.

Instead, create `.env.example`:
```env
# .env.example (commit this)
HOST=127.0.0.1
PORT=8000
LOG_LEVEL=INFO
TESSERACT_PATH=/path/to/tesseract
MODEL_PATH=/path/to/models
```

## Using Settings in Application

### In FastAPI

```python
from fastapi import FastAPI, Depends
from src.config import Settings, get_settings

app = FastAPI()

@app.get("/health")
def health(settings: Settings = Depends(get_settings)):
    return {
        "status": "healthy",
        "port": settings.PORT,
        "log_level": settings.LOG_LEVEL,
    }
```

### Direct Import

```python
from src.config import settings

def start_server():
    uvicorn.run(
        "main:app",
        host=settings.HOST,
        port=settings.PORT,
    )
```

## Testing Configuration

### Test Default Values

```python
def test_default_host():
    settings = Settings()
    assert settings.HOST == "127.0.0.1"
```

### Test Environment Override

```python
import os

def test_env_override(monkeypatch):
    monkeypatch.setenv("PORT", "9000")
    get_settings.cache_clear()
    settings = get_settings()
    assert settings.PORT == 9000
```

### Test Validation

```python
import pytest
from pydantic import ValidationError

def test_invalid_port_type(monkeypatch):
    monkeypatch.setenv("PORT", "not_a_number")
    get_settings.cache_clear()
    with pytest.raises(ValidationError):
        get_settings()
```

## Our Configuration Structure

```python
class Settings(BaseSettings):
    # T002.3.2: Server settings
    HOST: str = "127.0.0.1"
    PORT: int = 8000
    LOG_LEVEL: str = "INFO"

    # T002.3.3: Service paths
    TESSERACT_PATH: str = "/usr/bin/tesseract"
    MODEL_PATH: str = "./models"

    model_config = SettingsConfigDict(
        env_file=".env",
        env_file_encoding="utf-8",
        case_sensitive=False,
        extra="ignore",
    )
```

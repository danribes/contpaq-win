## What is Structured Logging?

Structured logging outputs log entries in a machine-readable format (typically JSON) rather than plain text. This enables:

1. **Easy parsing** - Log aggregation tools can parse JSON directly
2. **Searchability** - Query logs by specific fields
3. **Consistency** - All logs have the same schema
4. **Rich context** - Include arbitrary metadata with each log

### Traditional vs Structured Logging

**Traditional (Plain Text):**
```
2025-12-18 12:34:56 - INFO - Invoice processed: INV-001 in 150ms
```

**Structured (JSON):**
```json
{
  "timestamp": "2025-12-18T12:34:56.789Z",
  "level": "INFO",
  "message": "Invoice processed",
  "invoice_id": "INV-001",
  "duration_ms": 150,
  "service": "ai-service"
}
```

## Implementation Approach

### 1. Custom JSON Formatter

Python's `logging` module uses `Formatter` classes to convert log records to strings. We create a custom formatter that outputs JSON:

```python
import json
import logging
from datetime import datetime

class JSONFormatter(logging.Formatter):
    def format(self, record: logging.LogRecord) -> str:
        log_data = {
            "timestamp": datetime.utcnow().isoformat() + "Z",
            "level": record.levelname,
            "logger": record.name,
            "message": record.getMessage(),
            "module": record.module,
            "function": record.funcName,
            "line": record.lineno,
        }

        # Add exception info if present
        if record.exc_info:
            log_data["exception"] = {
                "type": record.exc_info[0].__name__,
                "message": str(record.exc_info[1]),
                "traceback": traceback.format_exception(*record.exc_info)
            }

        return json.dumps(log_data)
```

### 2. Handler Configuration

Handlers determine where logs are written. Common handlers:

- `StreamHandler` - Console output
- `FileHandler` - File output
- `RotatingFileHandler` - File with size-based rotation
- `TimedRotatingFileHandler` - File with time-based rotation

```python
from logging.handlers import RotatingFileHandler

# Console handler
console = logging.StreamHandler()
console.setFormatter(JSONFormatter())

# File handler with rotation (10MB max, 5 backups)
file_handler = RotatingFileHandler(
    filename="logs/app.log",
    maxBytes=10 * 1024 * 1024,  # 10 MB
    backupCount=5,
    encoding="utf-8"
)
file_handler.setFormatter(JSONFormatter())
```

### 3. Logger Hierarchy

Python loggers form a hierarchy based on their names:

```
root (logging.getLogger())
├── contpaq
│   └── ai
│       ├── extractor
│       └── validator
```

Child loggers inherit settings from parents, making configuration simpler.

```python
# Get logger for module
logger = logging.getLogger("contpaq.ai.extractor")

# Inherits handlers/level from "contpaq.ai" parent
logger.info("Extracting invoice")
```

## Platform-Specific Log Locations

Different platforms have conventions for log file locations:

### Windows
```python
import os
local_app_data = os.environ.get("LOCALAPPDATA")
log_dir = Path(local_app_data) / "ContPAQ-Win" / "Logs"
# Result: C:\Users\{user}\AppData\Local\ContPAQ-Win\Logs
```

### Linux/macOS
```python
from pathlib import Path
log_dir = Path.home() / ".contpaq-win" / "logs"
# Result: /home/{user}/.contpaq-win/logs
```

## Adding Context to Logs

Use the `extra` parameter to add custom fields:

```python
logger.info("Invoice processed", extra={
    "invoice_id": "INV-001",
    "duration_ms": 150,
    "pdf_pages": 3,
    "ocr_used": True
})
```

Output:
```json
{
  "timestamp": "2025-12-18T12:34:56.789Z",
  "level": "INFO",
  "message": "Invoice processed",
  "invoice_id": "INV-001",
  "duration_ms": 150,
  "pdf_pages": 3,
  "ocr_used": true
}
```

## Best Practices

### 1. Log at Appropriate Levels

| Level | Use For |
|-------|---------|
| DEBUG | Detailed diagnostic info (dev only) |
| INFO | General operational messages |
| WARNING | Something unexpected but handled |
| ERROR | Error that prevented operation |
| CRITICAL | System-wide failure |

### 2. Include Request Context

For web services, include request IDs to trace related logs:

```python
logger.info("Processing request", extra={
    "request_id": request.headers.get("X-Request-ID"),
    "client_ip": request.client.host
})
```

### 3. Log Boundaries, Not Everything

Log at service boundaries:
- Incoming requests
- Outgoing API calls
- Database operations
- Error conditions

Avoid logging:
- Every function call
- Sensitive data (passwords, tokens)
- Large data structures

### 4. Use Consistent Field Names

Define a schema for common fields:
- `request_id` - Request correlation ID
- `user_id` - User identifier
- `duration_ms` - Operation duration
- `invoice_id` - Invoice identifier

## Testing Logging

### Capture Log Output

```python
import io
import logging

def test_json_output():
    # Create string buffer
    log_capture = io.StringIO()
    handler = logging.StreamHandler(log_capture)
    handler.setFormatter(JSONFormatter())

    logger = logging.getLogger("test")
    logger.addHandler(handler)
    logger.setLevel(logging.INFO)

    logger.info("Test message")

    output = log_capture.getvalue()
    parsed = json.loads(output.strip())

    assert parsed["message"] == "Test message"
```

### Use pytest caplog

```python
def test_logs_request(caplog):
    with caplog.at_level(logging.INFO):
        process_request()

    assert "Request processed" in caplog.text
```

## Key Takeaways

1. **Structured logging** enables better log analysis and querying
2. **Custom formatters** convert LogRecords to JSON output
3. **Log rotation** prevents unlimited file growth
4. **Platform-specific paths** ensure logs go to appropriate locations
5. **Extra fields** add context without modifying log messages
6. **Logger hierarchy** simplifies configuration across modules

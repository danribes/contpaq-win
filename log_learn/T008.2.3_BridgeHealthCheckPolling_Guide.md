# T008.2.3 Learning Guide: Bridge Health Check Polling

## Overview

This guide covers testing health check functionality for multiple services using shared infrastructure while maintaining service isolation.

## Key Concepts

### 1. Generic Health Check Implementation

Design health check methods to work with multiple services:

```typescript
async performHealthCheck(service: 'ai' | 'bridge'): Promise<HealthCheckResult> {
  // Get service-specific values
  const status = service === 'ai' ? this.aiServiceStatus : this.bridgeServiceStatus;
  const port = service === 'ai' ? this.config.aiServicePort : this.config.bridgeServicePort;

  // Skip if not running
  if (status !== ServiceStatus.RUNNING) {
    return { healthy: false, status, skipped: true };
  }

  // Use service-specific port
  const url = `http://127.0.0.1:${port}/health`;
  // ... rest of implementation
}
```

### 2. Service-Specific State Tracking

Track each service's health state independently:

```typescript
class ProcessManager {
  // AI service state
  private aiConsecutiveFailures: number = 0;
  private aiLastHealthCheck: Date | undefined;
  private aiLastHealthStatus: boolean | null = null;

  // Bridge service state
  private bridgeConsecutiveFailures: number = 0;
  private bridgeLastHealthCheck: Date | undefined;
  private bridgeLastHealthStatus: boolean | null = null;
}
```

### 3. Polling Multiple Services

Check all services in each polling cycle:

```typescript
private startHealthCheckPolling(): void {
  this.healthCheckTimer = setInterval(async () => {
    // Check AI if running
    if (this.aiServiceStatus === ServiceStatus.RUNNING) {
      await this.performHealthCheck('ai');
    }
    // Check Bridge if running
    if (this.bridgeServiceStatus === ServiceStatus.RUNNING) {
      await this.performHealthCheck('bridge');
    }
  }, this.config.healthCheckInterval);
}
```

## Testing Strategies

### 1. Verify Correct Port Usage

```typescript
it('should use correct port for Bridge service', async () => {
  await manager.startBridgeService();

  await manager.performHealthCheck('bridge');

  expect(mockFetch).toHaveBeenCalledWith(
    'http://127.0.0.1:5000/health',  // Bridge port
    expect.any(Object)
  );
});

it('should use correct port for AI service', async () => {
  await manager.startAIService();

  await manager.performHealthCheck('ai');

  expect(mockFetch).toHaveBeenCalledWith(
    'http://127.0.0.1:8000/health',  // AI port
    expect.any(Object)
  );
});
```

### 2. Test Service Isolation

```typescript
it('should track failures independently', async () => {
  await manager.startAIService();
  await manager.startBridgeService();

  // Fail only bridge
  mockFetch.mockRejectedValue(new Error('Connection refused'));
  await manager.performHealthCheck('bridge');

  // Verify isolation
  const aiHealth = await manager.checkHealth('ai');
  const bridgeHealth = await manager.checkHealth('bridge');

  expect(aiHealth.consecutiveFailures).toBe(0);  // AI unaffected
  expect(bridgeHealth.consecutiveFailures).toBe(1);  // Bridge failed
});
```

### 3. Test Polling with Short Interval

```typescript
it('should check both services during polling', async () => {
  // Use short interval to avoid test timeout
  const manager = new ProcessManager({
    healthCheckInterval: 50,  // 50ms instead of 5000ms
    fetchFn: mockFetch,
  });

  await manager.startAll();

  // Wait for at least one polling cycle
  await new Promise(resolve => setTimeout(resolve, 100));

  // Verify both services checked
  expect(mockFetch).toHaveBeenCalledWith(
    expect.stringContaining(':8000/health'),
    expect.any(Object)
  );
  expect(mockFetch).toHaveBeenCalledWith(
    expect.stringContaining(':5000/health'),
    expect.any(Object)
  );
});
```

### 4. Test Status Skipping

```typescript
it('should skip health check if service not running', async () => {
  // Don't start the service
  expect(manager.getBridgeServiceStatus()).toBe(ServiceStatus.STOPPED);

  const result = await manager.performHealthCheck('bridge');

  expect(result.healthy).toBe(false);
  expect(result.skipped).toBe(true);
  expect(mockFetch).not.toHaveBeenCalled();  // No HTTP request
});
```

## Common Pitfalls

### 1. Port Confusion

**Problem**: Using wrong port for service health check.

**Solution**: Always verify the port in test assertions:

```typescript
const config = manager.getConfig();
expect(mockFetch).toHaveBeenCalledWith(
  expect.stringContaining(`:${config.bridgeServicePort}`),
  expect.any(Object)
);
```

### 2. Long Polling Intervals in Tests

**Problem**: Tests timeout waiting for polling interval.

**Solution**: Configure short interval for tests:

```typescript
const manager = new ProcessManager({
  healthCheckInterval: 50,  // 50ms for tests
});
```

### 3. Shared State Leakage

**Problem**: Service failures affect each other.

**Solution**: Verify isolation in tests:

```typescript
// After bridge failure
expect(aiHealth.consecutiveFailures).toBe(0);
expect(bridgeHealth.consecutiveFailures).toBe(1);
```

### 4. Not Testing Skip Behavior

**Problem**: Health check runs when service not running.

**Solution**: Test all non-RUNNING states:

```typescript
// Test STOPPED
expect(result.skipped).toBe(true);

// Test STARTING
manager.startBridgeService().catch(() => {});  // Don't await
expect(manager.getBridgeServiceStatus()).toBe(ServiceStatus.STARTING);
const result = await manager.performHealthCheck('bridge');
expect(result.skipped).toBe(true);

// Test ERROR
// ... cause error state
expect(result.skipped).toBe(true);
```

## Best Practices

1. **Generic Implementation**: Write one health check method that handles all services

2. **Service-Specific State**: Maintain separate tracking for each service

3. **Configuration Sharing**: Use same timeout/retry config unless service-specific needed

4. **Port Configuration**: Make ports configurable for testing and deployment

5. **Skip When Not Running**: Don't waste resources checking non-running services

6. **Test Isolation**: Always verify one service's failures don't affect another

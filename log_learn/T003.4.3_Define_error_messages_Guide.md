# Learning Guide: T003.4.3 - Define all error messages in Spanish

## Overview

This guide covers best practices for defining user-facing error messages in a multilingual application, with focus on Spanish language.

## Concepts Covered

### 1. Error Message Categories

Organize errors by type:

```json
{
  "errors": {
    "generic": "Ha ocurrido un error",
    "networkError": "Error de conexión",
    "serverError": "Error del servidor",
    "fileNotFound": "Archivo no encontrado",
    "validationFailed": "Error de validación"
  }
}
```

Categories:
- **Generic**: Catch-all errors
- **Network**: Connection issues
- **File**: File operations
- **Validation**: Form/data validation
- **Service**: Backend service issues
- **Business**: Domain-specific errors

### 2. User-Friendly Messages

Good error messages are:

```json
{
  "errors": {
    // ❌ Bad - too technical
    "dbError": "SQLException: Connection timeout after 30000ms",

    // ✅ Good - user-friendly
    "dbError": "No se pudo conectar con la base de datos. Intente nuevamente."
  }
}
```

Guidelines:
- Plain language, no jargon
- Explain what happened
- Suggest what to do
- Don't blame the user

### 3. Contextual Error Messages

Provide specific errors for specific situations:

```json
{
  "errors": {
    // Generic
    "invalidFile": "Archivo inválido",

    // Specific
    "invalidPdf": "El archivo no es un PDF válido",
    "pdfTooLarge": "El PDF excede el tamaño máximo permitido",
    "pdfPasswordProtected": "No se puede abrir un PDF protegido con contraseña"
  }
}
```

### 4. Spanish Error Message Patterns

Common patterns for Spanish error messages:

| Pattern | Example | Use For |
|---------|---------|---------|
| No se pudo + verb | "No se pudo guardar" | Failed actions |
| Error de/al + noun/verb | "Error al procesar" | Process failures |
| [Subject] no encontrado | "Archivo no encontrado" | Missing items |
| [Subject] inválido/a | "Factura inválida" | Invalid data |
| [Subject] no disponible | "Servicio no disponible" | Unavailable resources |

### 5. Including Actionable Advice

Help users recover from errors:

```json
{
  "errors": {
    // Without advice
    "networkError": "Error de conexión",

    // With advice
    "networkErrorWithAdvice": "Error de conexión. Verifique su conexión a internet e intente nuevamente."
  }
}
```

### Using Error Messages in Code

```typescript
import { useTranslation } from '../i18n';

function handleError(error: Error) {
  const { t } = useTranslation();

  // Map error types to translation keys
  const errorKey = getErrorKey(error);

  // Get translated message
  const message = t(`errors.${errorKey}`);

  // Show to user
  showNotification(message, 'error');
}

function getErrorKey(error: Error): string {
  if (error.message.includes('network')) return 'networkError';
  if (error.message.includes('404')) return 'fileNotFound';
  if (error.message.includes('timeout')) return 'timeout';
  return 'generic';
}
```

## Best Practices

### 1. Consistent Naming Convention

```json
{
  "errors": {
    // Use camelCase
    "networkError": "...",      // ✅
    "network_error": "...",     // ❌
    "NetworkError": "...",      // ❌

    // Use descriptive names
    "saveFailed": "...",        // ✅
    "error1": "..."             // ❌
  }
}
```

### 2. Avoid Concatenation

```typescript
// ❌ Bad - concatenation
const message = t('errors.prefix') + ': ' + t('errors.detail');

// ✅ Good - single key with interpolation
const message = t('errors.withDetail', { detail: specificError });
```

### 3. Log Technical Details Separately

```typescript
function handleError(error: Error) {
  const { t } = useTranslation();

  // Log technical details for developers
  console.error('Technical error:', error);

  // Show user-friendly message
  showNotification(t('errors.generic'));
}
```

### 4. Test Error Messages

```python
def test_error_message_exists(translations):
    """Verify error message is defined."""
    assert "networkError" in translations["errors"]

def test_error_message_is_spanish(translations):
    """Verify message is in Spanish."""
    message = translations["errors"]["networkError"]
    assert "conexión" in message.lower()
```

## Summary

Defining error messages involves:
1. ✅ Organize by category (network, file, validation, etc.)
2. ✅ Write user-friendly messages
3. ✅ Provide context-specific errors
4. ✅ Use consistent Spanish patterns
5. ✅ Include actionable advice where possible
6. ✅ Test for completeness and correctness

# T007.2 Learning Guide: Service Interfaces and Dependency Injection

## Overview

This guide explains how to design service interfaces in C# and register them for dependency injection in ASP.NET Core applications.

## What is a Service Interface?

A service interface defines a contract for functionality without specifying implementation details. This enables:

- **Loose coupling**: Code depends on abstractions, not implementations
- **Testability**: Mock implementations for unit testing
- **Flexibility**: Swap implementations without changing consumers

## Key Concepts

### 1. Interface Definition

```csharp
public interface ISdkService
{
    // Methods define the contract
    bool IsAvailable();
    string? GetVersion();

    // Properties for state
    bool IsConnected { get; }

    // Operations
    bool Connect(string companyName);
    void Disconnect();
}
```

### 2. Implementation

```csharp
public class SdkService : ISdkService
{
    private readonly ILogger<SdkService> _logger;

    public SdkService(ILogger<SdkService> logger)
    {
        _logger = logger;
    }

    public bool IsAvailable() => CheckSdkInstallation();
    public string? GetVersion() => GetSdkVersion();
    public bool IsConnected => _connectedCompany != null;
    public bool Connect(string companyName) => ConnectToSdk(companyName);
    public void Disconnect() => DisconnectFromSdk();
}
```

### 3. DI Registration

```csharp
// In Program.cs
builder.Services.AddScoped<ISdkService, SdkService>();
```

## Service Lifetimes

| Lifetime | Behavior | Use Case |
|----------|----------|----------|
| Singleton | One instance for app lifetime | Stateless services, caches |
| Scoped | One instance per request | Database contexts, SDK connections |
| Transient | New instance every time | Lightweight, stateless services |

```csharp
// Singleton - shared instance
builder.Services.AddSingleton<IMyService, MyService>();

// Scoped - per request
builder.Services.AddScoped<ISdkService, SdkService>();

// Transient - always new
builder.Services.AddTransient<IHelper, Helper>();
```

## Stub Implementation Pattern

When building incrementally, start with stubs:

```csharp
public class SdkService : ISdkService
{
    public bool IsAvailable()
    {
        // Stub - actual implementation in later task
        return false;
    }

    public string? GetVersion()
    {
        // Stub - will read from SDK DLLs
        return null;
    }

    public bool Connect(string companyName)
    {
        // Stub - will use COM interop
        _logger.LogInformation("Connect stub called");
        return false;
    }
}
```

## Testing Service Interfaces

### Mocking with Moq

```csharp
[Fact]
public void Controller_Uses_SdkService()
{
    // Arrange
    var mockSdk = new Mock<ISdkService>();
    mockSdk.Setup(s => s.IsAvailable()).Returns(true);
    mockSdk.Setup(s => s.GetVersion()).Returns("10.0.0");

    var controller = new HealthController(mockSdk.Object, _logger);

    // Act
    var result = await controller.GetHealth();

    // Assert
    mockSdk.Verify(s => s.IsAvailable(), Times.Once);
}
```

### Testing Interface Contract

```csharp
[Fact]
public void Interface_Has_Required_Methods()
{
    // Use reflection to verify interface contract
    var method = typeof(ISdkService).GetMethod("Connect");

    method.Should().NotBeNull();
    method.ReturnType.Should().Be(typeof(bool));
    method.GetParameters()[0].ParameterType.Should().Be(typeof(string));
}
```

### Testing Implementation

```csharp
[Fact]
public void Implementation_Returns_Stub_Values()
{
    var service = new SdkService(Mock.Of<ILogger<SdkService>>());

    service.IsAvailable().Should().BeFalse();
    service.GetVersion().Should().BeNull();
    service.IsConnected.Should().BeFalse();
}
```

## Best Practices

### 1. Keep Interfaces Focused

```csharp
// Good: Single responsibility
public interface ISdkService { }
public interface ICompanyService { }

// Bad: Too many responsibilities
public interface IGodService { /* 50 methods */ }
```

### 2. Use Constructor Injection

```csharp
// Good: Dependencies injected
public class SdkService : ISdkService
{
    private readonly ILogger<SdkService> _logger;

    public SdkService(ILogger<SdkService> logger)
    {
        _logger = logger;
    }
}

// Bad: Service locator pattern
public class SdkService : ISdkService
{
    public void DoSomething()
    {
        var logger = ServiceLocator.Get<ILogger>();
    }
}
```

### 3. Handle Null Parameters

```csharp
public SdkService(ILogger<SdkService> logger)
{
    _logger = logger ?? throw new ArgumentNullException(nameof(logger));
}
```

### 4. Use Async for I/O Operations

```csharp
public interface ISdkService
{
    Task<bool> ConnectAsync(string companyName);
    Task DisconnectAsync();
}
```

## Common Patterns

### Factory Pattern

```csharp
public interface ISdkServiceFactory
{
    ISdkService Create(string sdkType);
}

builder.Services.AddSingleton<ISdkServiceFactory, SdkServiceFactory>();
```

### Options Pattern

```csharp
public class SdkOptions
{
    public string? DefaultCompany { get; set; }
    public int TimeoutSeconds { get; set; } = 30;
}

builder.Services.Configure<SdkOptions>(configuration.GetSection("Sdk"));

public class SdkService : ISdkService
{
    private readonly SdkOptions _options;

    public SdkService(IOptions<SdkOptions> options)
    {
        _options = options.Value;
    }
}
```

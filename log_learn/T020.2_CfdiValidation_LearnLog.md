## Concepts Learned

### 1. Mexican CFDI Structure
CFDI (Comprobante Fiscal Digital por Internet) is Mexico's official digital invoice format:
- Required by SAT (Servicio de Administración Tributaria)
- Must include vendor RFC, invoice number, date, and amounts
- Standard IVA rate is 16%
- Some invoices are exempt (tasa cero)

### 2. IVA (VAT) Validation
The standard Mexican IVA calculation:

```python
DEFAULT_IVA_RATE = 0.16  # 16%
AMOUNT_TOLERANCE = 0.02  # Allow ±0.02 for rounding

expected_iva = subtotal * iva_rate
iva_difference = abs(iva_amount - expected_iva)

if iva_difference > AMOUNT_TOLERANCE:
    errors.append("El IVA no coincide...")
```

Key considerations:
- Standard rate is 16% for most goods/services
- Some items are exempt (tasa 0%)
- Rounding differences are common in real invoices

### 3. Tolerance for Financial Calculations
Used tolerance instead of exact equality for amount comparisons:

```python
AMOUNT_TOLERANCE = 0.02  # ±$0.02

# Instead of:
if calculated_total != total:  # Too strict

# Use:
if abs(calculated_total - total) > AMOUNT_TOLERANCE:
```

Reasons:
- Floating-point precision issues
- Rounding differences between systems
- Real-world invoice entry errors

### 4. Multiple Error Accumulation
Designed to collect all errors rather than failing on first:

```python
def validate_cfdi(...) -> CfdiValidationResult:
    errors: List[str] = []
    warnings: List[str] = []

    if not vendor_rfc:
        errors.append("RFC requerido")

    if not invoice_number:
        errors.append("Número requerido")

    # Continue checking all fields...

    return CfdiValidationResult(
        valid=len(errors) == 0,
        errors=errors,
        warnings=warnings,
    )
```

Benefits:
- User sees all issues at once
- No need for multiple validation attempts
- Better user experience

### 5. Warnings vs Errors Pattern
Separated validation issues into errors and warnings:

```python
class CfdiValidationResult(TypedDict):
    valid: bool          # Only False if errors exist
    errors: List[str]    # Block submission
    warnings: List[str]  # Inform but don't block
```

- **Errors**: Invalid data that blocks processing
  - Missing required fields
  - Mathematical inconsistencies
- **Warnings**: Unusual but potentially valid
  - Higher than normal IVA rate
  - Zero total invoice

### 6. Pydantic Field Constraints
Used Pydantic's built-in validators for request models:

```python
class CfdiValidationRequest(BaseModel):
    subtotal: float = Field(
        ...,
        description="Subtotal amount before IVA",
        ge=0,  # Greater than or equal to 0
    )

    iva_rate: Optional[float] = Field(
        default=0.16,
        ge=0,  # >= 0
        le=1,  # <= 1 (100%)
    )
```

Benefits:
- Automatic validation
- Clear error messages
- OpenAPI documentation

## Best Practices Identified

1. **Default to standard rate**: Use 16% IVA unless explicitly specified
2. **Allow tolerance**: Real-world data has rounding differences
3. **Collect all errors**: Better UX than one-at-a-time
4. **Spanish messages**: For Mexican accountant users
5. **Separate warnings from errors**: Don't block valid edge cases

## Patterns to Reuse

TOLERANCE = 0.02

def amounts_equal(a: float, b: float) -> bool:

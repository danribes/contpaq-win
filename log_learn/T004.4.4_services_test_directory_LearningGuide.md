# T004.4.4 Learning Guide: Service Layer Testing

## Overview
This guide covers testing patterns for the service layer in .NET applications using xUnit, Moq, and FluentAssertions.

## Service Testing Patterns

### 1. Basic Service Test Setup
```csharp
public class VendorServiceTests
{
    private readonly Mock<IVendorRepository> _mockRepository;
    private readonly Mock<ILogger<VendorService>> _mockLogger;
    private readonly VendorService _service;

    public VendorServiceTests()
    {
        _mockRepository = new Mock<IVendorRepository>();
        _mockLogger = new Mock<ILogger<VendorService>>();
        _service = new VendorService(
            _mockRepository.Object,
            _mockLogger.Object);
    }
}
```

### 2. Testing Successful Operations
```csharp
[Fact]
public async Task GetByRfcAsync_WhenExists_ReturnsVendor()
{
    // Arrange
    var expected = new Vendor { Rfc = "ABC123", Name = "Test" };
    _mockRepository.Setup(r => r.GetByRfcAsync("ABC123"))
        .ReturnsAsync(expected);

    // Act
    var result = await _service.GetByRfcAsync("ABC123");

    // Assert
    result.Should().NotBeNull();
    result.Rfc.Should().Be("ABC123");
    _mockRepository.Verify(r => r.GetByRfcAsync("ABC123"), Times.Once);
}
```

### 3. Testing Not Found Scenarios
```csharp
[Fact]
public async Task GetByRfcAsync_WhenNotExists_ReturnsNull()
{
    // Arrange
    _mockRepository.Setup(r => r.GetByRfcAsync("NOTFOUND"))
        .ReturnsAsync((Vendor?)null);

    // Act
    var result = await _service.GetByRfcAsync("NOTFOUND");

    // Assert
    result.Should().BeNull();
}
```

### 4. Testing Validation Logic
```csharp
[Theory]
[InlineData(null)]
[InlineData("")]
[InlineData("   ")]
public async Task CreateAsync_WithInvalidRfc_ThrowsArgumentException(string? rfc)
{
    // Arrange
    var request = new CreateVendorRequest { Rfc = rfc };

    // Act
    Func<Task> act = () => _service.CreateAsync(request);

    // Assert
    await act.Should().ThrowAsync<ArgumentException>()
        .WithMessage("*RFC*");
}
```

### 5. Testing Error Handling
```csharp
[Fact]
public async Task CreateAsync_WhenDuplicateRfc_ThrowsDuplicateException()
{
    // Arrange
    var request = new CreateVendorRequest { Rfc = "EXISTS123" };
    _mockRepository.Setup(r => r.ExistsAsync("EXISTS123"))
        .ReturnsAsync(true);

    // Act
    Func<Task> act = () => _service.CreateAsync(request);

    // Assert
    await act.Should().ThrowAsync<DuplicateVendorException>()
        .WithMessage("*EXISTS123*");
}
```

## Mocking Patterns

### Basic Setup and Verify
```csharp
// Setup return value
_mock.Setup(m => m.GetById(1)).Returns(item);

// Setup with callback
_mock.Setup(m => m.Save(It.IsAny<Item>()))
    .Callback<Item>(i => savedItem = i)
    .ReturnsAsync(true);

// Verify call was made
_mock.Verify(m => m.GetById(1), Times.Once);
_mock.Verify(m => m.Delete(It.IsAny<int>()), Times.Never);
```

### Argument Matchers
```csharp
// Any value of type
It.IsAny<string>()

// Specific condition
It.Is<string>(s => s.StartsWith("ABC"))

// In a range
It.IsInRange(1, 10, Range.Inclusive)

// Regex match
It.IsRegex(@"^ABC\d+$")
```

### Sequence Setup
```csharp
_mockService
    .SetupSequence(s => s.GetNext())
    .Returns("First")
    .Returns("Second")
    .Throws<InvalidOperationException>();
```

## FluentAssertions Patterns

### Object Assertions
```csharp
result.Should().NotBeNull();
result.Should().BeOfType<VendorDto>();
result.Should().BeEquivalentTo(expected, options =>
    options.Excluding(v => v.CreatedAt));
```

### Collection Assertions
```csharp
vendors.Should().HaveCount(3);
vendors.Should().Contain(v => v.Rfc == "ABC123");
vendors.Should().BeInAscendingOrder(v => v.Name);
vendors.Should().OnlyContain(v => v.IsActive);
```

### Exception Assertions
```csharp
// Sync
action.Should().Throw<ArgumentException>()
    .WithMessage("*invalid*");

// Async
await act.Should().ThrowAsync<InvalidOperationException>()
    .WithInnerException<DbException>();
```

## Best Practices

### 1. Arrange-Act-Assert (AAA)
```csharp
[Fact]
public async Task MethodName_Condition_ExpectedResult()
{
    // Arrange - setup test data and mocks
    var input = CreateTestInput();
    SetupMocks();

    // Act - call the method under test
    var result = await _service.Method(input);

    // Assert - verify results and interactions
    result.Should().NotBeNull();
    VerifyMockInteractions();
}
```

### 2. Test One Thing Per Test
```csharp
// Good - focused test
[Fact]
public async Task Create_WithValidData_SavesVendor()

// Bad - testing multiple things
[Fact]
public async Task Create_ValidatesAndSavesAndReturnsVendor()
```

### 3. Meaningful Test Names
```
MethodName_Condition_ExpectedResult

CreateAsync_WithValidRequest_ReturnsCreatedVendor
GetByRfcAsync_WhenNotFound_ReturnsNull
ValidateRfc_WithInvalidFormat_ThrowsValidationException
```

### 4. Test Isolation
- Each test should be independent
- Use constructor for shared setup
- Use IDisposable for cleanup
- Never depend on test execution order

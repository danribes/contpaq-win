# Learning Guide: T001.2.3 - README.md Documentation

## What is a README?

The README.md is the first file developers see when they visit a repository. It's the "front door" to your project and should answer:

- **What** is this project?
- **Why** does it exist?
- **How** do I use it?
- **How** do I contribute?

## Why Markdown?

README files use **Markdown** (.md) format because:

1. **Plain text**: Can be read without special tools
2. **Formatted rendering**: GitHub/GitLab render it beautifully
3. **Version control friendly**: Easy to diff and merge
4. **Portable**: Works everywhere

## Essential README Sections

### 1. Title & Badges
```markdown
# Project Name

![Build Status](https://img.shields.io/badge/build-passing-green)
![License](https://img.shields.io/badge/license-MIT-blue)
```

Badges provide quick status indicators.

### 2. Description
One paragraph explaining what the project does and why it matters.

```markdown
ContPAQ-Win is a Windows-native AI-powered invoice processing
application that automates data extraction and posting to ContPAQi.
```

### 3. Architecture/Overview
Visual representation helps understanding:

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│   User      │────▶│   App       │────▶│   Backend   │
└─────────────┘     └─────────────┘     └─────────────┘
```

### 4. Prerequisites
What users need before starting:

```markdown
## Prerequisites

- Windows 10/11 (64-bit)
- Python 3.11+
- ContPAQi 2022+
```

### 5. Installation
Step-by-step instructions:

```markdown
## Installation

1. Clone the repository
2. Install dependencies
3. Configure environment
4. Run the application
```

### 6. Usage Examples
Show don't tell:

```markdown
## Usage

```python
# Process an invoice
result = process_invoice("factura.pdf")
print(result.extracted_fields)
```
```

### 7. Project Structure
Help developers navigate:

```markdown
## Project Structure

src/
├── api/        # REST endpoints
├── services/   # Business logic
└── models/     # Data models
```

### 8. Contributing
How to help:

```markdown
## Contributing

1. Fork the repository
2. Create a feature branch
3. Submit a pull request
```

### 9. License
Legal stuff:

```markdown
## License

MIT License - see LICENSE file
```

## README Best Practices

### Do's ✅

1. **Keep it updated** - Outdated READMEs confuse users
2. **Use clear headings** - Make sections scannable
3. **Include examples** - Show real usage
4. **Add visuals** - Screenshots, diagrams, GIFs
5. **Link to docs** - Point to detailed documentation

### Don'ts ❌

1. **Don't be verbose** - Keep sections focused
2. **Don't assume knowledge** - Explain acronyms
3. **Don't forget prerequisites** - List all dependencies
4. **Don't skip installation** - Even "obvious" steps
5. **Don't ignore mobile** - Many read on phones

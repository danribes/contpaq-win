# T004.1.3 Learning Guide: NuGet Packages for ASP.NET Core

## Overview
This guide explains the NuGet packages selected for the ContPAQWinBridge service and best practices for package management in .NET projects.

## What is NuGet?
NuGet is the package manager for .NET. It enables developers to:
- Share and consume reusable code
- Manage project dependencies
- Keep packages updated

## PackageReference Format
Modern .NET uses PackageReference in the .csproj file:

```xml
<ItemGroup>
  <PackageReference Include="PackageName" Version="1.2.3" />
</ItemGroup>
```

### Version Formats
| Format | Example | Meaning |
|--------|---------|---------|
| Exact | `1.2.3` | Exactly version 1.2.3 |
| Range | `[1.0,2.0)` | >= 1.0 and < 2.0 |
| Floating | `1.2.*` | Latest 1.2.x |
| Wildcard | `*` | Latest version |

**Recommendation**: Use exact versions for reproducible builds.

## Serilog Packages

### Why Serilog?
Serilog provides structured logging, which means:
- Log events are objects, not strings
- Easy to query and analyze
- Multiple output destinations (sinks)
- Rich contextual information

### Package Breakdown

#### Serilog.AspNetCore
Main integration package for ASP.NET Core:
```csharp
// Program.cs
builder.Host.UseSerilog((context, config) =>
    config.ReadFrom.Configuration(context.Configuration));
```

Features:
- Request logging middleware
- Enrichers for HTTP context
- Configuration from appsettings.json

#### Serilog.Sinks.File
Write logs to files with rolling:
```csharp
.WriteTo.File("logs/app-.txt",
    rollingInterval: RollingInterval.Day,
    retainedFileCountLimit: 30)
```

Features:
- Rolling by date/size
- File retention policies
- Async writing

#### Serilog.Sinks.Console
Colored console output:
```csharp
.WriteTo.Console(
    outputTemplate: "[{Timestamp:HH:mm:ss} {Level:u3}] {Message:lj}{NewLine}{Exception}")
```

Features:
- Colored output by level
- Customizable templates
- Theme support

### Serilog Configuration Example
```json
// appsettings.json
{
  "Serilog": {
    "Using": ["Serilog.Sinks.Console", "Serilog.Sinks.File"],
    "MinimumLevel": {
      "Default": "Information",
      "Override": {
        "Microsoft": "Warning",
        "System": "Warning"
      }
    },
    "WriteTo": [
      { "Name": "Console" },
      {
        "Name": "File",
        "Args": {
          "path": "logs/bridge-.txt",
          "rollingInterval": "Day"
        }
      }
    ]
  }
}
```

## Swashbuckle Packages

### Why Swashbuckle?
Swashbuckle generates OpenAPI documentation for your API:
- Interactive Swagger UI
- Auto-generated API specs
- Try-it-out functionality

### Package Breakdown

#### Swashbuckle.AspNetCore
Main package that includes:
- SwaggerGen: Generate OpenAPI spec from code
- SwaggerUI: Interactive documentation UI
- Swagger: Core functionality

Setup:
```csharp
// Program.cs
builder.Services.AddEndpointsApiExplorer();
builder.Services.AddSwaggerGen();

// Later in pipeline
app.UseSwagger();
app.UseSwaggerUI();
```

#### Swashbuckle.AspNetCore.Annotations
Enables attribute-based documentation:

```csharp
[HttpGet("{id}")]
[SwaggerOperation(
    Summary = "Get vendor by RFC",
    Description = "Returns vendor details for the given RFC")]
[SwaggerResponse(200, "Vendor found", typeof(Vendor))]
[SwaggerResponse(404, "Vendor not found")]
public async Task<ActionResult<Vendor>> GetVendor(string id)
```

Benefits:
- More control over documentation
- Response type documentation
- Operation grouping

## ASP.NET Core SDK Implicit Packages

The Microsoft.NET.Sdk.Web SDK automatically includes:

| Framework Reference | Contents |
|--------------------|----------|
| Microsoft.AspNetCore.App | All ASP.NET Core packages |

This includes:
- Kestrel web server
- MVC/Razor Pages
- SignalR
- Identity
- Entity Framework Core (basic)
- Much more...

**No need to add**:
- Microsoft.AspNetCore.*
- Microsoft.Extensions.*
- System.Text.Json

## Package Management Commands

### Add Package (CLI)
```bash
dotnet add package Serilog.AspNetCore --version 8.0.0
```

### Update Package
```bash
dotnet add package Serilog.AspNetCore
# Adds latest version
```

### List Packages
```bash
dotnet list package
```

### Restore Packages
```bash
dotnet restore
```

## Best Practices

### 1. Pin Versions
```xml
<!-- Good: Exact version -->
<PackageReference Include="Serilog" Version="3.1.1" />

<!-- Avoid: Floating versions in production -->
<PackageReference Include="Serilog" Version="3.*" />
```

### 2. Group Related Packages
```xml
<ItemGroup>
  <!-- Logging -->
  <PackageReference Include="Serilog.AspNetCore" Version="8.0.0" />
  <PackageReference Include="Serilog.Sinks.File" Version="5.0.0" />
</ItemGroup>

<ItemGroup>
  <!-- OpenAPI -->
  <PackageReference Include="Swashbuckle.AspNetCore" Version="6.5.0" />
</ItemGroup>
```

### 3. Use Central Package Management
In `Directory.Packages.props`:
```xml
<Project>
  <PropertyGroup>
    <ManagePackageVersionsCentrally>true</ManagePackageVersionsCentrally>
  </PropertyGroup>
  <ItemGroup>
    <PackageVersion Include="Serilog.AspNetCore" Version="8.0.0" />
  </ItemGroup>
</Project>
```

Then in .csproj (no version needed):
```xml
<PackageReference Include="Serilog.AspNetCore" />
```

### 4. Regular Updates
- Check for security updates
- Review changelogs before updating
- Test after updating

## Key Takeaways

1. **SDK provides basics** - Web SDK includes ASP.NET Core packages
2. **Serilog for logging** - Structured, flexible, many sinks
3. **Swashbuckle for docs** - Auto-generate OpenAPI specs
4. **Pin versions** - Use exact versions for reproducibility
5. **Keep updated** - Regular security and feature updates

# T007.1 Learning Guide: Health Endpoints in ASP.NET Core

## Overview

This guide explains how to implement health check endpoints in ASP.NET Core Web APIs, using the pattern implemented for the ContPAQ Win Bridge service.

## What is a Health Endpoint?

A health endpoint is an API route (typically `/health`) that returns the current status of a service. It's used for:

- Load balancer health checks
- Kubernetes readiness/liveness probes
- Monitoring and alerting systems
- Service discovery

## Key Concepts

### 1. Health Status Levels

| Status | Meaning | HTTP Code |
|--------|---------|-----------|
| Healthy | All systems operational | 200 |
| Degraded | Reduced functionality | 200 |
| Unhealthy | Service not functioning | 503 |

### 2. Component Health

Track health of individual components:

```csharp
public record ComponentHealth
{
    public ComponentStatus Sdk { get; init; } = new();
    public ComponentStatus? Database { get; init; }
}

public record ComponentStatus
{
    public string Status { get; init; } = "Unknown";
    public bool IsAvailable { get; init; }
    public string? Version { get; init; }
    public string? Details { get; init; }
}
```

## Implementation Pattern

### Controller Structure

```csharp
[Route("api/[controller]")]
public class HealthController : BaseController
{
    private readonly ISdkService _sdkService;
    private readonly ILogger<HealthController> _logger;

    public HealthController(ISdkService sdkService, ILogger<HealthController> logger)
    {
        _sdkService = sdkService;
        _logger = logger;
    }

    [HttpGet]
    [Route("/health")]
    public async Task<IActionResult> GetHealth()
    {
        var sdkStatus = await GetSdkStatusAsync();
        var overallStatus = DetermineOverallStatus(sdkStatus);

        return Ok(new HealthResponse
        {
            Status = overallStatus,
            Timestamp = DateTime.UtcNow,
            Components = new ComponentHealth { Sdk = sdkStatus }
        });
    }
}
```

### Route Configuration

```csharp
// Multiple routes for flexibility
[HttpGet]
[Route("/health")]      // Root-level for load balancers
[Route("")]             // /api/health for API consistency
public async Task<IActionResult> GetHealth()
```

### Status Determination

```csharp
private static string DetermineOverallStatus(ComponentStatus sdkStatus)
{
    return sdkStatus.Status switch
    {
        HealthStatus.Healthy => HealthStatus.Healthy,
        HealthStatus.Degraded => HealthStatus.Degraded,
        _ => HealthStatus.Degraded
    };
}
```

## Best Practices

### 1. Always Return 200 for Health Checks

```csharp
// Good: Return 200 with status in body
return Ok(new HealthResponse { Status = "Unhealthy" });

// Avoid: Return 503 for unhealthy
// This can cause load balancers to remove all instances
```

### 2. Include Timestamp

```csharp
public DateTime Timestamp { get; init; } = DateTime.UtcNow;
```

### 3. Include Version

```csharp
public string? Version { get; init; } = Assembly
    .GetExecutingAssembly()
    .GetName()
    .Version?
    .ToString();
```

### 4. Handle Exceptions Gracefully

```csharp
try
{
    var isAvailable = _sdkService.IsAvailable();
    // ... build status
}
catch (Exception ex)
{
    _logger.LogError(ex, "Error checking SDK status");
    return new ComponentStatus
    {
        Status = HealthStatus.Unhealthy,
        Details = $"Error: {ex.Message}"
    };
}
```

## Testing Health Controllers

### Mocking Dependencies

```csharp
public class HealthControllerTests
{
    private readonly Mock<ISdkService> _mockSdkService;
    private readonly HealthController _controller;

    public HealthControllerTests()
    {
        _mockSdkService = new Mock<ISdkService>();
        _controller = new HealthController(
            _mockSdkService.Object,
            Mock.Of<ILogger<HealthController>>()
        );
    }
}
```

### Testing Different States

```csharp
[Fact]
public async Task GetHealth_Returns_Healthy_When_SDK_Available()
{
    // Arrange
    _mockSdkService.Setup(s => s.IsAvailable()).Returns(true);
    _mockSdkService.Setup(s => s.IsConnected).Returns(true);

    // Act
    var result = await _controller.GetHealth();
    var health = (result as OkObjectResult)?.Value as HealthResponse;

    // Assert
    health!.Status.Should().Be("Healthy");
}
```

## ASP.NET Core Built-in Health Checks

ASP.NET Core also provides built-in health check infrastructure:

```csharp
// In Program.cs
builder.Services.AddHealthChecks()
    .AddCheck<SdkHealthCheck>("sdk");

app.MapHealthChecks("/health");
```

Custom health check:

```csharp
public class SdkHealthCheck : IHealthCheck
{
    private readonly ISdkService _sdkService;

    public Task<HealthCheckResult> CheckHealthAsync(
        HealthCheckContext context,
        CancellationToken ct = default)
    {
        return _sdkService.IsAvailable()
            ? Task.FromResult(HealthCheckResult.Healthy())
            : Task.FromResult(HealthCheckResult.Degraded("SDK unavailable"));
    }
}
```

## Common Health Check Patterns

### Kubernetes Probes

```yaml
livenessProbe:
  httpGet:
    path: /health
    port: 80
  initialDelaySeconds: 5
  periodSeconds: 10

readinessProbe:
  httpGet:
    path: /health
    port: 80
  initialDelaySeconds: 3
  periodSeconds: 5
```

### Load Balancer Health Check

Most load balancers check:
- HTTP 200 status code
- Response within timeout (e.g., 5s)
- Path: `/health` or `/`

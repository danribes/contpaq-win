# Learning Guide: T001.1.5 - Database Directory Structure

## What is the Database Component?

The **Database** component provides persistent local storage for ContPAQ-Win using SQLite. It stores invoices, extracted data, user corrections, and audit history.

## Why SQLite?

SQLite is an embedded database engine - it runs inside your application, not as a separate server.

### Comparison with Other Databases

| Feature | SQLite | PostgreSQL | MySQL |
|---------|--------|------------|-------|
| Installation | None needed | Requires server | Requires server |
| Configuration | Zero | Complex | Complex |
| Backup | Copy single file | pg_dump command | mysqldump command |
| Performance (local) | Excellent | Good | Good |
| Concurrent writes | Limited | Excellent | Good |
| Best for | Desktop apps | Web servers | Web servers |

For ContPAQ-Win (single-user desktop app), SQLite is the optimal choice.

## Directory Structure Explanation

```
database/
├── migrations/
│   └── .gitkeep
└── seed/
    └── .gitkeep
```

### `database/migrations/`

**Database migrations** are versioned SQL scripts that modify the database schema. They allow:
- Tracking schema changes in version control
- Reproducible database setup
- Safe schema updates without data loss

Example migration files:
```
migrations/
├── 001_initial_schema.sql       # Create base tables
├── 002_add_confidence_column.sql # Add confidence scores
├── 003_add_audit_log.sql        # Add audit logging
└── 004_optimize_indexes.sql     # Performance improvements
```

Example migration content:
```sql
-- 001_initial_schema.sql
CREATE TABLE invoices (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    file_path TEXT NOT NULL UNIQUE,
    status TEXT DEFAULT 'uploaded',
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE extracted_fields (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    invoice_id INTEGER REFERENCES invoices(id),
    field_name TEXT NOT NULL,
    field_value TEXT,
    confidence REAL,
    user_corrected BOOLEAN DEFAULT FALSE
);
```

### `database/seed/`

**Seed data** is initial data loaded for development and testing:

```
seed/
├── sample_invoices.json    # Test invoice data
├── test_companies.json     # ContPAQi company data
└── field_mappings.json     # Default field configurations
```

## Key Database Concepts

### Schema vs. Data

- **Schema** = Structure (tables, columns, relationships)
- **Data** = Content (actual rows/records)

Migrations handle schema, seed handles data.

### Why Version Migrations?

Consider this scenario:

1. Developer A creates `invoices` table
2. Developer B adds `confidence` column
3. Developer A pulls changes - their database is out of sync!

With migrations:
1. Developer A runs migration 001 (creates table)
2. Developer B creates migration 002 (adds column)
3. Developer A runs pending migrations - database syncs automatically

### ACID Compliance

SQLite is **ACID compliant**:

- **A**tomicity - Transactions are all-or-nothing
- **C**onsistency - Database always valid after transaction
- **I**solation - Concurrent operations don't interfere
- **D**urability - Committed data survives crashes

This is critical for financial data like invoices.

## Integration Points

The database connects to all other components:

1. **AI Service** writes extracted fields after processing
2. **Desktop App** reads data for display and allows edits
3. **Windows Bridge** reads finalized data for ContPAQi posting
4. **All components** write to audit log for traceability

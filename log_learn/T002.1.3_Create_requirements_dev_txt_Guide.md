# Learning Guide: T002.1.3 - Development Dependencies

## What are Development Dependencies?

Development dependencies are packages needed only during development, not in production:
- Testing frameworks
- Linters and formatters
- Type checkers
- Documentation generators

## Why Separate Dev Dependencies?

### Production Install
```bash
pip install -r requirements.txt
# Installs: fastapi, torch, etc. (~2GB)
```

### Development Install
```bash
pip install -r requirements-dev.txt
# Installs: everything + pytest, black, etc.
```

Separating keeps production deployments small and fast.

## Including Base Requirements

```
# requirements-dev.txt
-r requirements.txt  # Include production deps

# Dev-only packages below
pytest==7.4.4
```

The `-r` flag includes another requirements file. This prevents duplication and ensures dev environment has production packages too.

## Dependency Categories Explained

### 1. Testing Framework

```
pytest==7.4.4
pytest-asyncio==0.23.3
pytest-cov==4.1.0
pytest-mock==3.12.0
```

**pytest**: The standard Python testing framework
```python
def test_invoice_extraction():
    result = extract_fields("invoice.pdf")
    assert result["total"] == 1500.00
```

**pytest-asyncio**: Test async code
```python
@pytest.mark.asyncio
async def test_async_upload():
    result = await upload_invoice("invoice.pdf")
    assert result.status == "success"
```

**pytest-cov**: Generate coverage reports
```bash
pytest --cov=src --cov-report=html
# Creates htmlcov/index.html with coverage visualization
```

**pytest-mock**: Easy mocking
```python
def test_with_mock(mocker):
    mock_ocr = mocker.patch("src.services.ocr.extract_text")
    mock_ocr.return_value = "Invoice Total: $100"
    # Test code that uses OCR
```

### 2. Code Formatting

```
black==23.12.1
```

**Black** is an opinionated formatter - it makes all code look the same:

Before Black:
```python
def process(data,options={},verbose = False):
    return data[ 'result' ]
```

After Black:
```python
def process(data, options={}, verbose=False):
    return data["result"]
```

Usage:
```bash
black src/           # Format all files
black --check src/   # Check without changing
```

### 3. Linting

```
ruff==0.1.11
```

**Ruff** is a fast linter that replaces flake8, isort, and others:

```bash
ruff check src/        # Find issues
ruff check --fix src/  # Auto-fix issues
```

Common issues Ruff catches:
- Unused imports
- Undefined variables
- Wrong import order
- Code complexity

### 4. Type Checking

```
mypy==1.8.0
types-Pillow==10.2.0.20240125
types-aiofiles==23.2.0.20240106
```

**mypy** checks type annotations:
```python
def calculate_total(items: list[float]) -> float:
    return sum(items)

# mypy catches this error:
calculate_total("not a list")  # Error: Expected list[float]
```

**Type stubs** provide type information for packages without built-in types:
```python
from PIL import Image
# Without types-Pillow, mypy doesn't know Image methods
```

### 5. HTTP Testing

```
httpx==0.26.0
```

**httpx** is a modern HTTP client, perfect for testing FastAPI:
```python
from httpx import AsyncClient

async def test_api_endpoint():
    async with AsyncClient(app=app, base_url="http://test") as client:
        response = await client.post("/upload", files={"file": pdf_data})
        assert response.status_code == 200
```

### 6. Documentation

```
mkdocs==1.5.3
mkdocs-material==9.5.3
```

**MkDocs** generates documentation from Markdown:
```bash
mkdocs serve   # Local preview at localhost:8000
mkdocs build   # Generate static site
```

**mkdocs-material** provides a professional theme.

### 7. Development Utilities

```
ipython==8.20.0
watchfiles==0.21.0
```

**IPython**: Enhanced Python shell for debugging
```python
# In code, drop into IPython:
from IPython import embed; embed()
```

**watchfiles**: Auto-reload during development
```bash
watchfiles "python -m uvicorn src.main:app" src/
# Restarts server when files change
```

## Development Workflow

```
1. Write code
      │
      ▼
2. Format with Black
      │
      ▼
3. Lint with Ruff
      │
      ▼
4. Type check with mypy
      │
      ▼
5. Run tests with pytest
      │
      ▼
6. Check coverage
      │
      ▼
7. Commit if all pass ✅
```

## Pre-commit Integration

You can automate these checks with pre-commit hooks:

```yaml
# .pre-commit-config.yaml
repos:
  - repo: https://github.com/psf/black
    rev: 23.12.1
    hooks:
      - id: black
  - repo: https://github.com/astral-sh/ruff-pre-commit
    rev: v0.1.11
    hooks:
      - id: ruff
```

## CI/CD Integration

In GitHub Actions:
```yaml
- name: Install dev dependencies
  run: pip install -r requirements-dev.txt

- name: Check formatting
  run: black --check src/

- name: Lint
  run: ruff check src/

- name: Type check
  run: mypy src/

- name: Test
  run: pytest --cov=src
```

## Version Pinning for Dev Deps

Dev dependencies should also be pinned for reproducibility:
- ✅ `pytest==7.4.4` - Everyone uses same version
- ❌ `pytest>=7.0.0` - Could cause inconsistent behavior

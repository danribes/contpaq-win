# T017.2 Learning Log: Invoice Processing Workflow

## Date: 2025-12-18

## Key Learnings

### 1. Testing React Hooks with renderHook

**Pattern**: Use `renderHook` from `@testing-library/react` to test hooks in isolation:
```typescript
import { renderHook, act, waitFor } from '@testing-library/react';

it('should set file when setFile is called', () => {
  const { result } = renderHook(() => useInvoice());

  act(() => {
    result.current.setFile(mockFile);
  });

  expect(result.current.file).toBe(mockFile);
});
```

**Key points**:
- `result.current` gives access to hook return value
- Wrap state updates in `act()` to trigger re-renders
- Use `await act(async () => {...})` for async operations

### 2. Mocking Dependencies in Hook Tests

**Pattern**: Mock external dependencies before importing the hook:
```typescript
jest.mock('../../../src/renderer/services/ai-service', () => ({
  AIServiceClient: jest.fn().mockImplementation(() => ({
    extractInvoice: jest.fn(),
  })),
  AIServiceError: class AIServiceError extends Error {
    // ...
  },
}));

// Then dynamically import to use fresh mocks
beforeEach(async () => {
  mockExtractInvoice = jest.fn();
  (AIServiceClient as jest.Mock).mockImplementation(() => ({
    extractInvoice: mockExtractInvoice,
  }));

  const module = await import('../../../src/renderer/hooks/useInvoice');
  useInvoice = module.useInvoice;
});
```

### 3. State Machine Pattern for Workflows

**Pattern**: Model complex workflows as state machines:
```typescript
type ProcessingState = 'none' | 'uploaded' | 'extracting' | 'extracted' | 'error';
```

**Benefits**:
- Clear and predictable state transitions
- Easy to test each transition
- Prevents invalid states
- Self-documenting code

### 4. Memoizing Service Clients

**Pattern**: Use `useMemo` to prevent recreating service clients:
```typescript
const aiClient = useMemo(
  () => new AIServiceClient(aiServiceUrl),
  [aiServiceUrl]
);
```

**Why it matters**: Without memoization, a new client would be created on every render, potentially causing issues with connection pooling or caching.

### 5. Guard Conditions in Async Operations

**Pattern**: Add guard conditions to prevent invalid operations:
```typescript
const extract = useCallback(async () => {
  // Guard: no file selected
  if (!file) {
    return;
  }

  // Guard: already loading
  if (loading) {
    return;
  }

  setLoading(true);
  // ... extraction logic
}, [file, loading, aiClient]);
```

**Benefits**:
- Prevents double submissions
- Handles edge cases gracefully
- Clear intent in code

### 6. Error Handling with Custom Error Types

**Pattern**: Handle custom error types differently:
```typescript
try {
  const result = await aiClient.extractInvoice(file);
  // ...
} catch (err) {
  // Handle AIServiceError with detail
  if (err instanceof AIServiceError && err.detail) {
    setError(err.detail);
  } else if (err instanceof Error) {
    setError(err.message);
  } else {
    setError('Unknown error occurred');
  }
  setState('error');
}
```

### 7. Testing Async State Transitions

**Pattern**: Test intermediate states during async operations:
```typescript
it('should follow none → uploaded → extracting → extracted flow', async () => {
  mockExtractInvoice.mockResolvedValue(createMockExtraction());
  const { result } = renderHook(() => useInvoice());

  // Initial state
  expect(result.current.state).toBe('none');

  // After file selection
  act(() => {
    result.current.setFile(mockFile);
  });
  expect(result.current.state).toBe('uploaded');

  // During extraction
  let extractPromise: Promise<void>;
  act(() => {
    extractPromise = result.current.extract();
  });
  expect(result.current.state).toBe('extracting');

  // After extraction
  await act(async () => {
    await extractPromise;
  });
  expect(result.current.state).toBe('extracted');
});
```

## Best Practices Applied

1. **Single Responsibility**: Hook only handles invoice processing state
2. **Clean Interface**: Returns only what consumers need
3. **Type Safety**: Full TypeScript types for all return values
4. **Error Recovery**: State allows retry after error
5. **Testability**: All dependencies can be mocked
6. **Immutable Updates**: State never mutated directly

## Design Decisions

1. **Why not useReducer?**: useState is simpler for this use case where state changes are localized
2. **Why memoize aiClient?**: Prevents unnecessary object creation and maintains reference stability
3. **Why preserve file on error?**: Allows user to retry extraction without re-uploading
4. **Why explicit loading state?**: Easier to check than `state === 'extracting'`

## Potential Improvements

1. Add abort controller to cancel in-flight requests
2. Add progress callback for large files
3. Implement optimistic updates
4. Add caching for repeated extractions of same file

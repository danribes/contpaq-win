# T005.1.1 Learning Guide: SQLite Database Schema Design

## Overview
This guide covers SQLite database schema design patterns for application development, focusing on the invoice processing domain.

## SQLite Data Types

### Type Affinity
SQLite uses type affinity rather than strict typing:

| Affinity | Example | Notes |
|----------|---------|-------|
| TEXT | VARCHAR, CHAR | String data, UUIDs |
| NUMERIC | DECIMAL | Stored as int/real |
| INTEGER | INT, BOOLEAN | Whole numbers |
| REAL | FLOAT, DOUBLE | Floating point |
| BLOB | BINARY | Raw bytes |

### Common Patterns

#### UUIDs in SQLite
```sql
-- Store as TEXT
id TEXT PRIMARY KEY
-- Generate in application code (Python/JS)
```

#### Timestamps
```sql
-- Use datetime() function for defaults
created_at TEXT NOT NULL DEFAULT (datetime('now'))
```

#### Boolean Values
```sql
-- Use INTEGER (0 = false, 1 = true)
user_verified INTEGER NOT NULL DEFAULT 0
```

## Foreign Keys in SQLite

### Enabling Foreign Keys
```sql
-- MUST be set per connection, not persistent
PRAGMA foreign_keys = ON;
```

### Defining Foreign Keys
```sql
-- Simple reference
vendor_id TEXT REFERENCES vendors(id)

-- With actions
invoice_id TEXT NOT NULL
    REFERENCES invoices(id)
    ON DELETE CASCADE
    ON UPDATE CASCADE
```

### Cascade Options
| Action | Behavior |
|--------|----------|
| CASCADE | Delete/update child rows |
| SET NULL | Set FK to NULL |
| SET DEFAULT | Set FK to default |
| RESTRICT | Prevent parent change |
| NO ACTION | Same as RESTRICT (default) |

## CHECK Constraints

### Enum-Like Constraints
```sql
-- State machine validation
state TEXT NOT NULL CHECK (
    state IN ('UPLOADED', 'EXTRACTED', 'VALIDATED', 'POSTED')
)

-- Multiple valid values
source_type TEXT NOT NULL CHECK (
    source_type IN ('text_based', 'scanned')
)
```

### Numeric Constraints
```sql
confidence REAL NOT NULL CHECK (confidence >= 0 AND confidence <= 100)
quantity REAL NOT NULL CHECK (quantity > 0)
```

## Schema Design Patterns

### 1. Base Table Pattern
```sql
CREATE TABLE IF NOT EXISTS table_name (
    id TEXT PRIMARY KEY,
    -- ... columns ...
    created_at TEXT NOT NULL DEFAULT (datetime('now')),
    updated_at TEXT NOT NULL DEFAULT (datetime('now'))
);
```

### 2. Parent-Child Relationship
```sql
-- Parent
CREATE TABLE invoices (
    id TEXT PRIMARY KEY,
    -- ...
);

-- Child with cascade delete
CREATE TABLE line_items (
    id TEXT PRIMARY KEY,
    invoice_id TEXT NOT NULL REFERENCES invoices(id) ON DELETE CASCADE,
    -- ...
);
```

### 3. One-to-One with Unique Constraint
```sql
CREATE TABLE contpaqi_entries (
    id TEXT PRIMARY KEY,
    invoice_id TEXT UNIQUE NOT NULL REFERENCES invoices(id),
    -- UNIQUE ensures one entry per invoice
);
```

### Idempotent Migrations
```sql
-- Use IF NOT EXISTS for tables
CREATE TABLE IF NOT EXISTS vendors (...)

-- Use IF NOT EXISTS for indexes
CREATE INDEX IF NOT EXISTS idx_name ON table(column)
```

## Domain-Specific Design

### Invoice State Machine
```
UPLOADED → EXTRACTED → VALIDATED → POSTED
    ↑          ↑           ↑
    └──────────┴───────────┘ (can go back on error)
```

### Extraction Results Pattern
```sql
-- Store each extracted field as a row
CREATE TABLE extraction_results (
    invoice_id TEXT NOT NULL,
    field_name TEXT NOT NULL,      -- e.g., 'vendor_rfc', 'total'
    extracted_value TEXT NOT NULL,
    confidence REAL NOT NULL,       -- 0.0 to 100.0
    -- Optional bounding box for UI highlighting
    bbox_x INTEGER,
    bbox_y INTEGER,
    bbox_width INTEGER,
    bbox_height INTEGER,
    user_verified INTEGER DEFAULT 0
);
```

## Testing SQL Schemas

### Python Test Pattern
```python
import sqlite3
import tempfile

def test_schema_valid():
    with open('schema.sql') as f:
        sql = f.read()

    conn = sqlite3.connect(':memory:')
    conn.executescript(sql)

    # Verify tables exist
    cursor = conn.execute(
        "SELECT name FROM sqlite_master WHERE type='table'"
    )
    tables = [row[0] for row in cursor]
    assert 'invoices' in tables

def test_foreign_keys_work():
    conn = sqlite3.connect(':memory:')
    conn.execute('PRAGMA foreign_keys = ON')
    # ... test FK enforcement
```

## Best Practices

### 1. Always Use IF NOT EXISTS
Makes migrations idempotent and re-runnable.

### 2. Document Tables and Columns
Use SQL comments for clarity.

### 3. Validate Data at Schema Level
Use CHECK constraints for enums and ranges.

### 4. Plan for Soft Deletes
Consider `deleted_at` column instead of CASCADE.

### 5. Use Meaningful Defaults
```sql
created_at TEXT NOT NULL DEFAULT (datetime('now'))
```

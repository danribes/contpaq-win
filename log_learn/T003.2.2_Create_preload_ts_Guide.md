# Learning Guide: T003.2.2 - Electron Preload Scripts & Context Bridge

## Overview

Preload scripts are the secure bridge between Electron's main process (Node.js) and renderer process (Chromium). They run in an isolated context with limited access to Node.js APIs.

## Why Preload Scripts?

### The Security Problem

```
┌─────────────────┐     ┌─────────────────┐
│  Main Process   │     │ Renderer Process │
│    (Node.js)    │ ──? │   (Chromium)     │
│  Full OS Access │     │   Web Content    │
└─────────────────┘     └─────────────────┘
```

**Without proper isolation:**
- XSS attacks could run system commands
- Malicious web content could access filesystem
- Remote code execution vulnerabilities

### The Solution: Context Isolation

```
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│  Main Process   │     │  Preload Script  │     │ Renderer Process │
│    (Node.js)    │ ◄──►│ (Isolated Node)  │◄───►│   (Chromium)     │
│  Full OS Access │     │  Limited API     │     │   Web Content    │
└─────────────────┘     └─────────────────┘     └─────────────────┘
```

## Key Concepts

### contextBridge

The `contextBridge` module safely exposes APIs to the renderer:

```typescript
import { contextBridge, ipcRenderer } from 'electron';

contextBridge.exposeInMainWorld('myAPI', {
  doSomething: () => ipcRenderer.invoke('do-something'),
});
```

**In renderer:**
```typescript
window.myAPI.doSomething();
```

### Why Not Just Expose ipcRenderer?

**DANGEROUS - Never do this:**
```typescript
// BAD - Exposes full ipcRenderer
contextBridge.exposeInMainWorld('electron', {
  ipcRenderer: ipcRenderer  // Security risk!
});
```

**SAFE - Expose specific functions:**
```typescript
// GOOD - Controlled API
contextBridge.exposeInMainWorld('api', {
  getData: () => ipcRenderer.invoke('get-data'),
});
```

## IPC Patterns

### Pattern 1: invoke (Request/Response)

Main process handler:
```typescript
ipcMain.handle('get-user', async (event, userId) => {
  return await database.getUser(userId);
});
```

Preload exposure:
```typescript
invoke: (channel: string, ...args: unknown[]) => {
  return ipcRenderer.invoke(channel, ...args);
}
```

Renderer usage:
```typescript
const user = await window.api.invoke('get-user', 123);
```

### Pattern 2: send (Fire and Forget)

Main process listener:
```typescript
ipcMain.on('log-event', (event, data) => {
  logger.info(data);
});
```

Preload exposure:
```typescript
send: (channel: string, ...args: unknown[]) => {
  ipcRenderer.send(channel, ...args);
}
```

Renderer usage:
```typescript
window.api.send('log-event', { action: 'click' });
```

### Pattern 3: on (Subscribe to Events)

Main process emission:
```typescript
mainWindow.webContents.send('update-available', version);
```

Preload exposure:
```typescript
on: (channel: string, callback: Function) => {
  ipcRenderer.on(channel, (event, ...args) => callback(...args));
}
```

Renderer usage:
```typescript
window.api.on('update-available', (version) => {
  showUpdateDialog(version);
});
```

## Channel Whitelisting

### Why Whitelist?

Without whitelisting, renderer could call ANY channel:
```typescript
// Malicious code in renderer could call:
window.api.invoke('dangerous-system-command');
```

### Implementation

```typescript
const validChannels = ['get-data', 'save-data', 'get-config'];

const api = {
  invoke: (channel: string, ...args: unknown[]) => {
    if (!validChannels.includes(channel)) {
      throw new Error(`Invalid channel: ${channel}`);
    }
    return ipcRenderer.invoke(channel, ...args);
  },
};
```

### Channel Naming Convention

Use namespaced channels for organization:
```
ai:extract-invoice
ai:check-health
bridge:get-vendors
db:save-invoice
app:get-version
```

## TypeScript Integration

### Interface Definition

```typescript
export interface ElectronAPI {
  invoke: (channel: string, ...args: unknown[]) => Promise<unknown>;
  send: (channel: string, ...args: unknown[]) => void;
  on: (channel: string, callback: (...args: unknown[]) => void) => void;
}
```

### Global Window Type

```typescript
declare global {
  interface Window {
    api: ElectronAPI;
  }
}
```

### Type-Safe Channels (Advanced)

```typescript
type InvokeChannels = 'get-user' | 'save-user' | 'get-config';
type SendChannels = 'log' | 'analytics';
type ReceiveChannels = 'update-available' | 'error';

interface TypedAPI {
  invoke: (channel: InvokeChannels, ...args: unknown[]) => Promise<unknown>;
  send: (channel: SendChannels, ...args: unknown[]) => void;
  on: (channel: ReceiveChannels, callback: Function) => void;
}
```

## Security Best Practices

### 1. Never Expose Raw Objects

```typescript
// BAD
contextBridge.exposeInMainWorld('node', {
  fs: require('fs'),
  process: process,
});

// GOOD
contextBridge.exposeInMainWorld('api', {
  readConfig: () => ipcRenderer.invoke('read-config'),
});
```

### 2. Strip Event Objects

```typescript
// BAD - Exposes IpcRendererEvent
on: (channel, callback) => {
  ipcRenderer.on(channel, callback);
}

// GOOD - Strip event
on: (channel, callback) => {
  ipcRenderer.on(channel, (event, ...args) => callback(...args));
}
```

### 3. Validate Input in Main Process

```typescript
// Main process handler
ipcMain.handle('delete-file', async (event, path) => {
  // ALWAYS validate!
  if (!path.startsWith(app.getPath('userData'))) {
    throw new Error('Access denied');
  }
  await fs.unlink(path);
});
```

### 4. Cleanup Listeners

```typescript
// Expose removal methods
removeListener: (channel: string, callback: Function) => {
  ipcRenderer.removeListener(channel, callback);
},
removeAllListeners: (channel: string) => {
  ipcRenderer.removeAllListeners(channel);
}
```

## Common Mistakes

### Mistake 1: Forgetting contextIsolation

```typescript
// In main process - DON'T disable this!
new BrowserWindow({
  webPreferences: {
    contextIsolation: false, // BAD!
  },
});
```

### Mistake 2: Using nodeIntegration

```typescript
// DON'T enable this!
new BrowserWindow({
  webPreferences: {
    nodeIntegration: true, // BAD!
  },
});
```

### Mistake 3: Not Handling Errors

```typescript
// BAD
invoke: (channel) => ipcRenderer.invoke(channel);

// GOOD
invoke: (channel) => {
  if (!validChannels.includes(channel)) {
    return Promise.reject(new Error(`Invalid channel: ${channel}`));
  }
  return ipcRenderer.invoke(channel);
}
```

# Learning Guide: T002.2.1 - Python Package Initialization

## What is __init__.py?

`__init__.py` is a special file that makes a directory a Python **package**. When Python sees a directory with `__init__.py`, it treats that directory as importable.

## Package vs. Module

```
module.py          # A single Python file (module)

package/           # A directory with __init__.py (package)
├── __init__.py
├── submodule1.py
└── submodule2.py
```

```python
import module           # Import a module
import package          # Import a package (runs __init__.py)
from package import submodule1  # Import from package
```

## __init__.py Purposes

### 1. Mark Directory as Package
```
# Without __init__.py:
import src.models  # ImportError: No module named 'src'

# With __init__.py:
import src.models  # Works!
```

### 2. Package-Level Initialization
```python
# src/__init__.py
print("src package loaded!")  # Runs when package is imported

# Usage:
import src  # Prints: "src package loaded!"
```

### 3. Define Public API
```python
# src/__init__.py
from .models import Invoice
from .services import process_pdf

__all__ = ["Invoice", "process_pdf"]

# Usage:
from src import Invoice  # Works
from src import internal_helper  # Not exported
```

### 4. Package Metadata
```python
# src/__init__.py
__version__ = "0.1.0"
__author__ = "Team Name"

# Usage:
import src
print(src.__version__)  # "0.1.0"
```

## Common Patterns

### Empty __init__.py
```python
# src/__init__.py
# (empty file - just marks directory as package)
```
Valid but provides no convenience imports.

### Convenience Imports
```python
# src/__init__.py
from .models.invoice import Invoice
from .models.field import ExtractedField
from .services.processor import process_invoice

# Now users can do:
from src import Invoice, process_invoice
# Instead of:
from src.models.invoice import Invoice
```

### Lazy Loading
```python
# src/__init__.py
def __getattr__(name):
    if name == "heavy_module":
        from . import heavy_module
        return heavy_module
    raise AttributeError(f"module {__name__!r} has no attribute {name!r}")
```

### Version from File
```python
# src/__init__.py
from importlib.metadata import version

__version__ = version("contpaq-win-ai-service")
```

## Special Variables

### __version__
```python
__version__ = "0.1.0"
```
Standard way to expose package version. Should match pyproject.toml.

### __author__
```python
__author__ = "Developer Name"
```
Attribution information.

### __all__
```python
__all__ = ["public_function", "PublicClass"]
```
Controls what `from package import *` exports. Also serves as documentation of public API.

### __path__
```python
# Automatically set by Python
print(__path__)  # ['/path/to/package']
```
Used for namespace packages and plugin systems.

## Package Structure Best Practices

### Flat Structure
```
src/
├── __init__.py
├── models.py
├── services.py
└── api.py
```
Good for small packages.

### Nested Structure (Our Approach)
```
src/
├── __init__.py
├── models/
│   ├── __init__.py
│   └── invoice.py
├── services/
│   ├── __init__.py
│   └── processor.py
└── api/
    ├── __init__.py
    └── routes.py
```
Better for larger packages with clear separation.

## Import Patterns

### Absolute Imports
```python
# From anywhere in the project
from src.models.invoice import Invoice
```

### Relative Imports
```python
# From within src package
from .models.invoice import Invoice  # Same level
from ..other_package import something  # Parent level
```

### Re-exports in __init__.py
```python
# src/models/__init__.py
from .invoice import Invoice
from .field import ExtractedField

# Now possible:
from src.models import Invoice
```

## Our Implementation

```python
"""
ContPAQ-Win AI Service
...docstring...
"""

__version__ = "0.1.0"
__author__ = "ContPAQ-Win Team"
__all__ = ["__version__", "__author__"]
```

### Why This Structure?
1. **Docstring**: Describes package purpose (shown in help())
2. **__version__**: Allows `import src; print(src.__version__)`
3. **__author__**: Attribution
4. **__all__**: Explicit public API (will grow as we add modules)

## Testing Package Initialization

```python
def test_src_is_importable_package():
    """Verify src can be imported"""
    import src
    assert hasattr(src, '__version__')
    assert src.__version__ == "0.1.0"
```

## Common Mistakes

### 1. Circular Imports
```python
# src/__init__.py
from .models import Invoice  # Invoice imports from services
# src/services.py
from . import Invoice  # Circular!
```

**Solution**: Import at function level or restructure.

### 2. Heavy Imports
```python
# src/__init__.py
import torch  # Slow! Loads even if not needed
```

**Solution**: Lazy loading or don't import in __init__.py.

### 3. Missing __init__.py
```
src/
├── models/  # No __init__.py!
│   └── invoice.py
```

**Result**: `from src.models import invoice` fails.

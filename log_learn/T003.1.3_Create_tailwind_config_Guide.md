# Learning Guide: T003.1.3 - Tailwind CSS Configuration

## Overview

Tailwind CSS is a utility-first CSS framework that provides low-level utility classes to build custom designs. This guide covers configuration for Electron/React desktop applications.

## Key Concepts

### Utility-First CSS

Instead of writing custom CSS:
```css
.btn {
  padding: 0.5rem 1rem;
  background-color: #3b82f6;
  border-radius: 0.375rem;
}
```

Use utility classes directly:
```html
<button class="px-4 py-2 bg-blue-500 rounded-md">
```

### Content Configuration (Purging)

The `content` array tells Tailwind which files to scan for class names:

```javascript
content: [
  "./src/**/*.ts",
  "./src/**/*.tsx",
  "./src/**/*.html",
]
```

**Why this matters**: Tailwind generates thousands of utility classes. In production, unused classes are removed (tree-shaking). Only classes found in these files are kept.

**Important**: Always use explicit patterns. Both `*.ts` and `*.tsx` needed separately for clear test assertions.

### Theme Extension

```javascript
theme: {
  extend: {
    colors: {
      primary: '#0ea5e9',
    },
  },
}
```

**extend vs replace**: Using `extend` adds to Tailwind's defaults. Without `extend`, you replace all default values.

## Configuration Structure

### Basic tailwind.config.js

```javascript
/** @type {import('tailwindcss').Config} */
module.exports = {
  content: ["./src/**/*.tsx"],
  theme: {
    extend: {
      // Custom values here
    },
  },
  plugins: [],
};
```

### Color Scales

Tailwind uses numeric scales (50-900) for colors:

```javascript
colors: {
  primary: {
    50: '#f0f9ff',   // Lightest
    100: '#e0f2fe',
    500: '#0ea5e9',  // Default
    900: '#0c4a6e',  // Darkest
  },
}
```

Usage: `bg-primary-500`, `text-primary-900`

### Custom Spacing

```javascript
spacing: {
  '18': '4.5rem',   // Custom between 16 (4rem) and 20 (5rem)
  '128': '32rem',   // Large spacing
}
```

Usage: `p-18`, `w-128`

## Electron + Tailwind Integration

### With Vite

Tailwind integrates via PostCSS. In `vite.config.ts`:

```typescript
import tailwindcss from 'tailwindcss';
import autoprefixer from 'autoprefixer';

export default {
  css: {
    postcss: {
      plugins: [tailwindcss, autoprefixer],
    },
  },
};
```

### Entry CSS File

Create `src/renderer/index.css`:

```css
@tailwind base;
@tailwind components;
@tailwind utilities;
```

## Best Practices

### 1. Use Semantic Color Names

```javascript
// Good - semantic meaning
colors: {
  success: '#22c55e',
  warning: '#f59e0b',
  error: '#ef4444',
}

// Avoid - no meaning
colors: {
  green1: '#22c55e',
  orange1: '#f59e0b',
}
```

### 2. Extend Don't Replace

Always put customizations in `extend` to keep Tailwind defaults:

```javascript
theme: {
  extend: {  // Keeps defaults
    fontFamily: {
      sans: ['Inter', 'system-ui'],
    },
  },
}
```

### 3. Keep plugins Array

Even if empty, include plugins for future additions:

```javascript
plugins: [],  // Ready for @tailwindcss/forms, etc.
```

### 4. TypeScript Integration

Use JSDoc type hint for IDE autocomplete:

```javascript
/** @type {import('tailwindcss').Config} */
module.exports = { ... }
```

## Common Tailwind Classes

### Layout
- `flex`, `grid`, `block`, `hidden`
- `justify-center`, `items-center`
- `gap-4`, `space-x-2`

### Spacing
- `p-4` (padding all), `px-4` (padding x), `py-4` (padding y)
- `m-4` (margin all), `mx-auto` (center horizontally)

### Colors
- `bg-blue-500`, `text-gray-700`
- `border-red-500`, `ring-green-500`

### Typography
- `text-sm`, `text-lg`, `text-2xl`
- `font-bold`, `font-medium`
- `leading-tight`, `tracking-wide`

### Borders
- `rounded`, `rounded-lg`, `rounded-full`
- `border`, `border-2`

## Testing Considerations

When testing Tailwind config files:
- Use string matching for key sections (`content`, `theme`, `extend`, `plugins`)
- Check for required file patterns (`.ts`, `.tsx`)
- Verify export syntax (`module.exports` or `export default`)
- Config is JavaScript, not JSON - can't use json.loads()

# Learning Guide: T001.1.1 - Create ai-service Directory Structure

## Overview

This guide explains the first step in setting up the ContPAQ-Win project: creating the directory structure for the AI service component.

## What is the AI Service?

The AI Service is one of three main components in the ContPAQ-Win architecture:

```
┌─────────────────────────┐
│  Desktop App (Electron) │  ← User interface
└───────────┬─────────────┘
            │
    ┌───────┴───────┐
    ▼               ▼
┌───────────┐  ┌───────────┐
│ AI Service│  │  Windows  │  ← This is what we're building
│  (Python) │  │  Bridge   │
│ port 8000 │  │  (C#)     │
└───────────┘  └───────────┘
```

The AI Service is responsible for:
- **PDF Processing**: Extract text from PDF invoices
- **OCR**: Convert scanned PDFs to text using Tesseract
- **AI Extraction**: Use LayoutLMv3 to identify invoice fields
- **Validation**: Validate RFC and CFDI compliance

## Why This Directory Structure?

### Standard Python Project Layout

The `ai-service/` directory follows Python best practices:

```
ai-service/
├── src/           ← Source code goes here
│   ├── models/    ← Pydantic data models
│   ├── services/  ← Business logic
│   ├── api/       ← FastAPI routes
│   └── utils/     ← Helper functions
└── tests/         ← Test files go here
    ├── unit/      ← Unit tests
    └── integration/ ← Integration tests
```

### Separation of Concerns

- **`src/`**: Contains only production code
- **`tests/`**: Contains only test code
- This separation makes it easy to:
  - Package only production code for deployment
  - Run tests independently
  - Calculate code coverage accurately

## Test-Driven Development (TDD)

### What is TDD?

TDD is a software development approach where you:
1. **Red**: Write a failing test first
2. **Green**: Write minimal code to make the test pass
3. **Refactor**: Improve the code while keeping tests green

### Why TDD for This Project?

The Constitution (`.specify/memory/constitution.md`) mandates TDD:

> **III. Test-First Development (NON-NEGOTIABLE)**
>
> All features MUST follow TDD methodology.
> - Tests MUST be written before implementation
> - Tests MUST fail before implementation begins (Red phase)

### TDD in Action (This Task)

**Red Phase** - We wrote tests that check if directories exist:
```python
def test_ai_service_directory_exists(self):
    ai_service_path = os.path.join(PROJECT_ROOT, "ai-service")
    assert os.path.isdir(ai_service_path)
```

The test failed because the directory didn't exist yet.

**Green Phase** - We created the directories:
```bash
mkdir -p ai-service/src ai-service/tests
```

Now the tests pass!

## Why Use .gitkeep Files?

Git doesn't track empty directories. To ensure our directory structure is preserved in version control, we add `.gitkeep` files:

```bash
touch ai-service/src/.gitkeep
touch ai-service/tests/.gitkeep
```

These are empty placeholder files that:
- Have no functional purpose
- Ensure git tracks the directory
- Are a common convention in software projects

## What is Serilog?

Serilog is a structured logging library for .NET that captures log data as structured events rather than plain text. This enables powerful log analysis and querying.

### Key Concepts

1. **Message Templates** - Logs with named placeholders
2. **Sinks** - Output destinations (Console, File, Database, etc.)
3. **Enrichers** - Add contextual data to every log
4. **Formatters** - Control output format (text, JSON, etc.)

---

## Serilog vs Built-in Logging

| Feature | Microsoft.Extensions.Logging | Serilog |
|---------|------------------------------|---------|
| Structured logging | Basic | Advanced |
| Output formats | Limited | Extensive |
| Enrichers | Manual | Built-in + custom |
| Sinks | Providers | 100+ sinks |
| Configuration | appsettings.json | Code + config |

## Compact JSON Format

Serilog's `CompactJsonFormatter` produces minimal JSON output:

```json
{"@t":"2025-12-18T12:34:56.789Z","@l":"Information","@m":"User logged in","UserId":"U001"}
```

### Field Mappings

| Field | Description | Example |
|-------|-------------|---------|
| `@t` | Timestamp (ISO 8601) | `2025-12-18T12:34:56.789Z` |
| `@m` | Message | `"User logged in"` |
| `@l` | Level | `"Information"` |
| `@x` | Exception | Full stack trace |
| `@i` | Event ID | `12345` |
| Custom | Your properties | Any name |

### Why Compact Format?

- **Smaller size** - No redundant field names
- **Faster parsing** - Consistent structure
- **Compatible** - Works with ELK, Splunk, etc.

## Setting Up Serilog

### 1. Install Packages

```bash
dotnet add package Serilog.AspNetCore
dotnet add package Serilog.Sinks.Console
dotnet add package Serilog.Sinks.File
dotnet add package Serilog.Formatting.Compact
dotnet add package Serilog.Enrichers.Environment
dotnet add package Serilog.Enrichers.Process
dotnet add package Serilog.Enrichers.Thread
```

### 2. Configure in Program.cs

```csharp
using Serilog;
using Serilog.Formatting.Compact;

// Bootstrap logger for startup
Log.Logger = new LoggerConfiguration()
    .WriteTo.Console(new CompactJsonFormatter())
    .CreateBootstrapLogger();

try
{
    var builder = WebApplication.CreateBuilder(args);

    // Full configuration with host integration
    builder.Host.UseSerilog((context, services, configuration) => configuration
        .ReadFrom.Configuration(context.Configuration)
        .ReadFrom.Services(services)
        .Enrich.FromLogContext()
        .Enrich.WithMachineName()
        .WriteTo.Console(new CompactJsonFormatter())
        .WriteTo.File(
            new CompactJsonFormatter(),
            "logs/app-.log",
            rollingInterval: RollingInterval.Day));

    var app = builder.Build();
    app.UseSerilogRequestLogging();
    app.Run();
}
catch (Exception ex)
{
    Log.Fatal(ex, "Application terminated unexpectedly");
}
finally
{
    Log.CloseAndFlush();
}
```

## Structured Logging Examples

### Basic Logging

```csharp
// Plain message
Log.Information("Application started");

// With structured data
Log.Information("Processing order {OrderId} for {Customer}", orderId, customerName);
```

### With Extra Context

```csharp
// Using ForContext
var log = Log.ForContext<OrderService>();
log.Information("Processing order {OrderId}", orderId);

// Using PushProperty
using (LogContext.PushProperty("CorrelationId", correlationId))
{
    Log.Information("Starting request");
    // All logs in this scope have CorrelationId
}
```

### Exception Logging

```csharp
try
{
    ProcessOrder(order);
}
catch (Exception ex)
{
    Log.Error(ex, "Failed to process order {OrderId}", order.Id);
}
```

## Enrichers

Enrichers add context to every log entry:

```csharp
.Enrich.FromLogContext()           // Dynamic properties
.Enrich.WithMachineName()          // Computer name
.Enrich.WithEnvironmentName()      // Dev/Staging/Prod
.Enrich.WithProcessId()            // Process ID
.Enrich.WithProcessName()          // Process name
.Enrich.WithThreadId()             // Thread ID
.Enrich.WithProperty("App", "MyApp") // Static property
```

### Custom Enricher

```csharp
public class UserEnricher : ILogEventEnricher
{
    public void Enrich(LogEvent logEvent, ILogEventPropertyFactory factory)
    {
        var user = GetCurrentUser();
        logEvent.AddPropertyIfAbsent(
            factory.CreateProperty("UserId", user?.Id ?? "anonymous"));
    }
}

// Register
.Enrich.With<UserEnricher>()
```

## File Sinks with Rotation

### Size-Based Rotation

```csharp
.WriteTo.File(
    new CompactJsonFormatter(),
    "logs/app.log",
    fileSizeLimitBytes: 10_000_000,  // 10 MB
    rollOnFileSizeLimit: true,
    retainedFileCountLimit: 5)
```

### Time-Based Rotation

```csharp
.WriteTo.File(
    new CompactJsonFormatter(),
    "logs/app-.log",
    rollingInterval: RollingInterval.Day,
    retainedFileCountLimit: 30)
```

### Combined

```csharp
.WriteTo.File(
    formatter: new CompactJsonFormatter(),
    path: "logs/app-.log",
    rollingInterval: RollingInterval.Day,
    fileSizeLimitBytes: 10_000_000,
    rollOnFileSizeLimit: true,
    retainedFileCountLimit: 30,
    shared: true,                      // Multiple processes
    flushToDiskInterval: TimeSpan.FromSeconds(1))
```

## Log Level Filtering

### Per-Namespace

```csharp
.MinimumLevel.Information()
.MinimumLevel.Override("Microsoft", LogEventLevel.Warning)
.MinimumLevel.Override("Microsoft.AspNetCore", LogEventLevel.Warning)
.MinimumLevel.Override("System", LogEventLevel.Warning)
.MinimumLevel.Override("Microsoft.Hosting.Lifetime", LogEventLevel.Information)
```

### In appsettings.json

```json
{
  "Serilog": {
    "MinimumLevel": {
      "Default": "Information",
      "Override": {
        "Microsoft": "Warning",
        "System": "Warning"
      }
    }
  }
}
```

## Request Logging

ASP.NET Core integration provides automatic request logging:

```csharp
app.UseSerilogRequestLogging(options =>
{
    options.EnrichDiagnosticContext = (diagnosticContext, httpContext) =>
    {
        diagnosticContext.Set("RequestHost", httpContext.Request.Host.Value);
        diagnosticContext.Set("UserAgent", httpContext.Request.Headers["User-Agent"]);
    };
});
```

Output:
```json
{"@t":"2025-12-18T12:34:56.789Z","@l":"Information","@m":"HTTP GET /api/orders responded 200 in 45.2ms","RequestMethod":"GET","RequestPath":"/api/orders","StatusCode":200,"Elapsed":45.2}
```

## Best Practices

### 1. Use Message Templates

```csharp
// Good - structured
Log.Information("Order {OrderId} created by {UserId}", orderId, userId);

// Bad - string interpolation
Log.Information($"Order {orderId} created by {userId}");
```

### 2. Set Appropriate Log Levels

| Level | Use For |
|-------|---------|
| Verbose | Detailed debugging info |
| Debug | Development diagnostics |
| Information | Normal operations |
| Warning | Unexpected but handled |
| Error | Failures |
| Fatal | Application crash |

### 3. Include Correlation IDs

```csharp
app.Use(async (context, next) =>
{
    var correlationId = context.Request.Headers["X-Correlation-ID"].FirstOrDefault()
        ?? Guid.NewGuid().ToString();

    using (LogContext.PushProperty("CorrelationId", correlationId))
    {
        await next();
    }
});
```

### 4. Avoid Sensitive Data

```csharp
// Bad - logs password
Log.Information("Login attempt for {User} with password {Password}", user, password);

// Good - omit sensitive data
Log.Information("Login attempt for {User}", user);
```

## Key Takeaways

1. **Serilog enables structured logging** - Properties, not string concatenation
2. **Compact JSON is efficient** - Smaller logs, consistent format
3. **Enrichers add context automatically** - Machine, process, thread info
4. **File rotation prevents disk issues** - Size and time-based limits
5. **Filter by namespace** - Reduce noise from framework logs
6. **Request logging is built-in** - UseSerilogRequestLogging()

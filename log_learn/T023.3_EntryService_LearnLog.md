## Concepts Learned

### 1. Thread-Safe Stub Implementation
Use locking for static shared data:

```csharp
private static readonly List<EntryRecord> _testEntries = new();
private static readonly object _lock = new();

public async Task<EntryResultDto> CreateAsync(CreateEntryRequest entry)
{
    string folio;
    lock (_lock)
    {
        folio = $"POL-{year}-{_folioCounter++:D4}";
        _testEntries.Add(new EntryRecord { Folio = folio, ... });
    }
    return new EntryResultDto { Folio = folio };
}
```

Why locking:
- Static data shared across all instances
- Counter increment and list add must be atomic
- Prevents race conditions in concurrent requests
- Test data pattern - SDK integration won't need this

### 2. Internal Record for Data Storage
Use private nested record for internal data:

```csharp
private record EntryRecord
{
    public required string Folio { get; init; }
    public required string VendorRfc { get; init; }
    public required string InvoiceNumber { get; init; }
    public DateTime InvoiceDate { get; init; }
    public decimal Total { get; init; }
    public DateTime CreatedAt { get; init; }
}
```

Benefits:
- Encapsulates internal storage structure
- Immutable by default (init-only)
- `required` ensures critical fields are set
- Separate from public DTOs

### 3. Folio Generation Pattern
Generate sequential identifiers with date prefix:

```csharp
private static int _folioCounter = 1;

var year = DateTime.Now.Year;
folio = $"POL-{year}-{_folioCounter++:D4}";
// POL-2024-0001, POL-2024-0002, ...
```

Format breakdown:
- `POL-` prefix for "póliza"
- Year for partitioning
- 4-digit padded counter (`D4`)
- Increment is thread-safe in lock block

### 4. Case-Insensitive Comparison
Use StringComparison for lookups:

```csharp
var existingEntry = _testEntries.FirstOrDefault(e =>
    e.VendorRfc.Equals(vendorRfc, StringComparison.OrdinalIgnoreCase) &&
    e.InvoiceNumber.Equals(invoiceNumber, StringComparison.OrdinalIgnoreCase));
```

Why OrdinalIgnoreCase:
- Fastest case-insensitive comparison
- Works for alphanumeric identifiers
- No culture-specific rules needed
- Consistent behavior across locales

### 5. Nullable Return Pattern
Return null for "not found" scenarios:

```csharp
public async Task<EntryResultDto?> GetByFolioAsync(string folio)
{
    if (string.IsNullOrWhiteSpace(folio))
        return null;

    var entry = _testEntries.FirstOrDefault(...);
    if (entry == null)
        return null;

    return new EntryResultDto { ... };
}
```

Pattern:
- Validate input first (return null for invalid)
- Search for entity
- Return null if not found
- Return DTO if found
- Caller handles null case

### 6. Spanish Message Construction
Include contextual data in messages:

```csharp
return new DuplicateCheckResult
{
    IsDuplicate = true,
    ExistingFolio = existingEntry.Folio,
    Message = $"Ya existe una póliza registrada con estos datos (Folio: {existingEntry.Folio})"
```

Best practices:
- Include relevant identifiers in message
- Use Spanish for user-facing content
- Keep technical details (folio) visible
- Actionable message for user

## Best Practices Identified

1. **Thread-safe static data**: Always use locking
2. **Private nested types**: Hide implementation details
3. **Validate inputs first**: Check null/empty before processing
4. **Case-insensitive lookups**: Use StringComparison
5. **Structured folio format**: Year + counter for partitioning
6. **Contextual messages**: Include relevant identifiers

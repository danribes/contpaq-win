# Learning Guide: T001.1.2 - Create desktop-app Directory Structure

## Overview

This guide explains the directory structure for the Electron/React desktop application component of ContPAQ-Win.

## What is the Desktop App?

The Desktop App is the user-facing component of ContPAQ-Win:

```
┌─────────────────────────┐
│  Desktop App (Electron) │  ← THIS COMPONENT
│  - User interface       │
│  - Process management   │
│  - Local database       │
└───────────┬─────────────┘
            │
    ┌───────┴───────┐
    ▼               ▼
┌───────────┐  ┌───────────┐
│ AI Service│  │  Windows  │
│  (Python) │  │  Bridge   │
└───────────┘  └───────────┘
```

The Desktop App is responsible for:
- **User Interface**: React-based UI for invoice processing
- **Process Management**: Start/stop/monitor AI Service and Windows Bridge
- **Local Storage**: SQLite database for invoice data
- **PDF Viewing**: Display PDFs with extraction highlighting

## Electron Architecture

Electron applications have two main processes:

### Main Process (`src/main/`)
The main process runs in Node.js and has access to:
- Operating system APIs
- File system
- Process spawning
- Window management

Future files:
```
desktop-app/src/main/
├── index.ts           # Application entry point
├── preload.ts         # Context bridge for renderer
├── process-manager.ts # Manage AI service & bridge processes
└── ipc-handlers.ts    # Handle IPC messages from renderer
```

### Renderer Process (`src/renderer/`)
The renderer process runs in Chromium and displays the UI:
- React components
- Tailwind CSS styling
- User interactions

Future files:
```
desktop-app/src/renderer/
├── index.html         # HTML template
├── index.tsx          # React entry point
├── App.tsx            # Root component
├── components/        # Reusable UI components
│   ├── InvoiceForm/
│   ├── PDFViewer/
│   └── StatusBar/
├── pages/             # Page components
├── services/          # API clients
├── hooks/             # Custom React hooks
├── i18n/              # Spanish translations
└── types/             # TypeScript interfaces
```

## Why Separate main/ and renderer/?

### Security (Context Isolation)
Electron security best practice requires separating main and renderer:
- Renderer has limited access (like a web page)
- Main has full system access
- Communication happens via IPC (Inter-Process Communication)

### Different Environments
- **Main**: Node.js environment, can use require(), fs, etc.
- **Renderer**: Browser environment, uses React, DOM APIs

### Build Process
Different bundling configurations:
- Main: Bundled for Node.js
- Renderer: Bundled for browser with webpack/vite

## Key Concepts

### 1. Process Isolation
Main and renderer are separate processes that communicate via:
- `ipcMain` / `ipcRenderer` - Async messaging
- `contextBridge` - Safe API exposure in preload

### 2. Preload Scripts
The preload script runs before the renderer:
```typescript
// preload.ts
contextBridge.exposeInMainWorld('electronAPI', {
  openFile: () => ipcRenderer.invoke('dialog:openFile'),
  extractInvoice: (path) => ipcRenderer.invoke('ai:extract', path),
});
```

### 3. Tailwind CSS
All styling uses Tailwind utility classes:
```tsx
// Using Tailwind (required by constitution)
<button className="bg-blue-500 hover:bg-blue-700 text-white font-bold py-2 px-4 rounded">
  Procesar Factura
</button>
```

## Directory Structure Rationale

```
desktop-app/
└── src/
    ├── main/        # Electron main process
    │   └── .gitkeep
    └── renderer/    # React renderer process
        └── .gitkeep
```

This structure:
1. **Separates concerns** between main and renderer
2. **Enables code splitting** for better bundling
3. **Follows Electron conventions** for electron-builder
4. **Supports TypeScript** with separate tsconfig per process

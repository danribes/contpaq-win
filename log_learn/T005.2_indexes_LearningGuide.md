# T005.2 Learning Guide: Database Indexing in SQLite

## Overview
This guide covers database indexing strategies for SQLite, focusing on performance optimization for invoice processing applications.

## What Are Indexes?

Indexes are data structures that improve query speed by allowing the database to find rows without scanning the entire table.

```sql
-- Without index: O(n) full table scan
SELECT * FROM invoices WHERE state = 'UPLOADED';

-- With index: O(log n) index lookup
CREATE INDEX idx_invoice_state ON invoices(state);
```

## SQLite Index Types

### 1. Regular Index
```sql
CREATE INDEX idx_name ON table(column);

-- Multiple columns (compound index)
CREATE INDEX idx_name ON table(col1, col2);
```

### 2. Unique Index
```sql
-- Enforces uniqueness
CREATE UNIQUE INDEX idx_name ON table(column);

-- Equivalent to UNIQUE constraint
-- SQLite creates implicit index for UNIQUE columns
```

### 3. Partial Index
```sql
-- Only index rows matching condition
CREATE INDEX idx_active ON invoices(state)
WHERE state != 'POSTED';
```

## Index Design Patterns

### 1. Foreign Key Indexes
Always index foreign key columns for join performance:
```sql
-- Parent-child relationship
CREATE TABLE invoices (id TEXT PRIMARY KEY, ...);
CREATE TABLE line_items (invoice_id TEXT REFERENCES invoices(id), ...);

-- Index the FK
CREATE INDEX idx_lineitem_invoice ON line_items(invoice_id);
```

### 2. Query Pattern Indexes
Index columns used in WHERE clauses:
```sql
-- Common query: get invoices by state
SELECT * FROM invoices WHERE state = 'UPLOADED';

-- Create matching index
CREATE INDEX idx_invoice_state ON invoices(state);
```

### 3. Compound Indexes
For queries filtering on multiple columns:
```sql
-- Query pattern
SELECT * FROM extraction_results
WHERE invoice_id = ? AND field_name = ?;

-- Compound index (order matters!)
CREATE INDEX idx_extraction_field ON extraction_results(invoice_id, field_name);
```

### 4. Covering Indexes
Include all columns needed by query:
```sql
-- Query only needs these columns
SELECT state, created_at FROM invoices WHERE vendor_id = ?;

-- Covering index (no table lookup needed)
CREATE INDEX idx_invoice_vendor_state ON invoices(vendor_id, state, created_at);
```

## Index Naming Conventions

| Pattern | Example | Use Case |
|---------|---------|----------|
| `idx_{table}_{column}` | idx_invoice_state | Single column |
| `idx_{table}_{col1}_{col2}` | idx_extraction_invoice_field | Compound |
| `uidx_{table}_{column}` | uidx_vendor_rfc | Unique |

## When to Index

### Do Index:
- Foreign key columns
- Columns in WHERE clauses
- Columns in ORDER BY
- Columns in JOIN conditions
- Columns with high cardinality

### Don't Index:
- Small tables (< 1000 rows)
- Columns with low cardinality (few unique values)
- Columns frequently updated
- Columns rarely used in queries

## Analyzing Query Performance

### EXPLAIN QUERY PLAN
```sql
-- See how SQLite executes the query
EXPLAIN QUERY PLAN
SELECT * FROM invoices WHERE state = 'UPLOADED';

-- Output indicates index usage
-- SEARCH TABLE invoices USING INDEX idx_invoice_state
```

### Without Index
```
SCAN TABLE invoices (~1000 rows)
```

### With Index
```
SEARCH TABLE invoices USING INDEX idx_invoice_state (state=?)
```

## SQLite Index Internals

### B-Tree Structure
SQLite uses B-tree indexes:
- Balanced tree structure
- O(log n) lookups
- Automatically maintained on INSERT/UPDATE/DELETE

### Storage Cost
- Indexes require additional disk space
- Each index roughly doubles write time
- Trade-off: read performance vs. write performance

## Best Practices

### 1. Use IF NOT EXISTS
```sql
CREATE INDEX IF NOT EXISTS idx_name ON table(column);
```
Makes migration idempotent.

### 2. Index Order Matters
For compound indexes, put most selective column first:
```sql
-- Better: state has few values, invoice_id has many
CREATE INDEX idx_name ON extraction_results(invoice_id, field_name);

-- Worse: reversed
CREATE INDEX idx_name ON extraction_results(field_name, invoice_id);
```

### 3. Don't Over-Index
- Each index slows writes
- Only create indexes for actual query patterns
- Monitor and remove unused indexes

### 4. Consider Partial Indexes
```sql
-- Only index non-archived invoices
CREATE INDEX idx_active_invoices ON invoices(state)
WHERE state != 'ARCHIVED';
```

## Common Mistakes

### 1. Missing FK Indexes
```sql
-- Bad: FK without index
invoice_id TEXT REFERENCES invoices(id)

-- Good: Add index
CREATE INDEX idx_lineitem_invoice ON line_items(invoice_id);
```

### 2. Wrong Column Order
```sql
-- Query: WHERE a = ? AND b = ?
-- Bad: CREATE INDEX idx ON table(b, a)
-- Good: CREATE INDEX idx ON table(a, b)
```

### 3. Duplicate Indexes
```sql
-- Redundant: UNIQUE creates implicit index
CREATE TABLE vendors (rfc TEXT UNIQUE);
CREATE INDEX idx_rfc ON vendors(rfc);  -- May be redundant
```

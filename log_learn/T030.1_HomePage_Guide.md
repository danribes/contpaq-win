# T030.1 Learning Guide: HomePage with Invoices List, Filters, and Empty State

## Overview

This guide covers creating a home page component in React that displays a list of invoices with filtering capabilities, navigation actions, and empty states. The component uses Tailwind CSS for styling and interacts with the Electron main process via IPC.

## Key Concepts

### 1. Fetching Data on Mount with useEffect

```typescript
// Fetch invoices when filter changes (also runs on mount)
useEffect(() => {
  fetchInvoices(activeFilter);
}, [activeFilter, fetchInvoices]);

// Fetch counts on mount only
useEffect(() => {
  fetchCounts();
}, [fetchCounts]);
```

**Key Points:**
- Avoid duplicate calls by consolidating effects
- Use proper dependency arrays
- Handle loading and error states

### 2. IPC Communication with Electron

```typescript
const result = await window.electronAPI.invoke('db:get-invoices', filters);

if (result && typeof result === 'object') {
  const response = result as { success: boolean; invoices?: Invoice[] };
  if (response.success && response.invoices) {
    setInvoices(response.invoices);
  }
}
```

**Key Points:**
- Always check response success status
- Handle both success and error cases
- Type-check responses before using them

### 4. Empty State Component

```tsx
function EmptyState({ filterState }: EmptyStateProps): JSX.Element {
  const getMessage = (): string => {
    if (filterState) {
      const stateLabel = STATUS_CONFIG[filterState]?.label.toLowerCase();
      return `No hay facturas ${stateLabel}s`;
    }
    return 'No hay facturas';
  };

  return (
    <div data-testid="empty-state" className="flex flex-col items-center py-16">
      <EmptyIcon />
      <h3>{getMessage()}</h3>
      <p>Haga clic en "Nueva Factura" para comenzar...</p>
      <button onClick={() => navigate('/processing')}>
        Nueva Factura
      </button>
    </div>
  );
}
```

### 5. Currency and Date Formatting

```typescript
// Mexican Peso currency format
function formatCurrency(amount: number): string {
  return new Intl.NumberFormat('es-MX', {
    style: 'currency',
    currency: 'MXN',
  }).format(amount);
}

// Spanish locale date format
function formatDate(dateString: string): string {
  const date = new Date(dateString);
  return new Intl.DateTimeFormat('es-MX', {
    day: '2-digit',
    month: '2-digit',
    year: 'numeric',
  }).format(date);
}
```

## Testing Strategies

### 1. Setting Up Global Mocks
```typescript
// In tests/setup.ts
Object.defineProperty(window, 'electronAPI', {
  writable: true,
  value: {
    invoke: jest.fn().mockResolvedValue({ success: true, invoices: [] }),
    send: jest.fn(),
    on: jest.fn(),
    removeListener: jest.fn(),
  },
});
```

### 2. Mocking Multiple IPC Calls
```typescript
mockInvoke
  .mockResolvedValueOnce({ success: true, invoices: sampleInvoices }) // first call
  .mockResolvedValueOnce({ success: true, invoices: sampleInvoices }) // second call
  .mockResolvedValueOnce({ success: true, invoices: [] }); // third call
```

### 3. Testing with waitFor
```typescript
it('should display invoices', async () => {
  mockInvoke.mockResolvedValue({ success: true, invoices: sampleInvoices });

  renderWithRouter(<HomePage />);

  await waitFor(() => {
    expect(screen.getByText('FAC-001')).toBeInTheDocument();
  });
});
```

### 4. Testing Filter Interactions
```typescript
it('should filter when tab clicked', async () => {
  const user = userEvent.setup();
  renderWithRouter(<HomePage />);

  await user.click(screen.getByText(/validadas/i));

  await waitFor(() => {
    expect(mockInvoke).toHaveBeenCalledWith('db:get-invoices',
      expect.objectContaining({ state: 'VALIDATED' })
    );
  });
});
```

### 5. Testing Duplicate Text Elements
```typescript
// When same text appears multiple times
it('should display vendor names', async () => {
  renderWithRouter(<HomePage />);

  await waitFor(() => {
    const elements = screen.getAllByText('Proveedor A');
    expect(elements.length).toBeGreaterThanOrEqual(1);
  });
});
```

## Common Pitfalls

### 1. Double useEffect Calls

**Problem**: Component fetches data twice on mount.

**Solution**: Consolidate effects or use a flag:
```typescript
// Bad - calls fetchInvoices twice
useEffect(() => { fetchInvoices(filter); fetchCounts(); }, []);
useEffect(() => { fetchInvoices(filter); }, [filter]);

// Good - single call on filter change (including mount)
useEffect(() => { fetchInvoices(filter); }, [filter]);
useEffect(() => { fetchCounts(); }, []);
```

### 2. Mock Call Sequence

**Problem**: Tests fail because mock doesn't match call sequence.

**Solution**: Account for all IPC calls in order:
```typescript
// Component makes: fetchInvoices, fetchCounts, then fetchInvoices on filter change
mockInvoke
  .mockResolvedValueOnce({ success: true, invoices: data })
  .mockResolvedValueOnce({ success: true, invoices: data })  // fetchCounts
  .mockResolvedValueOnce({ success: true, invoices: [] });   // filter change
```

### 3. Link vs Button for Navigation

**Problem**: Need both click action and navigation.

**Solution**: Wrap button in Link:
```tsx
<Link to="/processing" data-testid="new-invoice-link">
  <button className="...">Nueva Factura</button>
</Link>
```

## Best Practices

1. **Loading States**: Always show loading indicator during async operations
2. **Error Handling**: Display user-friendly error messages
3. **Empty States**: Provide actionable empty states with instructions
4. **Localization**: Use Intl APIs for dates and currency

6. **Test IDs**: Add data-testid for elements that need testing

# Learning Guide: T002.4.2 - Test Fixtures Directory

## What are Test Fixtures?

Test fixtures are reusable test data and resources:
- Sample files (PDFs, images, JSON)
- Mock data structures
- Expected output for validation
- Configuration files for testing

## Fixtures Directory Structure

```
ai-service/
└── tests/
    ├── conftest.py         # Shared pytest fixtures
    ├── fixtures/           # Test data files
    │   ├── __init__.py     # Package marker
    │   ├── sample_invoice.pdf
    │   └── sample_scanned_invoice.pdf
    ├── unit/               # Unit tests
    └── integration/        # Integration tests
```

## Why a Fixtures Package?

### Benefits

1. **Centralized test data**: All fixtures in one location
2. **Importable paths**: Can access via Python imports
3. **Version controlled**: Fixtures tracked with code
4. **Reusable**: Multiple tests can use same fixtures

### Package vs Directory

```python
# With __init__.py (package)
from ai_service.tests.fixtures import sample_data

# Without __init__.py (just directory)
# Cannot import, must use file paths
```

## Using FIXTURES_DIR from conftest.py

### In conftest.py

```python
from pathlib import Path

FIXTURES_DIR = Path(__file__).parent / "fixtures"

@pytest.fixture
def sample_pdf_path():
    return FIXTURES_DIR / "sample_invoice.pdf"
```

### In Test Files

```python
from ai_service.tests.conftest import FIXTURES_DIR

def test_pdf_processing():
    pdf_path = FIXTURES_DIR / "sample_invoice.pdf"
    result = process_pdf(pdf_path)
    assert result is not None
```

## Common Fixture Types

### 1. Sample Files

```
fixtures/
├── sample_invoice.pdf      # Real PDF for testing
├── sample_image.png        # Image for OCR testing
└── expected_output.json    # Expected extraction result
```

### 2. Mock Data

```python
# fixtures/mock_data.py
SAMPLE_INVOICE_DATA = {
    "vendor_rfc": "ABC123456789",
    "vendor_name": "Test Vendor",
    "total": 1234.56,
}
```

### 3. Test Configuration

```
fixtures/
└── test_config.env         # Test environment variables
```

## Best Practices

### 1. Keep Fixtures Small

```python
# Good - minimal fixture
SAMPLE_RFC = "ABC123456789"

# Bad - huge fixture
HUGE_DATABASE_DUMP = {...}  # 10000 lines
```

### 2. Use Descriptive Names

```
fixtures/
├── invoice_text_based.pdf      # Clear purpose
├── invoice_scanned_low_res.pdf # Specific variant
└── invoice_multi_page.pdf      # Different scenario
```

### 3. Include Expected Outputs

```
fixtures/
├── sample_invoice.pdf
└── sample_invoice_expected.json  # Expected extraction result
```

### 4. Document Fixtures

```python
# fixtures/__init__.py
"""
Test Fixtures:
- sample_invoice.pdf: Standard Mexican invoice (CFDI)
- sample_scanned_invoice.pdf: Scanned invoice at 300 DPI
"""
```

## Fixture Loading Patterns

### 1. Direct File Path

```python
def test_process_pdf():
    pdf_path = FIXTURES_DIR / "sample_invoice.pdf"
    with open(pdf_path, "rb") as f:
        content = f.read()
    # Process content
```

### 2. Pytest Fixture

```python
@pytest.fixture
def sample_pdf_bytes():
    pdf_path = FIXTURES_DIR / "sample_invoice.pdf"
    with open(pdf_path, "rb") as f:
        return f.read()

def test_process_pdf(sample_pdf_bytes):
    result = process_pdf(sample_pdf_bytes)
    assert result is not None
```

### 3. Factory Fixture

```python
@pytest.fixture
def pdf_loader():
    def _loader(filename):
        path = FIXTURES_DIR / filename
        with open(path, "rb") as f:
            return f.read()
    return _loader

def test_multiple_pdfs(pdf_loader):
    pdf1 = pdf_loader("invoice1.pdf")
    pdf2 = pdf_loader("invoice2.pdf")
```

## Testing with Fixtures

### Check Fixture Exists

```python
def test_fixture_exists():
    pdf_path = FIXTURES_DIR / "sample_invoice.pdf"
    assert pdf_path.exists(), f"Fixture missing: {pdf_path}"
```

### Skip If Missing

```python
@pytest.mark.skipif(
    not (FIXTURES_DIR / "sample_invoice.pdf").exists(),
    reason="Fixture file not available"
)
def test_pdf_extraction():
    # Test that requires fixture
    pass
```

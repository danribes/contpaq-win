## Concepts Learned

### 1. TypeScript HTTP Client Pattern
Structure for service clients:

```typescript
export class BridgeServiceClient {
  private readonly baseUrl: string;
  private readonly timeout: number;

  constructor(baseUrl: string = 'http://localhost:5000', options: Options = {}) {
    this.baseUrl = baseUrl.replace(/\/$/, '');
    this.timeout = options.timeout ?? 30000;
  }

  async methodName(request: Request): Promise<Response> {
    return this.fetchJson<ApiResponse>(`${this.baseUrl}/endpoint`, { ... });
  }
}
```

Pattern elements:
- Default values in constructor
- Normalize URL (remove trailing slash)
- Private helper for fetch with error handling
- Type-safe request/response

### 2. AbortController for Timeout
Implement request timeout with AbortController:

```typescript
private async fetchJson<T>(url: string, options: RequestInit): Promise<T> {
  const controller = new AbortController();
  const timeoutId = setTimeout(() => controller.abort(), this.timeout);

  try {
    const response = await fetch(url, {
      ...options,
      signal: controller.signal,
    });
    clearTimeout(timeoutId);
    // ... handle response
  } catch (error) {
    if (error instanceof DOMException && error.name === 'AbortError') {
      throw new BridgeServiceError('La solicitud excedió el tiempo de espera');
    }
    throw error;
  }
}
```

Why AbortController:
- Native browser/Node.js API
- Clean cancellation mechanism
- Integrates with fetch signal option
- Can detect abort vs other errors

### 3. Date Serialization for API
Convert Date to ISO string for JSON:

```typescript
const body = {
  invoiceDate: request.invoiceDate.toISOString().split('T')[0],
  // "2024-12-15T10:30:00.000Z" → "2024-12-15"
};
```

Why split on 'T':
- API expects date-only format (YYYY-MM-DD)
- ISO string includes time component
- Simple string operation vs date library

### 4. Graceful 404 Handling
Return null instead of throwing for "not found":

```typescript
async getVendorByRfc(rfc: string): Promise<VendorResult | null> {
  try {
    const response = await this.fetchJson<...>(...);
    return response.data ? { ... } : null;
  } catch (error) {
    // Return null for 404 (not found)
    if (error instanceof BridgeServiceError && error.statusCode === 404) {
      return null;
    }
    throw error;
  }
}
```

Benefits:
- Natural API for lookup operations
- Caller uses `if (result)` pattern
- Only real errors throw exceptions
- Distinguishes "not found" from "error"

### 5. Custom Error Class
Extend Error with additional context:

```typescript
export class BridgeServiceError extends Error {
  public readonly statusCode?: number;
  public readonly detail?: string;

  constructor(message: string, statusCode?: number, detail?: string) {
    super(message);
    this.name = 'BridgeServiceError';
    this.statusCode = statusCode;
    this.detail = detail;
  }
}
```

Why custom error:
- Distinguish from other errors
- Carry HTTP status code
- Preserve API detail message
- Type-safe error handling

### 6. Jest Mock Pattern for fetch
Mock global fetch for testing:

```typescript
const mockFetch = jest.fn();
global.fetch = mockFetch;

beforeEach(() => {
  jest.clearAllMocks();
});

it('should return data', async () => {
  mockFetch.mockResolvedValueOnce({
    ok: true,
    json: async () => ({ success: true, data: { ... } }),
  });

  const result = await client.method();
  expect(result).toEqual({ ... });
});
```

Key points:
- mockResolvedValueOnce for async response
- Mock json() as async function
- Clear mocks between tests
- Can verify call arguments

## Best Practices Identified

1. **Normalize URLs**: Remove trailing slashes
2. **Timeout all requests**: Use AbortController
3. **Type API responses**: Define interface for each endpoint
4. **Graceful 404**: Return null for lookups
5. **Spanish messages**: User-facing errors in Spanish
6. **Export types**: Let consumers use request/response types

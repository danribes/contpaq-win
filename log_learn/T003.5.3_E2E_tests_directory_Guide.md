# Learning Guide: T003.5.3 - Create desktop-app/tests/e2e/ directory

## Overview

This guide covers organizing end-to-end tests for an Electron desktop application.

## Concepts Covered

### 1. E2E Test Directory Structure

Organize tests by purpose:

```
tests/e2e/
├── e2e.config.ts      # Test configuration
├── workflows/         # Complete user journeys
├── pages/             # Page object models
└── fixtures/          # Test data
```

### 2. Workflow Tests

Test complete user journeys:

```typescript
// tests/e2e/workflows/invoice-processing.test.ts
describe('Invoice Processing Workflow', () => {
  it('processes invoice from upload to posting', async () => {
    // Step 1: Upload PDF
    await homePage.clickNewInvoice();
    await processingPage.uploadFile('sample-invoice.pdf');

    // Step 2: Wait for extraction
    await processingPage.waitForExtraction();

    // Step 3: Verify extracted data
    expect(await processingPage.getRFC()).toBe('XAXX010101000');

    // Step 4: Validate
    await processingPage.clickValidate();

    // Step 5: Post to ContPAQi
    await processingPage.clickPost();
    await processingPage.waitForPostSuccess();

    // Verify final state
    expect(await processingPage.getStatus()).toBe('Registrada');
  });
});
```

### 3. Page Object Model Pattern

Abstract UI interactions:

```typescript
// tests/e2e/pages/ProcessingPage.ts
export class ProcessingPage {
  private selectors = {
    dropzone: '[data-testid="dropzone"]',
    processButton: '[data-testid="process-button"]',
    rfcInput: '[data-testid="rfc-input"]',
  };

  async uploadFile(filename: string): Promise<void> {
    const filePath = path.join(__dirname, '../fixtures', filename);
    const dropzone = await this.page.$(this.selectors.dropzone);
    await dropzone?.uploadFile(filePath);
  }

  async waitForExtraction(): Promise<void> {
    await this.page.waitForSelector('[data-testid="extraction-complete"]', {
      timeout: 60000,
    });
  }

  async getRFC(): Promise<string> {
    return this.page.$eval(
      this.selectors.rfcInput,
      (el) => (el as HTMLInputElement).value
    );
  }

  async clickValidate(): Promise<void> {
    await this.page.click('[data-testid="validate-button"]');
  }
}
```

## Code Examples

### Complete E2E Test Example

```typescript
// tests/e2e/workflows/duplicate-detection.test.ts
import { ProcessingPage } from '../pages/ProcessingPage';
import { electronConfig, timeouts } from '../e2e.config';

describe('Duplicate Detection', () => {
  let processingPage: ProcessingPage;

  beforeAll(async () => {
    // Launch Electron app
    app = await electron.launch(electronConfig);
    processingPage = new ProcessingPage(app);
  });

  afterAll(async () => {
    await app.close();
  });

  it('warns when uploading duplicate invoice', async () => {
    // Upload first invoice
    await processingPage.uploadFile('invoice-001.pdf');
    await processingPage.waitForExtraction();
    await processingPage.clickValidate();
    await processingPage.clickPost();

    // Upload same invoice again
    await processingPage.uploadFile('invoice-001.pdf');
    await processingPage.waitForExtraction();

    // Should show duplicate warning
    await processingPage.clickPost();
    const warning = await processingPage.getDuplicateWarning();
    expect(warning).toContain('duplicado');
  });
});
```

### Page Object Base Class

```typescript
// tests/e2e/pages/BasePage.ts
export abstract class BasePage {
  protected page: Page;

  constructor(page: Page) {
    this.page = page;
  }

  async waitForLoad(): Promise<void> {
    await this.page.waitForLoadState('networkidle');
  }

  async screenshot(name: string): Promise<void> {
    await this.page.screenshot({
      path: `./tests/e2e/screenshots/${name}.png`,
    });
  }

  async getByTestId(testId: string): Promise<ElementHandle | null> {
    return this.page.$(`[data-testid="${testId}"]`);
  }
}
```

## Best Practices

### 1. Use data-testid for Selectors

```tsx
// In component
<button data-testid="save-button">Guardar</button>

// In test
await page.click('[data-testid="save-button"]');
```

### 2. Organize by User Journey

```
workflows/
├── invoice-processing.test.ts  # Happy path
├── duplicate-detection.test.ts # Edge case
├── vendor-creation.test.ts     # Related flow
└── error-recovery.test.ts      # Error handling
```

### 3. Handle Async Operations

```typescript
// Wait for specific condition
await page.waitForSelector('[data-testid="success-message"]');

// Wait with timeout
await page.waitForSelector('[data-testid="extraction-complete"]', {
  timeout: 60000,
});

// Poll for condition
await expect(async () => {
  const status = await page.textContent('[data-testid="status"]');
  expect(status).toBe('Validada');
}).toPass({ timeout: 30000 });
```

### 4. Screenshot on Failure

```typescript
afterEach(async function() {
  if (this.currentTest?.state === 'failed') {
    const name = this.currentTest.title.replace(/\s+/g, '-');
    await page.screenshot({ path: `./screenshots/${name}.png` });
  }
});
```

## E2E vs Unit Tests

| Aspect | Unit Tests | E2E Tests |
|--------|-----------|-----------|
| Scope | Single function/component | Full workflow |
| Speed | Fast (<1s) | Slow (10-60s) |
| Dependencies | Mocked | Real |
| Reliability | High | Medium (flaky) |
| Debugging | Easy | Harder |
| Use case | Logic verification | User journey |

## Summary

E2E test organization involves:
1. ✅ Separate directories by purpose (workflows, pages, fixtures)
2. ✅ Use Page Object Model for maintainability
3. ✅ Configure appropriate timeouts for different operations
4. ✅ Handle Electron-specific requirements
5. ✅ Use data-testid for reliable selectors
6. ✅ Test complete user journeys, not individual features

# T017.1 Learning Log: Processing Page Layout

## Date: 2025-12-18

## Key Learnings

### 1. URL.createObjectURL Mocking in Jest/jsdom

**Problem**: `TypeError: URL.createObjectURL is not a function` when testing file handling.

**Solution**: Mock the URL APIs at the top of the test file before any imports:
```typescript
global.URL.createObjectURL = jest.fn(() => 'blob:mock-url');
global.URL.revokeObjectURL = jest.fn();
```

**Why it works**: jsdom doesn't implement `URL.createObjectURL` because it's a browser API for creating blob URLs. By mocking it globally before tests run, we can test components that create object URLs for file previews.

### 2. Responsive Split-Screen with Tailwind

**Pattern**: Use Tailwind's responsive prefixes for adaptive layouts:
```tsx
// Container
<div className="flex flex-col lg:flex-row gap-4">
  {/* Left panel */}
  <div className="w-full lg:w-1/2">...</div>
  {/* Right panel */}
  <div className="w-full lg:w-1/2">...</div>
</div>
```

**Key classes**:
- `flex-col lg:flex-row`: Stack vertically on mobile, side-by-side on large screens
- `w-full lg:w-1/2`: Full width on mobile, half width on large screens
- `gap-4`: Consistent spacing between panels

### 3. Status Badge Pattern

**Pattern**: Use a configuration object for status-based styling:
```typescript
interface StatusConfig {
  label: string;
  badgeClass: string;
}

const STATUS_CONFIG: Record<string, StatusConfig> = {
  none: { label: 'Sin archivo', badgeClass: 'bg-gray-100 text-gray-600' },
  uploaded: { label: 'Cargado', badgeClass: 'bg-blue-100 text-blue-700' },
  // ...
};
```

**Benefits**:
- Easy to add new statuses
- Consistent styling across the app
- Type-safe access to status properties

### 4. Memory Management with Object URLs

**Pattern**: Clean up object URLs when component unmounts or file changes:
```typescript
const handleClear = useCallback(() => {
  if (pdfUrl) {
    URL.revokeObjectURL(pdfUrl);  // Prevent memory leaks
  }
  setPdfUrl(null);
}, [pdfUrl]);
```

**Why it matters**: `URL.createObjectURL()` creates a reference that persists until explicitly revoked or the page unloads. Not revoking can cause memory leaks.

### 5. Testing Conditional Rendering

**Pattern**: Test both states of conditional rendering:
```typescript
// Initial state - FileUpload shown
expect(screen.getByTestId('file-upload')).toBeInTheDocument();

// After file selection - PDFViewer shown
fireEvent.click(screen.getByTestId('mock-file-select'));
await waitFor(() => {
  expect(screen.getByTestId('pdf-viewer')).toBeInTheDocument();
});

// FileUpload should be gone
expect(screen.queryByTestId('file-upload')).not.toBeInTheDocument();
```

**Note**: Use `queryByTestId` instead of `getByTestId` when checking for absence, as `getByTestId` throws if element not found.

### 6. Full-Height Layout Pattern

**Pattern**: For a full-height page with header and content:
```tsx
<div className="h-full flex flex-col">
  <header className="...">Header content</header>
  <div className="flex-1 overflow-hidden">
    {/* Content area fills remaining space */}
  </div>
</div>
```

**Key classes**:
- `h-full`: Take full height of parent
- `flex flex-col`: Stack children vertically
- `flex-1`: Grow to fill available space
- `overflow-hidden`: Prevent content overflow

## Best Practices Applied

1. **Component composition**: ProcessingPage uses FileUpload, PDFViewer as child components
2. **State colocation**: File and status state managed where they're used
3. **Spanish UI text**: "Procesar Factura", "Sin archivo", "Cargado" for target audience
4. **Accessibility**: Semantic HTML with header element, button titles
5. **Test isolation**: Mocking child components to test ProcessingPage in isolation

# T008.3.1 Learning Guide: Auto-Restart with Max Retries

## Overview

This guide covers implementing automatic process restart functionality with configurable maximum retry limits. This is essential for building resilient applications that can recover from temporary failures.

## Key Concepts

### 1. Process Crash Detection

Detecting process crashes requires distinguishing between:

| Exit Type | Exit Code | Status Before Exit | Action |
|-----------|-----------|-------------------|--------|
| Graceful shutdown | 0 | STOPPING | No restart |
| Clean exit | 0 | RUNNING | No restart |
| Crash | Non-zero | RUNNING | Auto-restart |
| Kill (SIGTERM) | null | STOPPING | No restart |

```typescript
process.on('exit', (code, signal) => {
  if (status === 'STOPPING') {
    // Deliberate shutdown - no restart
    return;
  }

  if (code !== 0) {
    // Crash detected - consider auto-restart
    handleAutoRestart(code, signal);
  }
});
```

### 2. Restart Circuit Breaker Pattern

The circuit breaker pattern prevents infinite restart loops:

```
Normal State → Crash → Restart 1 → Crash → Restart 2 → ...
                                                      ↓
                    Max Retries Exceeded → Open Circuit (no more restarts)
```

This protects against:
- Configuration errors
- Missing dependencies
- Resource exhaustion
- Persistent bugs

### 3. Event-Driven Architecture

Using events for communication:

```typescript
// Events emitted during auto-restart lifecycle
manager.on('restart', (event) => {
  console.log(`Service ${event.service} restarting (attempt ${event.restartCount})`);
});

manager.on('maxRestartsExceeded', (event) => {
  notifyAdmin(`Service ${event.service} failed ${event.maxRestarts} times`);
});
```

## Code Patterns

### Auto-Restart Handler

```typescript
private handleAutoRestart(
  service: 'ai' | 'bridge',
  code: number | null,
  signal: string | null
): void {
  // Guard: Check if auto-restart is enabled
  if (!this.config.enableAutoRestart) {
    console.log(`[${service}] Auto-restart disabled`);
    return;
  }

  // Guard: Check max restarts
  const restartCount = this.getRestartCount(service);
  if (restartCount >= this.config.maxRestarts) {
    console.warn(`[${service}] Max restarts exceeded`);
    this.emitMaxRestartsExceeded(service);
    return;
  }

  // Increment counter BEFORE restart attempt
  this.incrementRestartCount(service);

  // Build reason for logging/events
  const reason = `crash (exit code: ${code}${signal ? `, signal: ${signal}` : ''})`;

  // Emit restart event
  this.emit('restart', {
    service,
    restartCount: this.getRestartCount(service),
    reason,
    timestamp: new Date(),
  });

  // Attempt restart (non-blocking)
  this.startService(service).catch((err) => {
    console.error(`[${service}] Auto-restart failed:`, err);
  });
}
```

### Configuration Interface

```typescript
interface AutoRestartConfig {
  enableAutoRestart: boolean;  // Feature toggle

const DEFAULT_CONFIG = {
  enableAutoRestart: true,

```

### Independent Service Counters

```typescript
class ProcessManager {
  private aiRestartCount: number = 0;
  private bridgeRestartCount: number = 0;

  getRestartCount(service: 'ai' | 'bridge'): number {
    return service === 'ai' ? this.aiRestartCount : this.bridgeRestartCount;
  }

  resetRestartCount(service: 'ai' | 'bridge'): void {
    if (service === 'ai') {
      this.aiRestartCount = 0;
    } else {
      this.bridgeRestartCount = 0;
    }
  }
}
```

## Common Pitfalls

### 1. Counter Increment Timing

**Problem**: Incrementing counter after start may cause race conditions.

**Solution**: Increment before starting:
```typescript
// Wrong
await this.startService();
this.restartCount++;

// Correct
this.restartCount++;
await this.startService();
```

### 2. Blocking Exit Handler

**Problem**: Awaiting restart in exit handler can cause issues.

**Solution**: Use fire-and-forget with error handling:
```typescript
// Wrong
process.on('exit', async () => {
  await this.startService(); // Blocks!
});

// Correct
process.on('exit', () => {
  this.startService().catch(console.error);
});
```

### 3. Not Distinguishing Exit Types

**Problem**: Restarting on graceful shutdown creates infinite loop.

**Solution**: Check status before restart:
```typescript
if (this.status === 'STOPPING') {
  return; // Deliberate shutdown
}
```

### 4. Shared Counters Between Services

**Problem**: One service crashing affects another's restart limit.

**Solution**: Use independent counters per service.

## Best Practices

1. **Feature Toggle**: Always provide `enableAutoRestart` config
2. **Reasonable Default**: 3 restarts is common default
3. **Event Emission**: Emit events for monitoring/alerting
4. **Reason Tracking**: Include crash reason in events
5. **Manual Reset**: Provide `resetRestartCount()` for recovery
6. **Independent Counters**: Each service has own counter
7. **Logging**: Log each restart attempt with context

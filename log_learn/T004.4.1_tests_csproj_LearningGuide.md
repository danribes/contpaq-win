# T004.4.1 Learning Guide: .NET Test Projects

## Overview
This guide covers creating and configuring .NET test projects using the SDK-style project format and xUnit test framework conventions.

## Key Concepts

### 1. SDK-Style Test Projects
Modern .NET test projects use the SDK-style format:

```xml
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <TargetFramework>net8.0</TargetFramework>
    <IsTestProject>true</IsTestProject>
  </PropertyGroup>
</Project>
```

### 2. Essential Properties

#### IsTestProject
Marks the project as a test project:
```xml
<IsTestProject>true</IsTestProject>
```
This enables:
- Integration with `dotnet test`
- IDE test discovery
- Test-specific build behaviors

#### IsPackable
Test projects should not be packaged:
```xml
<IsPackable>false</IsPackable>
```

### 3. Project References
Test projects reference the main project:

```xml
<ItemGroup>
  <ProjectReference Include="..\MainProject\MainProject.csproj" />
</ItemGroup>
```

Using relative paths:
- `..` navigates up one directory
- Maintains portability across environments
- Works with solution-relative builds

### 4. Naming Conventions

| Item | Convention | Example |
|------|------------|---------|
| Project | `{MainProject}.Tests` | `ContPAQWinBridge.Tests` |
| Namespace | `{MainNamespace}.Tests` | `ContPAQWinBridge.Tests` |
| Directory | Mirror main project | `Controllers/`, `Services/` |
| Test Class | `{Class}Tests` | `VendorControllerTests` |

### 5. Solution Integration

Adding test project to solution file:
```
Project("{GUID}") = "ProjectName.Tests", "path\to\project.csproj", "{ProjectGUID}"
EndProject
```

Configuration mappings:
```
GlobalSection(ProjectConfigurationPlatforms) = postSolution
    {ProjectGUID}.Debug|Any CPU.ActiveCfg = Debug|Any CPU
    {ProjectGUID}.Debug|Any CPU.Build.0 = Debug|Any CPU
    {ProjectGUID}.Release|Any CPU.ActiveCfg = Release|Any CPU
    {ProjectGUID}.Release|Any CPU.Build.0 = Release|Any CPU
EndGlobalSection
```

## Test Project Structure

### Typical Layout
```
ContPAQWinBridge.Tests/
├── ContPAQWinBridge.Tests.csproj
├── GlobalUsings.cs          # Global using statements
├── Controllers/             # Controller tests
│   └── VendorControllerTests.cs
├── Services/                # Service tests
│   └── VendorServiceTests.cs
└── Helpers/                 # Test utilities
    └── TestData.cs
```

### GlobalUsings.cs
Common using statements for all tests:
```csharp
global using Xunit;
global using FluentAssertions;
global using Moq;
global using ContPAQWinBridge.Controllers;
global using ContPAQWinBridge.Services;
```

## Testing Frameworks Comparison

### xUnit vs NUnit vs MSTest

| Feature | xUnit | NUnit | MSTest |
|---------|-------|-------|--------|
| Test Attribute | `[Fact]` | `[Test]` | `[TestMethod]` |
| Parameterized | `[Theory]` | `[TestCase]` | `[DataRow]` |
| Setup | Constructor | `[SetUp]` | `[TestInitialize]` |
| Teardown | `IDisposable` | `[TearDown]` | `[TestCleanup]` |
| Parallelism | Default on | Optional | Optional |

### xUnit Best Practices
1. **Constructor for setup** - Use constructor instead of attributes
2. **IDisposable for cleanup** - Implement for resource cleanup
3. **Fact vs Theory** - Use `[Fact]` for single tests, `[Theory]` for parameterized
4. **No static state** - Tests run in parallel by default

## Common Patterns

### Test Class Structure
```csharp
public class VendorServiceTests : IDisposable
{
    private readonly Mock<IVendorRepository> _mockRepo;
    private readonly VendorService _service;

    public VendorServiceTests()
    {
        _mockRepo = new Mock<IVendorRepository>();
        _service = new VendorService(_mockRepo.Object);
    }

    [Fact]
    public async Task GetByRfc_WhenExists_ReturnsVendor()
    {
        // Arrange
        var vendor = new Vendor { Rfc = "ABC123" };
        _mockRepo.Setup(r => r.GetByRfc("ABC123"))
            .ReturnsAsync(vendor);

        // Act
        var result = await _service.GetByRfc("ABC123");

        // Assert
        result.Should().NotBeNull();
        result.Rfc.Should().Be("ABC123");
    }

    public void Dispose()
    {
        // Cleanup if needed
    }
}
```

### Theory with InlineData
```csharp
[Theory]
[InlineData("ABC123456789", true)]  // Valid RFC
[InlineData("INVALID", false)]       // Invalid RFC
[InlineData("", false)]              // Empty RFC
public void ValidateRfc_ReturnsExpected(string rfc, bool expected)
{
    var result = RfcValidator.Validate(rfc);
    result.Should().Be(expected);
}
```

## Running Tests

### Command Line
```bash
# Run all tests
dotnet test

# Run specific project
dotnet test ContPAQWinBridge.Tests

# With verbosity
dotnet test -v normal

# With coverage
dotnet test --collect:"XPlat Code Coverage"
```

### Visual Studio
- Test Explorer: View → Test Explorer
- Run All: Ctrl+R, A
- Debug Test: Right-click → Debug
